# 收盘快照与基线增量对账测试用例

> 对应任务：`docs/tasks/T-057-收盘快照与基线增量对账.md`

## 1. 快照采集

| ID | 级别 | 场景 | 前置 | 步骤 | 期望 |
|---|---|---|---|---|---|
| SNAP-001 | P0 | 日盘收盘快照 | CTP/SimVenue 持仓可用，执行消费者已追平 | 触发 capture，session=DAY | 生成一份 READY run，账户/策略快照完整 |
| SNAP-002 | P0 | 夜盘收盘快照 | 夜盘收盘，交易日历可用 | 触发 capture，session=NIGHT | trading_day 按交易日历归属，不与自然日混淆 |
| SNAP-003 | P0 | CTP 查询失败 | 模拟 CTP 持仓查询失败 | 触发 capture | run=FAILED，旧基线仍有效，产生告警 |
| SNAP-004 | P0 | 重复执行 | 同一 trading_day/session/run_key 已存在 | 重复触发 capture | 不产生重复快照，返回已有 run 或冲突 |
| SNAP-005 | P0 | 账户总持仓 | positions 有 ag2612/au2612 | capture | ACCOUNT 快照明细与 positions 完全一致 |
| SNAP-006 | P0 | 策略持仓 | strategy_positions 有策略持仓 | capture | STRATEGY 快照明细与 strategy_positions 一致 |
| SNAP-007 | P0 | daily_init 快照 | strategy_daily_state 有 avgPx/ytd1/today1/ytd2 | capture | daily_init 快照字段完整，strategy_version/deployment 正确 |
| SNAP-008 | P1 | 手工/未分配 | 账户有手工簿持仓 | capture | MANUAL 快照正确，正差额进入 UNASSIGNED，状态 READY_WITH_UNASSIGNED |
| SNAP-009 | P1 | 版本切换 | 策略当前版本 v0.2，运行 deployment v0.1 | capture | 快照记录实际运行版本 v0.1，不记录错误 current_version |
| SNAP-010 | P1 | daily_init 过期 | strategy_saved_at 早于 cutoff_at-120s | capture | 记录 STRATEGY_DAILY_STATE_STALE warning，仍可生成持仓基线；Runner 不使用旧 daily_init |
| SNAP-011 | P1 | 迟到成交 | 快照完成后出现 cutoff 前成交 | 触发重算 | 旧快照不变，产生新版本或 late event 证据 |

## 2. 账户/策略归属对账

| ID | 级别 | 场景 | 期望 |
|---|---|---|---|
| RECON-001 | P0 | 账户持仓 = 策略 + 手工 + 未分配 | 多空分别相等，run=READY |
| RECON-002 | P0 | 账户多 1 手 | 记录 UNASSIGNED=+1，run=READY_WITH_UNASSIGNED，生成基线 |
| RECON-003 | P0 | 策略满仓/空仓 | long/short 分别校验，不能用净额掩盖 |
| RECON-003A | P0 | 策略归属超过账户 | 负差额，run=MISMATCH，不生成基线 |
| RECON-004 | P0 | 同一合约多策略反向持仓 | 账户 long/short 与策略分项分别核对 |
| RECON-005 | P1 | 策略 daily_init 与 strategy_positions 不一致 | 标记差异，不静默覆盖 |
| RECON-006 | P1 | 手工单未归集 | 进入 MANUAL，不并入策略 |

## 3. 基线增量对账

| ID | 级别 | 场景 | 期望 |
|---|---|---|---|
| BASE-001 | P0 | 无新成交 | 当前持仓 = 基线，pass |
| BASE-002 | P0 | 基线后买入 | 当前持仓 = 基线 + 买入净额，pass |
| BASE-003 | P0 | 基线后买入再卖出 | 净额回到基线，pass |
| BASE-004 | P0 | 基线前历史成交 | 不参与当前增量，pass |
| BASE-005 | P0 | 基线后平仓 | 策略/账户持仓归零，pass |
| BASE-006 | P1 | 基线后部分成交 | 仅按已成交增量，pass |
| BASE-007 | P1 | 迟到成交 | 不修改旧基线；生成新快照或标记 late event |

## 4. Runtime 门禁与延迟

| ID | 级别 | 场景 | 期望 |
|---|---|---|---|
| GATE-001 | P0 | 管理面正常延迟 5-10s | OPEN 仍允许；标记 DELAYED |
| GATE-002 | P0 | 连续 60s 不一致 | OPEN 被拒绝；告警 |
| GATE-003 | P0 | 单次对账失败 | 不立即阻断 OPEN；记录 WARN/DEGRADED |
| GATE-004 | P0 | 策略需要平仓 | 即使对账失败，CLOSE/CANCEL/REDUCE 仍允许 |
| GATE-005 | P1 | 无 READY 基线 | OPEN 拒绝，返回明确原因 |
| GATE-006 | P1 | risk 快照过期 | OPEN 拒绝，CLOSE 允许 |

## 5. 版本与重启

| ID | 级别 | 场景 | 期望 |
|---|---|---|---|
| VER-001 | P0 | Runner 重启 | 按 strategy_version/deployment 加载 daily state |
| VER-002 | P0 | 同日版本切换 | 旧版本 daily_init 快照保留，新版本独立 |
| VER-003 | P1 | 无 daily_init | Runner 不静默使用旧版本；阻断并告警 |
| VER-004 | P1 | deployment 版本与 current_version 不一致 | 以实际 deployment 为准 |

## 6. 自动化测试建议

- `ClosePositionSnapshotServiceTest`
  - 账户/策略/手工/未分配快照
  - 多空分别校验
  - mismatch 状态
  - 重复 run 幂等
- `PositionBaselineServiceTest`
  - baseline 选择
  - 增量成交过滤
  - 版本切换
- `ReconciliationGateDelayTest`
  - 正常延迟允许
  - 连续失败阻断
  - CLOSE 始终允许
- SQL 集成测试
  - 快照表唯一约束
  - 历史快照不可覆盖
  - CTP 失败不更新基线
