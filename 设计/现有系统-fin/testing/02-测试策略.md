# 测试策略

- 目标：每个任务可验证，每个里程碑可视化验证
- 原则：测试不依赖远程 CTP；允许造数；前端截图比对；后端指标/图表可视化

---

## 1. 测试分层

| 层级 | 内容 | 工具 | 是否依赖 CTP |
|---|---|---|---|
| L1 单元测试 | 领域模型、定价、Greeks、指标算子、风控 | JUnit 5 / jqwik / AssertJ | 否 |
| L2 组件测试 | SBE 编解码、Aeron 封装、Replay、SimExchange | JUnit + Testcontainers | 否 |
| L3 契约测试 | Control Plane API、SBE schema 兼容 | OpenAPI + SBE 互操作 | 否 |
| L4 集成测试 | 回放 + Runtime + SimExchange 端到端 | JUnit + 影子库 | 否 |
| L5 视觉测试 | Web/Desktop 页面截图比对 | Playwright | 否 |
| L6 性能测试 | 延迟/吞吐/GC/队列 | JMH + HDR + JFR | 否 |
| L7 基线对比 | 与 C++ 信号/报价/成交对比 | Python/Excel 报告 | 否 |
| L8 实盘联调 | 盛立 CTP 评测盘/小资金 | 人工 + 自动化 | 是 |

### 1.1 写→读契约门禁（P0）

同一份数据如果既有**写入入口**又有**读取方**，必须有一条测试同时经过两端，用真实 Mapper 和真实读取方断言，不能只 mock。

- 典型场景：`PUT /strategies/{id}/versions` 写 `strategy_versions`，runner 通过 `DeploymentConfigLoader` 读部署版本。
- 反例（2026-11-11 事故）：写路径写版本表、读路径读 `strategies.config_json`，两侧单元测试各自通过，配置更新永远不生效。
- 要求：
  1. 新增/修改 API 时，必须附带一条「写→读」断言（例：`StrategyVersionContractIT`）。
  2. 涉及迁移的表，测试库必须跑完整 V2 迁移（`tools/testing/prepare-contract-db.sh`），禁止手写子集表结构。
  3. CI 的 `Contract tests (write path -> read path)` 步骤必须通过。
  4. 禁止用 `verify(mapper).insertXxx()` 代替「写进去的字节 = 读出来的字节」的断言。

## 2. 影子库（测试数据隔离）

### 2.1 数据库

| 用途 | 数据库/实例 | 说明 |
|---|---|---|
| 开发 | `quantlink_fin` | 日常开发 |
| 测试/影子 | `quantlink_fin_shadow` | 自动化测试专用，可随时重置 |
| ClickHouse 测试 | `quantlink_fin_shadow` | 独立 database |
| Chronicle 测试 | `./data/shadow/chronicle` | 独立目录 |

- 测试不得连接开发库/生产库
- 连接串由环境变量注入：
  - `QF_PG_URL`
  - `QF_PG_USER`
  - `QF_PG_PASSWORD`
  - `QF_CH_URL`
- 测试启动时校验数据库名包含 `_shadow`，否则拒绝运行

### 2.2 重置与种子

实际脚本（2026-11-11 核对）：

```
tools/db/reset-shadow.sh      重建影子库并跑迁移
tools/db/seed-shadow.sh       导入种子
tools/db/backup.sh            备份（无恢复演练脚本）
tools/db/verify-shadow.sh     校验表/行数
tools/db/apply-v2-migrations.sh
tools/testing/prepare-contract-db.sh   契约测试库（qf_it_config_shadow）

tests/seed/
├── shadow-seed.sql           当前唯一的种子文件
└── viewer_trader_accounts.sql  VIEWER/TRADER 权限夹具（2026-11-11 新增）
```

> 早期计划里的 `tools/db/dump-shadow.sh`、`tests/seed/*.sql` 分表文件均不存在，
> 已按实际实现改写。种子只保留 `shadow-seed.sql` 一个入口。

`reset-shadow.sh`：

1. 删除并重建 shadow database
2. 执行 Flyway migration
3. 导入 `tests/seed/*.sql`
4. 输出摘要（表/行数）

### 2.3 造数

允许：

- 直接 SQL 造用户/账户/策略/合约/订单/持仓
- Java Test Data Factory 造领域对象
- Python 脚本生成历史回放数据
- 模拟期权链生成器造期权行情
- SimExchange 造订单/成交

禁止：

- 在开发库/生产库造测试数据
- 测试数据未标记 `test_` 前缀或 `source=test`

## 3. 测试数据规范

### 3.1 标识

| 类型 | 前缀/标记 |
|---|---|
| 用户 | `test_` |
| 账户 | `TEST-` |
| 策略 | `TEST-STRAT-` |
| 合约 | 真实合约名，`synthetic=true` 标记模拟行情 |
| 订单 | `source=test` |
| 回放 | `replay=true` |

### 3.2 固定种子

- 随机数固定 seed（默认 42）
- 时间冻结：`QF_TEST_NOW=2026-11-06T09:00:00+08:00`
- UI 截图时冻结时间/禁用动画/固定字体

---

## 4. 前端截图比对

### 4.1 工具

- Web：Playwright
- Electron：Playwright Electron
- 基线目录：`tests/visual/baselines/<task-id>/<viewport>/<page>.png`
- 差异目录：`tests/visual/diffs/<task-id>/<timestamp>/`
- 报告：`tests/visual/report/index.html`

### 4.2 视口

| 平台 | 视口 |
|---|---|
| Web | 1920x1080、1440x900、1366x768 |
| Desktop | 1600x1000、1280x800 |
| 主题 | dark（默认）、light |

### 4.3 规则

- 固定测试数据（影子库 + seed）
- 固定时区 `Asia/Shanghai`
- 禁用动画/过渡
- 固定字体（打包字体）
- 隐藏光标/时间戳/随机数
- 阈值：像素差异 ≤ 0.1%；超过则失败
- 基线更新必须走 PR/评审，不能测试时自动覆盖

### 4.4 命名

```
tests/visual/baselines/T-018/dark-1920x1080/trading-cockpit.png
tests/visual/baselines/T-019/light-1440x900/strategy-config.png
```

## 5. 可视化验证（非 UI 任务）

| 任务类型 | 可视化证据 |

| 更新服务器 | 版本列表、更新/回滚截图 |

证据统一放：

```
docs/evidence/<milestone>/<task-id>/
```

## 7. CI 流程

```
1. 编译（Gradle）
2. 单元测试
3. SBE 互操作测试
4. 启动影子库（Testcontainers）
5. 集成测试（Replay + SimExchange）
6. 启动 Web/Electron
7. Playwright 截图比对
8. 生成报告
9. 失败保留 diff/截图/日志
```
