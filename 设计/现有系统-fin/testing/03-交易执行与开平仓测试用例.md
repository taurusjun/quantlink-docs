## 1. 交易所开平规则基线

| 交易所 | 开仓 | 平仓 | 平今 | 平昨 | 当前策略 |
|---|---|---|---|---|---|
| SHFE 上期所 | OPEN | CLOSE 自动解析 | CLOSE_TODAY | CLOSE_YESTERDAY | 已实现：按今昨仓自动选一个 offset |
| INE 能源中心 | OPEN | CLOSE 自动解析 | CLOSE_TODAY | CLOSE_YESTERDAY | 与 SHFE 一致 |
| DCE 大商所 | OPEN | CLOSE | 拒绝 | 拒绝 | 只允许 CLOSE |
| CZCE 郑商所 | OPEN | CLOSE | 拒绝 | 拒绝 | 只允许 CLOSE |
| CFFEX 中金所 | OPEN | CLOSE | 拒绝 | 拒绝 | 只允许 CLOSE |
| GFEX 广期所 | OPEN | CLOSE | 拒绝 | 拒绝 | 只允许 CLOSE |
| SimVenue（原 SimLocal） | 按合约 `exchange` 元数据套用以上规则 | 同左 | 同左 | 同左 | 仅开发/测试 |

当前实现：

- 业务默认只表达 `OPEN / CLOSE`，执行层按今昨仓解析成唯一 offset
- 参考 quantlink-trading：SHFE/INE 今仓 → `CloseToday`，昨仓 → `Close`；其他交易所统一 `Close`
- 已实现 `ExecutionOffsetPolicy`：CLOSE 先看今仓，再看昨仓；今昨合计不足直接拒绝，不 fallback 开仓
- 已增加 `positions.today_long/today_short/yesterday_long/yesterday_short`
- UI 根据合约 `exchange` 动态显示可选开平：
  - SHFE/INE：`OPEN / CLOSE(自动) / CLOSE_TODAY(高级) / CLOSE_YESTERDAY(高级)`
  - 其他：`OPEN / CLOSE`
- CTP Adapter 将 offset 映射为 CTP 的 `CombOffsetFlag`
- 只减仓模式只允许平仓类 offset，并按可平仓位校验

## 6. 撤单测试

### 6.1 状态定义

| 状态 | 含义 |
|---|---|
| NEW | 已落库，未收到柜台确认 |
| OPEN | 柜台已接受，未成交 |
| PARTIAL | 部分成交 |
| CANCEL_REQUESTED | 已发撤单，等待柜台 |
| CANCELED | 柜台确认已撤 |
| CANCEL_FAILED | 撤单发送失败/柜台拒绝 |
| ACK_TIMEOUT | 超时未收到 ACK |
| FILLED | 全部成交 |

### 6.2 用例

| ID | 优先级 | 场景 | 步骤 | 期望 |
|---|---|---|---|---|
| CAN-001 | P0 | 撤销未成交单 | 对 OPEN 单点撤单 | `CANCEL_REQUESTED`，收到确认后 `CANCELED` |
| CAN-002 | P0 | 撤销部分成交单 | 对 PARTIAL 单撤单 | 已成交部分保留，剩余撤销 |
| CAN-003 | P0 | 撤销已成交单 | 对 FILLED 单撤单 | 拒绝，状态不变 |
| CAN-004 | P0 | 重复撤单 | 对同一单撤两次 | 第二次拒绝/幂等，不产生重复撤单 |
| CAN-005 | P0 | 柜台撤单失败 | 断 Aeron/柜台拒撤 | `CANCEL_FAILED`，页面可见，不显示 CANCELED |
| CAN-006 | P0 | 全撤 | 顶部应急全撤 | 逐单回执，显示成功/失败数量 |
| CAN-007 | P0 | 全撤范围 | 按 account/instrument scope | 只撤范围内订单 |
| CAN-008 | P0 | 撤单后成交 | 撤单请求发出后柜台先成交 | 以柜台最终状态为准，不能本地强制 CANCELED |
| CAN-009 | P1 | 撤单超时 | 发撤后长时间无回报 | 标记超时/待人工确认，不自动装作已撤 |
| CAN-010 | P1 | 策略 TTL 撤单 | 策略单超过 60 秒 | SIM 置 CANCELED；CTP 发撤单并等待回执 |
| CAN-011 | P1 | ACK 超时 | 手工 NEW 超 30 秒 | `ACK_TIMEOUT`，页面可见 |
| CAN-012 | P2 | 撤单失败重试 | CANCEL_FAILED 后重试 | 有次数上限、审计和最终失败提示 |

### 6.3 当前实现边界

- 订单页原来的“DB-only 全撤”已删除
- 应急全撤走 Aeron，逐单更新 `CANCEL_REQUESTED / CANCEL_FAILED`
- 策略 TTL 会自动撤超时策略单
- `CANCEL_FAILED` 目前没有自动无限重试；需要人工或后续补重试策略
- `CANCEL_REQUESTED` 不能视为已撤，必须等柜台回报

## 8.1 与 quantlink-trading 的对齐点

参考 `ors/China/src/ORSServer.cpp::SetCombOffsetFlag`：

- 前端/策略只发 `OPEN / CLOSE / CLOSE_INTRADAY` 语义
- ORS 按 `todayLong / ONLong / todayShort / ONShort` 自动选 offset
- SHFE/INE：今仓 → `CloseToday`，昨仓 → `Close`
- 其他交易所：统一 `Close`
- 参考实现不拆子单；当前默认也不应拆子单
- 数量超过今昨合计时，参考实现会 fallback 开仓；本系统应改为拒绝，避免反向开仓

因此测试必须同时断言：

```text
请求 offset（业务意图）
实际 resolved offset（执行层解析）
CTP 最终 CombOffsetFlag
持仓 today/ON 变化
```
