## 5. 详细测试用例

### 5.1 持仓与对账

#### TC-T030-001 账户快照比策略+手工多 1 手

- 类型：Integration
- 优先级：P0
- 前置：账户 SIMVENUE-001 快照多 1 手 ag2612；策略 A/B 与手工簿合计少 1 手。
- 步骤：
  1. 刷新账户快照。
  2. 打开账户汇总和未分配页面。
  3. 查看 `attributed/unassigned/diff`。
- 期望：
  - `account_position = 10`
  - `A=2 + B=7 + manual=0 = 9`
  - `UNASSIGNED=1`，页面黄色/红色
  - 不得自动平账或塞入 A/B

#### TC-T030-002 手工簿只计一次

- 类型：Integration
- 优先级：P0
- 前置：账户 10 手，策略 A=2、B=7、手工簿=1。
- 步骤：刷新账户汇总。
- 期望：手工簿只计一次；策略汇总不含手工簿；账户=10。

#### TC-T030-003 未分配成交认领

- 类型：E2E
- 优先级：P0
- 前置：一笔外部成交进入 UNASSIGNED。
- 步骤：运维打开未分配，认领到手工簿/策略。
- 期望：持仓更新、审计 `UNASSIGNED_ASSIGN`、未分配 badge 减少。

#### TC-T030-004 超过阈值未认领阻止开仓

- 类型：Integration
- 优先级：P1
- 前置：配置未认领金额/手数阈值。
- 步骤：制造超阈值未分配，尝试新开仓。
- 期望：返回 `UNASSIGNED_BLOCK`；平仓/撤单允许。

### 5.2 策略平仓与并发

#### TC-T030-005 A=2/B=8/账户=10，A 平 5

- 类型：Integration
- 优先级：P0
- 步骤：A 发平仓 5。
- 期望：`STRATEGY_POSITION_INSUFFICIENT`；B 持仓不变。

#### TC-T030-006 A 平 2 后持仓归属

- 类型：Integration
- 优先级：P0
- 步骤：A 平 2 成交。
- 期望：账户 8、A 0、B 8；B PnL 不变。

#### TC-T030-007 并发平仓

- 类型：Concurrency
- 优先级：P0
- 步骤：并发两笔 A 平 2。
- 期望：仅一笔成功；另一笔 `STRATEGY_POSITION_INSUFFICIENT`；不出现负持仓。

### 5.3 策略持仓与 PnL

#### TC-T030-008 跨交易所策略持仓

- 类型：Integration
- 优先级：P0
- 前置：策略 CROSS 同时持有 SHFE ag 和 DCE TA。
- 步骤：打开策略持仓。
- 期望：按交易所分组；不合并/覆盖；列表显示交易所集合。

#### TC-T030-009 今日/昨日转换

- 类型：Integration
- 优先级：P0
- 步骤：日终结算后查看策略和账户持仓。
- 期望：today→yesterday 正确；平今/平昨可用量正确。

#### TC-T030-010 期权到期/行权

- 类型：Integration
- 优先级：P1
- 步骤：模拟到期/行权事件。
- 期望：策略持仓、乘数、PnL、Greeks 按规则更新；不污染其他策略。

#### TC-T030-011 重新部署不重复持仓

- 类型：Integration
- 优先级：P0
- 步骤：策略 v3→v4 版本更新（允许 carry）。
- 期望：`position_epoch` 不变；不出现重复持仓行；deployment 仅作为来源。

#### TC-T030-012 FIFO PnL 与手续费

- 类型：Unit
- 优先级：P0
- 步骤：多次开平仓，比较策略 PnL。
- 期望：FIFO、手续费逐笔、已实现/未实现拆分正确；asOf/source 可见。

#### TC-T030-013 账户 PnL 快照

- 类型：Integration
- 优先级：P0
- 前置：有出入金、手续费、已实现/未实现。
- 期望：账户 PnL 以柜台快照权威；出入金剔除；diff/tolerance 可见。

#### TC-T030-014 策略 PnL 与账户 PnL 差异

- 类型：Integration
- 优先级：P0
- 步骤：注入策略汇总与账户快照差异。
- 期望：`RECON_DIFF` 显示；超过阈值告警；快照陈旧阻止开仓。

#### TC-T030-015 mark source 切换

- 类型：Integration
- 优先级：P1
- 步骤：LAST/SETTLEMENT/THEORETICAL 切换。
- 期望：PnL 重算、asOf/source 更新；不混用其他柜台价格。

#### TC-T030-016 多策略共享账户 PnL

- 类型：Integration
- 优先级：P0
- 期望：各策略 PnL 独立；账户 PnL 权威；手工/未分配可归因。

### 5.4 手工簿与未分配

#### TC-T030-017 手工单归属

- 类型：E2E
- 优先级：P0
- 步骤：手工下单成交。
- 期望：book_type=MANUAL；不出现在策略排名/自动收盘；手工簿详情无部署 Tab。

#### TC-T030-018 手工簿撤单/平仓

- 类型：E2E
- 优先级：P1
- 期望：只影响手工簿；不触发策略停止/部署逻辑。

#### TC-T030-019 收盘不自动平手工簿

- 类型：Integration
- 优先级：P0
- 前置：手工簿有持仓，临近收盘。
- 期望：自动收盘只处理 STRATEGY；手工簿保留，除非显式配置。

#### TC-T030-020 未分配不进入策略排名

- 类型：UI/Integration
- 优先级：P1
- 期望：UNASSIGNED 单独分区、badge、置顶红色；策略 PnL 不含未分配。

### 5.5 订单/成交/回报归属

#### TC-T030-021 同账户两策略同合约成交

- 类型：Integration
- 优先级：P0
- 步骤：A/B 各成交 1 手。
- 期望：book/strategy 分别归属；不串单；策略持仓/PnL 正确。

#### TC-T030-022 手工单落 MANUAL

- 类型：Integration
- 优先级：P0
- 期望：手工单 `book_id=MANUAL`，strategy_id null；账户汇总正确。

#### TC-T030-023 未知成交落 UNASSIGNED

- 类型：Integration
- 优先级：P0
- 步骤：注入无 clientOrderId 映射的外部成交。
- 期望：进入 UNASSIGNED，不猜策略；可认领。

#### TC-T030-024 ORS 重启映射恢复

- 类型：Chaos
- 优先级：P0
- 步骤：发送订单，重启 ORS，再收回报。
- 期望：clientOrderId→context 恢复；成交归属正确；旧回报不覆盖。

#### TC-T030-025 SBE v1/v2 兼容

- 类型：Integration
- 优先级：P0
- 步骤：发送 v1 与 v2 消息。
- 期望：v2 正常归属；v1 进入兼容队列；不得直接更新策略持仓。

### 5.6 行情与多柜台

#### TC-T030-026 同合约两柜台不同价格

- 类型：Integration
- 优先级：P0
- 步骤：SIMVENUE/SIMNOW 同时有 ag2612 不同价格。
- 期望：策略详情、手工预检、PnL 使用各自 `(counterparty, exchange, instrument)`。

#### TC-T030-027 行情断线

- 类型：Chaos
- 优先级：P0
- 步骤：断开当前柜台行情。
- 期望：策略详情显示 NO_MARKET_DATA/stale；禁止开仓；不 fallback 其他柜台价格。

#### TC-T030-028 固定种子价

- 类型：Security/Integration
- 优先级：P1
- 期望：FIXTURE/固定价在 SHADOW/LIVE 不可用于下单预检；只能开发 fixture。

#### TC-T030-029 多交易所行情

- 类型：Integration
- 优先级：P1
- 步骤：同一柜台 SHFE/DCE 行情。
- 期望：策略持仓/PnL 按交易所分组；筛选正确。

### 5.7 路由与旧 ORS

#### TC-T030-030 无 ACTIVE ORS

- 类型：Integration
- 优先级：P0
- 期望：`NO_ACTIVE_ROUTE`；不插订单、不发 Aeron、不 fallback legacy。

#### TC-T030-031 旧 ORS CANCELED 覆盖新 FILLED

- 类型：Chaos
- 优先级：P0
- 步骤：新 ORS FILLED 后旧 ORS 发 CANCELED。
- 期望：保持 FILLED；旧回报 `STALE_UPDATE`；告警。

#### TC-T030-032 旧 fencing/route/orderEpoch

- 类型：Integration
- 优先级：P0
- 期望：全部拒绝；策略持仓/订单状态不变。

#### TC-T030-033 FENCED 状态

- 类型：Chaos
- 优先级：P0
- 步骤：ORS 重启/换 fencing。
- 期望：旧 stream FENCED；新 ORS 查柜台确认；不靠旧回报猜。

### 5.8 权限

#### TC-T030-034 VIEWER/TRADER/ADMIN 矩阵

- 类型：Security
- 优先级：P0
- 步骤：三类用户访问策略/订单/持仓/下单/应急。
- 期望：VIEWER 只读授权账户；TRADER 只能交易授权账户；ADMIN 无交易权；越权 403 + 审计。

#### TC-T030-035 权限版本失效

- 类型：Security
- 优先级：P1
- 步骤：撤销权限后旧页面提交。
- 期望：403；旧会话不能继续下单。

#### TC-T030-036 策略详情越权

- 类型：Security
- 优先级：P0
- 期望：非授权账户策略返回 403，不返回空列表。

### 5.9 绑定、版本、Fork

#### TC-T030-037 首次部署绑定四元组

- 类型：Integration
- 优先级：P0
- 步骤：策略首次部署。
- 期望：写入 bound_agent/account/counterparty/ors；不可清空。

#### TC-T030-038 部署到其他 Agent/账户

- 类型：API
- 优先级：P0
- 期望：`409 STRATEGY_BOUND_TO_CONTEXT`；四个 bound 字段逐项校验。

#### TC-T030-039 编辑版本更新到同 Agent

- 类型：E2E
- 优先级：P0
- 步骤：编辑策略，保存新版本，更新当前 Agent。
- 期望：历史版本保留；generation 增加；不能换账户/ORS；旧 preview 失效。

#### TC-T030-040 Fork 不继承持仓/PnL

- 类型：E2E
- 优先级：P0
- 步骤：从 A Fork 到新账户/Agent。
- 期望：新 strategy_id、parent/version；持仓=0、订单/成交/PnL 从零；原策略不变。

#### TC-T030-041 版本更新默认平仓

- 类型：E2E
- 优先级：P0
- 步骤：策略有持仓，更新 v4。
- 期望：默认阻止/要求先平仓；carry 升级需显式确认、原因、审计。

#### TC-T030-042 部署失败回滚

- 类型：Chaos
- 优先级：P1
- 步骤：新版本启动失败。
- 期望：回滚上一稳定版；旧挂单/持仓处理有记录；审计 generation。

### 5.12 迁移、约束、性能

#### TC-T030-055 迁移回填

- 类型：Migration
- 优先级：P0
- 步骤：shadow 库执行迁移。
- 期望：orders/trades 无 book 为 0；旧手工单进 MANUAL；失败进 UNASSIGNED；可回滚。

#### TC-T030-056 数据库约束

- 类型：DB
- 优先级：P0
- 步骤：插入重复 ACTIVE 策略/账户/order stream。
- 期望：唯一约束/部分索引拒绝；审计/告警。

#### TC-T030-057 启动 invariants

- 类型：Integration
- 优先级：P1
- 期望：重复 ACTIVE、账户/柜台冲突、order stream 冲突在启动时报告并阻断。

#### TC-T030-058 迁移后对账

- 类型：Migration
- 优先级：P0
- 期望：账户快照 vs 策略+手工+未分配；差异有清单；不自动配平。

#### TC-T030-059 策略详情性能

- 类型：Performance
- 优先级：P1
- 前置：10 万订单/成交，50 个策略。
- 期望：详情首屏 < 1s；分页 < 300ms；无 N+1。

#### TC-T030-060 行情推送性能

- 类型：Performance
- 优先级：P1
- 期望：多柜台 5 档行情；无跨柜台串价；队列/背压可见。

#### TC-T030-061 回归

- 类型：Regression
- 优先级：P0
- 范围：手工单、期权链、策略部署、监控、告警、审计、对账。
- 期望：现有 P0 回归全绿；新增 V2 用例全绿。

### 5.13 Pair 策略专项

#### TC-T030-062 Pair 创建与双腿配置

- 类型：E2E / API
- 优先级：P0
- 步骤：
  1. 新建 `futures_pair` 策略，第一腿 `ag2612`、第二腿 `ag2706`。
  2. 保存 `strategy_pair_configs`。
  3. 读取策略详情与列表。
- 期望：
  - 策略 `target` 显示双腿 `ag2612 / ag2706`。
  - 详情返回 `pairConfig.leg1/leg2`。
  - 列表不显示 Agent/ORS，只显示规则和账户。

#### TC-T030-063 Pair 指标

- 类型：E2E
- 优先级：P1
- 步骤：为 Pair 策略创建价差、Z-Score、对冲延迟指标，打开策略详情。
- 期望：
  - 详情“策略指标”区显示 3 个指标。
  - 未采集时显示 `未采集/NO_DATA`，不得显示空白区域。

#### TC-T030-064 Pair 编辑双腿

- 类型：E2E / API
- 优先级：P0
- 步骤：把第二腿从 `ag2706` 改为 `au2612` 并保存。
- 期望：
  - `strategies.config_json.leg1/leg2` 与 `strategy_pair_configs` 同时更新。
  - 绑定规则/账户保持不变。
  - 已有持仓/PnL 不被改写。

#### TC-T030-065 Pair 平仓归属

- 类型：Integration
- 优先级：P0
- 步骤：账户有持仓但策略对某一腿没有归属，发该腿平仓。
- 期望：
  - 返回 `STRATEGY_POSITION_INSUFFICIENT` 或 422。
  - 不得用第二腿持仓抵扣第一腿，不得平到其他策略。

#### TC-T030-066 Pair 复制

- 类型：E2E / API
- 优先级：P0
- 步骤：复制已绑定 Pair 策略。
- 期望：
  - 新策略复制配置、双腿、指标和版本。
  - 不复制持仓、订单、成交、PnL、运行状态和绑定。
  - `parent_strategy_id` 指向来源策略。

#### TC-T030-067 Pair 绑定展示口径

- 类型：E2E
- 优先级：P0
- 步骤：打开策略列表和详情。
- 期望：
  - 标的/双腿是主信息。
  - 绑定区只显示规则和账户。
  - 交易员页面不展示 Agent/ORS。

### 5.14 指标、PnL 与驾驶舱数据

#### TC-T030-068 指标定义必须收到值

- 类型：Integration / E2E
- 优先级：P0
- 步骤：保持行情运行 10 秒，查询 `indicator_defs` 与 `indicator_values`。
- 期望：
  - 每个启用的策略/全局指标都有最新 `value`、`status`、`ts`。
  - 不得只有硬编码 ID 有值，策略向导创建的 `indicator_id` 也必须更新。
  - 行情线程不得因指标写库阻塞；队列满时丢弃并计数。

#### TC-T030-069 策略 PnL 实时与快照

- 类型：Integration / E2E
- 优先级：P0
- 步骤：
  1. Pair 策略双腿开仓、再接双腿平仓。
  2. 查询策略详情、`strategy_pnl_snapshot`、WebSocket。
- 期望：
  - 详情 PnL 随行情/成交变化，不靠手动刷新。
  - 快照按固定低频落库，带 `as_of/source`。
  - 平仓后 PnL 保留已实现值，不归零。

#### TC-T030-070 驾驶舱无死数据

- 类型：E2E
- 优先级：P0
- 步骤：打开交易驾驶舱。
- 期望：
  - 指标卡显示最新值和数据龄，不显示“无数据/—”。
  - 组合 Delta/Vega/PnL/保证金来自组合快照。
  - 数据源和 as-of 可见；不得使用固定 IV 或静态 metrics 冒充实时值。

#### TC-T030-071 账户出入金口径

- 类型：Integration
- 优先级：P1
- 步骤：对比 CTP `TradingAccount.Deposit/Withdraw`、账户快照与 UI。
- 期望：
  - 字段有明确来源和时间。
  - 无出入金时显示 0，不伪造非零值。
  - 非零事件必须能穿透 SBE → DB → 策略详情账户卡片。
