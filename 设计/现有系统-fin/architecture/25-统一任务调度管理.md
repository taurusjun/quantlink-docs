# 25 - 统一任务调度管理

> 状态：方案待实现（TODO）
>
> 目标：把当前分散在 control-plane `@Scheduled`、CTP 适配器内部循环、systemd timer 的定时任务，收敛成一套可查询、可配置、可手动触发、可审计的调度能力。

## 1. 背景

当前定时任务分散在三种执行边界：

| 任务 | 当前位置 | 执行方式 | 管理方式 |
|---|---|---|---|
| 账户/持仓收盘查询 | CTP 适配器 | 适配器内部 1s 时钟检查，到点在同一 CTP 会话查询 | `/api/v1/query-schedule` + 交易日历页面 |
| 账户/持仓常规轮询 | CTP 适配器 | 每 30s 在同一会话查询 | `--position-interval` |
| 费率/保证金刷新 | systemd | `quantlink-fin-fee-refresh.timer` 15:05 | 服务器 unit |
| 交易日历检查 | systemd | 每天 06:15 | 服务器 unit |
| CTP agent 启动 | systemd | 交易日 08:45 | 服务器 unit |
| 组合快照 | control-plane | `PortfolioSnapshotTask` 2s | 无 |
| 指标历史 | control-plane | 每天 15:10 | 无 |
| 数据保留清理 | control-plane | 每天 03:30 | 无 |
| 对账/状态监控 | control-plane | 固定 delay | 无 |

问题：

- 没有统一页面查看“有哪些任务、下次何时跑、上次结果”
- 修改时间需要改服务器文件或 systemd unit
- 失败没有统一重试/告警/审计
- systemd、Adapter、Java 三类执行方式容易混用，特别是 CTP 不能另开 session
- 手工触发没有统一入口

## 2. 目标与非目标

### 目标

- 统一任务清单、时间配置、启停、手动触发、执行历史
- 任务执行仍留在正确的边界：
  - Java 内部任务由 control-plane 执行
  - CTP 会话内任务由 agent/适配器执行，绝不由 control-plane 另开 CTP 登录
  - systemd 任务先只读展示，不直接由 Web 改 unit
- 支持交易日/非交易日判断
- 防重复执行（多实例/重入）
- 所有手动触发和配置变更进入审计

### 非目标（P1 不做）

- 不做通用分布式工作流引擎
- 不允许 Web 直接以 root 修改 systemd
- 不把 CTP 查询迁移到 control-plane 进程
- 不做任意脚本上传/执行

## 3. 任务分类

### INTERNAL

control-plane 内部 Java 任务：

- 组合快照
- 指标历史
- 数据保留
- 费率/保证金导入（P2）
- 交易日历检查（P2）

执行方式：调度器直接调用注册的 `JobHandler`。

### AGENT

需要账户会话或 agent 本地能力的任务：

- CTP 收盘账户/持仓查询
- 费率/保证金 CTP 查询（P2）
- ORS/策略进程巡检

执行方式：调度器发布 agent 命令；agent 在本地会话中执行并回报结果。

### SYSTEMD_READONLY

短期不迁移的 systemd timer：

- CTP agent 启动
- DB 备份
- archive 监控/保留
- 证书续期

执行方式：P1 只读展示名称、时间、上次/下次执行；不提供 Web 编辑。

## 4. 数据模型

```sql
CREATE TABLE scheduled_jobs (
    job_key        TEXT PRIMARY KEY,
    name           TEXT NOT NULL,
    job_type       TEXT NOT NULL CHECK (job_type IN ('INTERNAL','AGENT','SYSTEMD_READONLY')),
    schedule       TEXT NOT NULL,              -- HH:mm 或 cron
    timezone       TEXT NOT NULL DEFAULT 'Asia/Shanghai',
    enabled        BOOLEAN NOT NULL DEFAULT TRUE,
    trading_day_only BOOLEAN NOT NULL DEFAULT FALSE,
    timeout_seconds INTEGER NOT NULL DEFAULT 60,
    retry_limit    INTEGER NOT NULL DEFAULT 0,
    payload_json   JSONB NOT NULL DEFAULT '{}'::jsonb,
    next_run_at    TIMESTAMPTZ,
    last_run_at    TIMESTAMPTZ,
    last_status    TEXT NOT NULL DEFAULT 'NEVER',
    last_error     TEXT NOT NULL DEFAULT '',
    updated_by     TEXT NOT NULL DEFAULT '',
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE scheduled_job_runs (
    run_id         BIGSERIAL PRIMARY KEY,
    job_key        TEXT NOT NULL REFERENCES scheduled_jobs(job_key),
    trigger_type   TEXT NOT NULL CHECK (trigger_type IN ('SCHEDULE','MANUAL','RETRY')),
    started_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at    TIMESTAMPTZ,
    status         TEXT NOT NULL DEFAULT 'RUNNING',
    message        TEXT NOT NULL DEFAULT '',
    requested_by   TEXT NOT NULL DEFAULT ''
);
```

约束：

- `next_run_at` 由调度器计算并持久化
- `enabled=false` 不计算下次执行
- 同一 `job_key` 同时只允许一个 RUNNING（数据库 advisory lock 或唯一部分索引）
- 手动触发也必须写 `scheduled_job_runs`

## 5. API

```text
GET    /api/v1/scheduled-jobs
GET    /api/v1/scheduled-jobs/{jobKey}
PUT    /api/v1/scheduled-jobs/{jobKey}       # 时间、启用、超时、重试
POST   /api/v1/scheduled-jobs/{jobKey}/run  # 手动触发
GET    /api/v1/scheduled-jobs/{jobKey}/runs?limit=50
```

返回字段至少包含：

```json
{
  "jobKey": "ctp_close_query",
  "name": "CTP 收盘账户/持仓查询",
  "jobType": "AGENT",
  "schedule": "15:00,02:30",
  "enabled": true,
  "tradingDayOnly": true,
  "nextRunAt": "...",
  "lastRunAt": "...",
  "lastStatus": "SUCCESS",
  "lastError": ""
}
```

## 6. 调度器

```text
每 10s：
  SELECT ... FROM scheduled_jobs
  WHERE enabled AND next_run_at <= now()
  ORDER BY next_run_at
  FOR UPDATE SKIP LOCKED
```

执行流程：

1. 获取数据库 advisory lock
2. 写 `scheduled_job_runs` RUNNING
3. 按 `job_type` 路由
4. 超时控制
5. 写终态、错误、耗时
6. 计算下一次 `next_run_at`
7. 失败按 `retry_limit` 重试

时间语义：

- `HH:mm`：每天固定时间
- 支持逗号分隔多时间点，例如 `15:00,02:30`
- `trading_day_only=true` 时，非交易日跳过并记录 `SKIPPED_NON_TRADING_DAY`
- 夜盘任务归属日期按交易日历规则处理

## 7. 三类任务的路由

### INTERNAL

```java
interface ScheduledJobHandler {
    String key();
    void run(JobContext context) throws Exception;
}
```

P1 注册：

- `portfolio_snapshot`
- `indicator_history`
- `retention_cleanup`

### AGENT

调度器写入 `agent_commands` 或通过 agent 心跳下发：

```json
{
  "command": "QUERY_ACCOUNT_POSITION",
  "jobKey": "ctp_close_query",
  "accountId": "TEST-001",
  "reason": "scheduled close query"
}
```

agent 侧约束：

- 只在 CTP 已登录（`login_status=LOGGED_IN`）后执行
- 在现有 CTP 会话内查询
- 不创建第二个 CTP session
- 执行结果上报 `scheduled_job_runs`

短期兼容：

- 保留适配器内部 `ctp-query-schedule.conf` 作为执行层
- 调度器 P1 只负责展示/配置/手动触发，实际查询仍由适配器完成
- P2 再统一迁移到 agent command

### SYSTEMD_READONLY

P1 只读：

- 读取 `systemctl show <unit> -p ActiveState,NextElapseUSecRealtime,LastTriggerUSec`
- 或解析 `systemctl list-timers --output=json`
- 不提供编辑
- 后续迁移到 INTERNAL 后再开放配置

## 8. 管理页面

路由：`/scheduler`，放在“数据与接入”分组。

页面结构：

- 顶部：任务总数、启用数、失败数、下次执行
- 筛选：类型、状态、关键字
- 表格列：
  - 任务名
  - 类型
  - 计划
  - 启停
  - 上次执行
  - 上次状态
  - 下次执行
  - 操作：编辑、手动触发、历史
- 详情抽屉：
  - 最近 50 次执行记录
  - 错误信息
  - 配置修改
  - 审计信息

手动触发：

- 需要二次确认
- 写审计 `SCHEDULED_JOB_MANUAL_RUN`
- 返回 runId，前端轮询/WS 获取结果

## 9. 权限与安全

- 只有 ADMIN 能修改/触发
- TRADER 只读
- 所有配置修改、手动触发写 audit_log
- 禁止自由填写 shell 命令
- AGENT 任务只允许白名单 command
- SYSTEMD_READONLY 不提供写接口
