## 1. 目标

把当前运行在交易主机上的 SimLocal 匹配器，升级为**独立部署的模拟交易所（Sim Venue）**，同时保证：

```text
1. Runner / Control Plane / Agent 仍然把它当作正常交易所
2. 所有接入走正式 Aeron/SBE 合同
3. 不存在 simInprocess / 直连 Java 对象 / HTTP tick 的旁路
4. 模拟交易所与 CTP Adapter 平级，不互相调用
5. 可跨主机部署，不依赖 aeron:ipc
6. 支持订单、撤单、回报、成交、行情、持仓、对账和重启恢复
```

一句话：

```text
Sim Venue 是交易所，不是控制面的一个内置服务；
CTP Adapter 是另一个交易所的适配器；
两者共享正式接入合同，但互不依赖。
```

---

## 2. 非目标

第一版不做：

```text
真实交易所 wire protocol（CTP 二进制/FIX 完整兼容）
公网暴露
真实资金/真实清算
多地域容灾
完整交易所规则（集合竞价、期权行权、交割）
```

第一版要做：

```text
独立进程/独立主机
Aeron/SBE 正式合同
独立账本与 journal
可恢复、可对账、可观测
```

## 3. SimLocal 历史问题与 V2 更新

SimLocal 历史形态（已淘汰）：

```text
Trading Host
  ├─ Runner
  ├─ Control Plane（SimExchangeService 仅保留行情/本地 canary；无 simInprocess 下单分支）
  ├─ SimExchange（2120-2123）
  └─ sim-venue 内置行情生成器（1001）
```

> V2 更新（2026-11-10）：control-plane 已删除 `SimExchangeService` 和 canary 下单支路；
> 模拟撮合只由独立 `sim-venue` 承担。control-plane 仅保留 `StrategyOrderExpiryService`
> 做策略挂单的 TTL 撤单，不再持有任何进程内撮合器。

SimLocal 阶段主要问题（历史）：

```text
1. aeron:ipc 只能同机
2. Control Plane 的 in-process SimExchange 快速路径（V2 已删除）
3. SimExchange 只有单账户/单账本，缺少 venue 级 journal
4. stream 和 channel 写死
5. 重启只恢复持仓，不恢复完整订单/成交/账户状态
6. 远程部署没有 session / auth / fencing 的完整边界
```

## 4. 目标架构

```text
Trading Host                              Exchange Host
------------                              -------------
Strategy Runner ── Aeron/UDP ───────────▶ Sim Venue Gateway
Control Plane   ── Aeron/UDP ───────────▶   ├─ Session / Auth / Fencing
                                            ├─ Sequence / Heartbeat
                                            ├─ Fan-out / Egress
                                            ├─ Market Data Publisher
                                            └─ Venue Core
                                                 ├─ Order Book
                                                 ├─ Matching Engine
                                                 ├─ Account Ledger
                                                 ├─ Position / Fee / Margin
                                                 ├─ OrderUpdate / Trade
                                                 ├─ Journal
                                                 └─ Snapshot
```

职责：

| 组件 | 职责 |
|---|---|
| Sim Venue Core | 撮合、订单簿、账户、持仓、费用、快照 |
| Sim Venue Gateway | Aeron/SBE、session、fencing、序列、fan-out、健康 |
| Sim Venue Store | journal、snapshot、恢复 |
| Sim Venue MD | 5 档行情、时间戳、网络发布 |
| Venue Registry | venue/account/ORS/channel 注册与发现 |
| Control Plane | 管理面、异步消费、审计、UI、对账 |
| Runner | 策略、本地风控、直接 Aeron |
| CTP Adapter | 真实 CTP 接入，和 Sim Venue 平级 |

## 5. 正式接入合同

### 5.1 消息

沿用现有 SBE：

```text
OrderRequest
CancelRequest
OrderUpdate
Trade
MarketData
PositionSnapshot
AccountSnapshot
GatewayHealth
```

### 5.2 必填字段

```text
accountId
strategyKey
requestId
sequence
targetAgentId
routeId
fencingToken
```

### 5.3 接入规则

```text
手工单、策略单、算法单统一走 OrderRouter
  → account 的 ACTIVE ORS
  → venue channel + streams
  → Aeron
```

禁止：

```text
if SIM → 直接调用 Java SimExchange
if CTP → 走 Aeron
```

### 5.4 顺序与幂等

```text
每个 venue stream 有单调 sequence
OrderRequest 按 clientOrderId 幂等
OrderUpdate 拒绝旧 sequence
Trade 按 tradeId 幂等
旧 fencingToken 直接拒绝
```

## 6. 传输与部署

### Phase 1：同机独立进程

```text
Sim Venue 独立 JVM
仍使用 aeron:ipc
先移除 in-process 分支
```

目的：证明“没有控制面特殊路径也能交易”。

### Phase 2：独立主机

```text
Sim Venue 独立 Linux 主机
aeron:udp
独立 media driver
独立磁盘
```

目的：证明“跨主机仍像正常交易所一样接入”。

### Phase 3：生产化

```text
journal + snapshot + replay
多客户端 fan-out / multicast
active-passive 或 Aeron Cluster
网络隔离 / VPN / allowlist
故障注入和场所级对账
```

### Channel 设计

`ors_instances` 及 venue registry 需要从“只有 stream”扩展为“channel + stream”：

```text
order_channel
cancel_channel
update_channel
trade_channel
md_channel
```

示例：

```text
SimLocal local:
  order_channel = aeron:ipc
  order_stream  = 2120

Sim Venue remote:
  order_channel = aeron:udp?endpoint=10.0.0.20:20120
  order_stream  = 2120

CTP SimNow:
  order_channel = aeron:ipc
  order_stream  = 2100
```

注意：

```text
stream id 只在 channel 内唯一
不能假设 2120 在所有 venue 上唯一
```

## 7. Venue 数据与恢复

### 7.1 账户模型

第一版建议：

```text
一个 Sim Venue 可以承载多个 account
每个 account 独立 cash / positions / orders / trades
```

如果为了快速落地，也可以：

```text
一个 account = 一个 Sim Venue 实例
```

但这会限制后续多账户测试；设计上应预留多账户模型。

### 7.2 Journal

```text
OrderRequest
CancelRequest
OrderUpdate
Trade
AccountSnapshot
PositionSnapshot
```

append-only，按 venue + sequence 排序。

### 7.3 Snapshot

```text
order book snapshot
account ledger snapshot
position snapshot
last sequence
last requestId
```

### 7.4 恢复

```text
启动 → load snapshot → replay journal → 校验 sequence
→ 拒绝旧 fencing token / 旧 sequence
→ 发布 GatewayHealth
```

不能只恢复持仓；必须恢复订单、成交、账户与 sequence。

## 8. 行情

Sim Venue 应该拥有自己的行情发布：

```text
Sim Venue MD
  → 5 档盘口
  → Aeron MD channel
  → Runner / Control Plane
```

行情源可以是：

```text
synthetic
replay
外部行情适配器
```

但**发布者**是 Sim Venue；Runner 只从 Aeron 消费，不通过 Control Plane HTTP。

---

## 9. 安全与所有权

```text
1. 只允许内网/VPN/专线访问，不暴露公网
2. Venue Gateway 校验 accountId / targetAgentId / routeId / fencingToken
3. 每个 account 只允许一个 ACTIVE ORS
4. 拒绝旧 fencing token
5. 限制 rate / max order size / max message size
6. 记录 session、登录、拒绝、断线
7. Aeron UDP 没有内置加密，必须网络层隔离
```

## 10. 可观测性与对账

### 指标

```text
venue_up
matching_latency_p50/p99
order_rate
reject_rate
sequence_gap
journal_lag
snapshot_age
session_count
backpressure
```

### 对账

```text
Venue Snapshot
  → orders / trades / positions / accounts
  → Control Plane compare
  → mismatch = block OPEN
```

必须按 `account_id` 隔离，不能只用全局本地一致性。

## 11. 迁移步骤

```text
Step 0：设计定稿 + 接口冻结
Step 1：同机独立 Sim Venue，仍 IPC
Step 2：移除 simInprocess / 内置 SimExchange 下单（已完成）
Step 3：channel 配置化（aeron:ipc → aeron:udp）
Step 4：独立主机 + 独立 media driver + 独立磁盘
Step 5：journal / snapshot / replay
Step 6：session / fencing / security
Step 7：可观测性与场所对账
Step 8：双跑对比 → 切换 → 删除旧路径
```

双跑期间：

```text
同一策略同一时刻只能有一个 ACTIVE execution owner
旧 SimLocal 与新 SimVenue 不能同时接受同一账户订单
```

## 12. 验收标准

```text
[ ] Runner/Control Plane 不知道 Sim Venue 是模拟器
[ ] 手工单和策略单走同一条 OrderRouter
[x] 没有 simInprocess 分支
[ ] 没有 HTTP tick 作为远程 venue 行情
[ ] Sim Venue 跨主机可连接
[ ] 断网后 fail-closed，不重复下单
[ ] 重启后订单/成交/持仓/账户/sequence 可恢复
[ ] 旧 fencingToken / 旧 sequence 被拒绝
[ ] 场所 vs 本地 orders/trades/positions/accounts = 0 差异
[ ] 故障注入通过：断网、重启、重复、背压、磁盘慢、时钟偏移
[ ] 双跑期间两个 SimLocal 不会同时成交
```

## 16. 7×24 模拟交易所例外

Sim Venue 是模拟交易所，不受真实交易日历和交易时段限制：

```text
venue_type = SIM
  → 24×7 接受订单
  → 不检查今日是否交易日
  → 不检查品种日盘/夜盘
  → 手工单、策略单、回放测试均可在周末执行
```

实现边界：

```text
1. Control Plane 只对 venue_type=SIM 跳过日历/时段门禁
2. Runner 本地 risk snapshot 返回 calendarRequired=false
3. CTP / SimNow / SimShengli 仍然强制执行真实交易日历
4. Sim Venue 服务自身不依赖交易日历
5. 策略如果需要模拟收盘平仓，必须显式配置，不自动套用真实收盘
```

这不是放宽真实交易风控，而是承认：

```text
Sim Venue 是一个 7×24 的独立模拟交易所
```
