# 模拟交易所（CTP Adapter 接口）设计

- 日期：2026-11-06
- 对应任务：T-027
- 同类产品调研：`docs/research/simulated-exchange-landscape.md`
- 目标：在 **CTP Adapter 的 `CtpSession` 接口**下实现一个可配置的模拟交易所，尽量模拟真实交易所的行情、报单、撤单、查询与异步回报行为。

---

## 1. 接口位置

```text
ORS Core / Runtime
      │  OrderRequest / CancelRequest (Aeron + SBE)
      ▼
CTP Adapter
      ├── CtpLiveSession   : 真实 CTP Trader/MD SPI
      └── SimulatedCtpSession : 模拟交易所
                │
                ├── ReplayMarketData  真实 tick + 抖动
                ├── MatchingEngine    价格-时间优先
                ├── LatencyQueue      异步随机延迟
                ├── ExchangeRules     涨跌停/tick/lot/时段
                └── AccountLedger     资金/持仓/手续费
```

模拟器不改变 ORS Core 的接口，只替换 CTP Adapter 内部的 `CtpSession` 实现。

---

## 2. 能模拟什么

| 能力 | 可模拟程度 | 说明 |
|---|---|---|
| 登录/认证/结算确认 | 高 | 按 CTP 回调顺序返回成功/失败/超时 |
| 行情订阅 | 高 | 基于真实 tick 回放，支持 5 档盘口 |
| 行情抖动 | 高 | 价格/量/盘口随机扰动，可配置幅度与分布 |
| 限价单/市价单 | 高 | 价格-时间优先撮合 |
| 部分成交 | 高 | 大单吃薄盘口，多次成交回报 |
| DAY/FAK/FOK/IOC | 高 | 按规则撤剩余/全撤 |
| 开平/平今/平昨 | 中高 | 按交易所规则模拟，需规则表 |
| 撤单/改单 | 高 | 撤单回报、未知单拒绝 |
| 资金/持仓查询 | 高 | 成交后更新，按查询时点返回 |
| 报单拒单 | 高 | 价格越界、数量越限、资金不足、非交易时段 |
| 涨跌停/最小变动/手数 | 高 | 配置驱动 |
| 交易时段/午休/夜盘 | 中高 | 需交易日历；夜盘归属下一交易日 |
| 集合竞价 | 中 | 可模拟开盘/收盘竞价，但队列细节近似 |
| 断线/重连 | 高 | 主动注入断线、重连、重复登录 |
| 查询限流 | 高 | 每秒查询次数限制 |
| 异步延迟 | 高 | 报单/撤单/查询/行情分别配置延迟分布 |
| 自成交预防 | 中 | 可模拟“拒绝/撤销/允许”策略 |
| 交易所拒单码 | 中 | 可模拟常见错误码，精确文本需规则表 |
| 期权基本撮合 | 中高 | 期权合约、盘口、成交可模拟 |
| 期权保证金 | 中 | 需保证金公式/参数 |
| 行权/指派 | 低 | 第一版不做，后续按规则表 |

---

## 3. 做不到 / 只能近似

| 项目 | 原因 | 建议 |
|---|---|---|
| 真实隐藏流动性/冰山单 | 交易所内部不可见 | 只能建模近似 |
| 精确排队位置 | 取决于真实撮合和撤单时序 | 用概率/队列模型 |
| 做市商保护/报价义务 | 交易所规则不公开或不完整 | 按规则配置近似 |
| 真实对手方行为 | 不可观测 | 用统计模型 |
| 交易所内部风控 | 不对外公开 | 只模拟常见拒单 |
| 精确结算/交割 | 交易所/柜台内部流程 | 第一版不做 |
| 期权行权/指派 | 规则复杂，且当前阶段不做行权 | 后续任务 |
| CTP 二进制 wire protocol | 模拟器在 SPI 层，不在网络层 | 如需要另做协议模拟器 |
| 真实网络抖动 | 依赖物理网络 | 用延迟分布近似 |
| 交易所手续费阶梯 | 依赖账户/成交量 | 配置费率表 |

## 4. 需要更多信息才能做准

1. **交易所/品种范围**：只做 SHFE au/ag，还是 DCE/CFFEX/ZCE 也要？
2. **合约规则**：tick、lot、乘数、涨跌停、保证金率、手续费、最大单笔。
3. **交易时段**：日盘/夜盘/午休/集合竞价/节假日，夜盘归属规则。
4. **撮合规则**：价格-时间优先？是否支持市价保护、FAK/FOK、平今/平昨。
5. **自成交预防**：拒绝、撤销还是允许？
6. **拒单码**：需要模拟哪些 CTP 错误码和文本？
7. **延迟分布**：p50/p99 目标、是否区分报单/撤单/查询/行情。
8. **行情数据源**：u50 全天文件、ClickHouse、还是实时回放？是否包含期权链？
9. **期权规则**：保证金公式、行权/指派、到期处理。
10. **账户初始状态**：资金、持仓、手续费率。
11. **可复现性**：固定 seed 是否必须逐笔一致。
12. **故障注入场景**：断线、重复登录、查询超时、部分成交、拒单。

## 5. 配置草案

```yaml
seed: 42
mode: replay              # replay | synthetic
replay:
  file: /data/u50_data/20260318/source/u50_20260318.csv
  speed: 10               # 10x
  loop: false
jitter:
  price_ticks: 0.5
  size_pct: 0.1
  book_levels: 5
latency_ms:
  order_ack: {p50: 2, p99: 15}
  cancel_ack: {p50: 2, p99: 12}
  query: {p50: 20, p99: 100}
  market_data: {p50: 1, p99: 5}
matching:
  algorithm: price_time
  partial_fill: true
  self_trade: reject
rules:
  instruments:
    au2612:
      exchange: SHFE
      tick: 0.02
      lot: 1
      multiplier: 1000
      price_limit_pct: 0.08
      margin_rate: 0.10
faults:
  disconnect_every_n_orders: 0
  reject_rate: 0.001
  duplicate_ack_rate: 0
```

## 6. 实现顺序

1. `SimulatedCtpSession` 骨架 + 配置 + 登录/订阅
2. Replay 行情 + 抖动 + 5 档盘口
3. 撮合引擎 + 限价/市价/部分成交
4. FAK/FOK/DAY/撤单
5. 资金/持仓/手续费
6. 异步延迟队列 + 固定 seed
7. 拒单/断线/重连/限流
8. 规则表（SHFE au/ag 优先）
9. 与 ORS Core 联调 + 行为差异报告

---

## 7. 验收原则

- 同一 seed、同一输入，成交/回报必须可复现。
- 延迟是“可配置的随机”，测试断言区间而不是精确值。
- 所有“模拟不了”的行为必须在报告里显式列出，不能假装一致。
- 模拟器不能绕过 ORS Core 的风控与审计。
