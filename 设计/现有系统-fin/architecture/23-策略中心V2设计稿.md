## 1. 结论

V2 采用**策略中心**，不再使用顶部柜台选择器。

```text
策略是交易意图、持仓、PnL、订单、成交和风控的主对象。
柜台 / 交易所 / 账户 / ORS / Agent 是策略的部署属性。
```

登录用户、交易账户、策略是三层不同概念：

```text
登录用户：test_admin
交易账户：SIMLOCAL-001 / SIMVENUE-001
策略：TEST-STRAT-PAIR-01 / TEST-STRAT-HEDGE-01
```

交易员进入系统后，首先看到的是策略，而不是“当前柜台”。

本版已在第 17 节逐项回答交易员复审的 10 项 P0、17 项 P1、10 项 P2。

---

## 2. 已确认业务约束

```text
1. 一个柜台可以对接多个交易所。
2. v1 一个柜台 = 一个账户。
3. 一个账户可以有多个策略。
4. 一个策略只能部署在一个 Agent / 柜台 / 账户 / ORS。
5. 不支持跨柜台策略。
6. 策略必须有持仓，否则无法计算策略 PnL 和风险。
7. 策略 PnL 按策略自身成交和持仓计算。
8. 账户 PnL 以柜台账户快照为权威，并与策略汇总对账。
9. 订单、成交、持仓都必须带账户 / 柜台 / 策略 / 交易所属性。
10. 只有总持仓页面以账户为维度汇总。
11. 手工单必须有归属，不能出现无主 PnL。
12. 紧急操作默认作用于当前策略，账户/全部范围必须显式选择。
```

## 3. 领域模型

### 3.1 分层

```text
登录用户 User
  └─ 权限：可访问的账户 / 策略

柜台 Counterparty
  ├─ 支持的交易所：SHFE / DCE / CZCE / CFFEX / INE / SIM
  ├─ 行情通道
  ├─ 下单 / 撤单 / 回报 / 成交通道
  ├─ 交易日历 / 交易时段
  └─ 账户 Account（v1 1:1）

账户 Account
  └─ ORS Instance（v1 1:1）

策略 Strategy
  └─ StrategyDeployment（一个策略同一时刻只允许一个 ACTIVE 部署）
       ├─ Agent
       ├─ Counterparty
       ├─ Account
       ├─ ORS
       └─ Environment
```

### 3.2 柜台与交易所分离

柜台不是交易所：

```text
SimNow 柜台可以接 SHFE / DCE / CZCE / CFFEX
SimShengli 柜台同理
SimVenue 是模拟柜台/模拟交易所
```

因此数据模型必须有：

```text
counterparty
counterparty_exchange
account
instrument.exchange
orders.exchange
trades.exchange
```

不能只靠 `counterparty.exchange` 一个字段。

### 3.3 策略

```text
Strategy
  strategy_id
  name
  type
  version
  status
  config

StrategyDeployment
  deployment_id
  strategy_id
  generation
  agent_id
  counterparty_id
  account_id
  ors_id
  environment
  desired_state
  actual_state

Strategy 绑定上下文（首次部署后不可变）
  bound_agent_id
  bound_counterparty_id
  bound_account_id
  bound_ors_id
```

不变量：

```text
一个策略最多一个 ACTIVE deployment
一个策略不能同时部署到两个账户/柜台
策略切换部署上下文必须产生新 deployment generation
```

部署状态机：

```text
UNBOUND → BOUND → ACTIVE
                 └→ FAILED
ACTIVE → STOPPING → INACTIVE
FAILED/ACTIVE → ROLLED_BACK
```

部署前固定流程：

```text
cancel → drain → reconcile → release → bind → deploy
```

失败自动回滚上一稳定版本；LIVE/ACTIVE 部署需要审批或二次确认。

### 3.4 策略生命周期与不可迁移约束

```text
strategy_status:
  DRAFT       草稿，尚未首次部署
  VALIDATED   配置校验通过，尚未部署
  ARCHIVED    归档，不再运行

deployment_status:
  UNBOUND           从未部署
  BOUND             已首次部署，绑定上下文，但当前停止
  ACTIVE            当前运行
  INACTIVE          已部署但未激活
  FAILED            部署失败
  STOPPING          正在停止/撤单/drain
  ROLLED_BACK       已回滚到上一稳定版本
```

```text
strategies
  strategy_id
  parent_strategy_id       Fork 来源
  forked_from_version
  bound_agent_id           首次部署后不可变
  bound_counterparty_id    首次部署后不可变
  bound_account_id         首次部署后不可变
  bound_ors_id             首次部署后不可变（逻辑 ORS 槽位）
  strategy_status          DRAFT / VALIDATED / ARCHIVED
  deployment_status        UNBOUND / BOUND / ACTIVE / INACTIVE / FAILED / STOPPING / ROLLED_BACK
  current_version
```

规则：

```text
首次部署时写入 bound_agent_id / bound_counterparty_id / bound_account_id / bound_ors_id
四者一旦写入，不可清空、不可改绑
停止、INACTIVE、FAILED 都不解除绑定
已部署策略不能出现在“选择策略部署”列表
更新版本只能部署到同一个 Agent/Account/ORS
要换 Agent 只能 Fork 新策略

v1 一账户一 ORS：Fork 到另一个 Agent 必须使用另一个账户/柜台；
同一账户的多个策略可以共享同一个 ORS，但不能生成第二个 ORS。
```

数据库和服务端都必须校验四元组：

```text
strategy_deployments.agent_id       == strategies.bound_agent_id
strategy_deployments.counterparty_id == strategies.bound_counterparty_id
strategy_deployments.account_id     == strategies.bound_account_id
strategy_deployments.ors_id         == strategies.bound_ors_id
```

任何一项不一致返回：

```text
409 STRATEGY_BOUND_TO_CONTEXT
```

`bound_ors_id` 是逻辑 ORS 槽位；ORS 进程重启、PID 变化不改变槽位；更换 `ors_id` 视为更换执行上下文，必须 Fork。

Fork 目标规则（v1）：

```text
原策略的 Agent/Account/Counterparty/ORS 四元组保持不变
Fork 必须选择另一个未绑定的账户/柜台/ORS/Agent
同一账户不能创建第二个 ORS；因此同账户 Fork 到另一个 Agent 不允许
同一账户可以有多个策略，但只能共享同一个 ORS
```

### 3.5 策略版本

```text
strategy_versions
  strategy_id
  version
  config_json
  parent_version
  created_by
  created_at
  change_note
```

编辑已部署策略只生成新版本，不覆盖运行中的配置：

```text
编辑 → 新 draft version → 校验 → 更新到当前 Agent
```

历史版本保留，可回滚，但只能回滚到同一个 Agent。

版本更新规则：

```text
默认：停止新开仓 → 撤销挂单 → 平仓 → 对账 → 更新到当前 Agent
高级：显式“携带持仓升级”，必须填写原因并二次确认
```

- 默认平仓后更新，避免旧逻辑接管新持仓
- 携带持仓升级时，`position_epoch` 不变，`deployment_generation` 变化
- `strategy_positions` 的归属键为 `(book_id, position_epoch, account_id, exchange, instrument_id)`
- `deployment_id` 只做成交来源/审计，不作为持仓归属主键
- PnL 曲线标记版本切换点，不能静默混算
- 版本更新不得改变绑定 Agent

### 3.6 Fork

Fork 生成新策略 ID，不移动原策略：

```text
源策略: TEST-STRAT-PAIR-01 (bound agent-simlocal-01)
Fork:   TEST-STRAT-PAIR-01-FORK-01
        parent_strategy_id = TEST-STRAT-PAIR-01
        forked_from_version = v3
        复制配置
        不复制持仓、订单、成交、PnL、运行状态
        可选择新的 Agent / 柜台 / 账户
```

Fork 不继承持仓；新策略从零开始形成自己的 PnL 和持仓历史。

### 3.7 交易簿 Book

手工单不能是无主的。使用独立 `Book` 实体，而不是把手工簿伪装成可部署策略：

```text
Book
  book_id
  book_type       STRATEGY / MANUAL / UNASSIGNED
  account_id
  counterparty_id
  owner_user_id
  display_name
  status
```

| book_type | book_id | 说明 |
|---|---|---|
| STRATEGY | strategy_id | 自动策略，可部署 |
| MANUAL | UUID | 每账户默认一个手工簿，手工单归属；记录 owner_user_id，v1 不支持子簿，v2 可扩展 |
| UNASSIGNED | UUID | 外部/未知成交，待认领 |

手工簿：

- 出现在账户汇总、总持仓和手工簿页面
- 不出现在策略部署列表、策略排名、自动收盘调度
- 不显示“部署/激活/停止策略”
- 只显示手工簿专用动作：撤单、平仓、只减仓

`strategy_positions` 主键/唯一键：

```text
(book_id, position_epoch, account_id, exchange, instrument_id)
```

`deployment_id` 只作为成交来源/审计，不作为持仓归属键。成交事务必须同时更新数量、均价、`realized_pnl`、`fees`；日终执行 today→yesterday；期权到期/行权单独处理。

`strategy_positions` 只统计 `book_type=STRATEGY`；手工簿/未分配持仓写入独立的 `book_positions`：

```text
book_positions
  book_id
  book_type        MANUAL / UNASSIGNED
  account_id
  counterparty_id
  exchange
  instrument_id
  source
  as_of
  stale
  long_qty / short_qty
  today_long / today_short
  yesterday_long / yesterday_short
  avg_price
  realized_pnl
  fees
  updated_at
```

账户归因只从两类表读取一次：

```text
attributed = sum(strategy_positions book_type=STRATEGY)
           + sum(book_positions book_type=MANUAL)
```

未分配持仓只来自 `book_positions book_type=UNASSIGNED`，不能与手工簿混用。

### 3.8 持仓等式与权威来源

账户持仓以柜台快照为权威：

```text
account_position = counter snapshot（权威）
```

策略持仓和手工簿是归因：

```text
attributed_position = sum(strategy positions) + manual book position
unassigned_position = account_position - attributed_position
```

`unassigned_position` 只能是差额和待认领项，不能作为配平万能项，也不能静默塞进某个策略。

### 3.9 策略平仓校验

策略平仓先使用策略自身持仓，再与账户可平量取更严格者：

```text
A 策略持仓 2，B 策略持仓 8，账户持仓 10
A 平 5
→ 策略可平量 2 不足，拒绝 STRATEGY_POSITION_INSUFFICIENT
A 平 2
→ 策略和账户都允许，成交后账户 8、A 0、B 8
```

规则：

- 今昨仓、平今/平昨基于策略持仓解析
- 同时校验账户快照可平量；任一不足拒绝
- 同一 `(book_id, epoch, account_id, exchange, instrument_id)` 下单/成交加行锁或乐观版本
- `applyFill` 不允许 clamp 负数；超平直接报错
- 服务端生成 reduce-only 订单

```text
  counterparty_id

```

`position_epoch` 只在策略明确重置持仓归属时递增；普通版本更新、deployment generation 变化不改变 epoch。Fork 新策略从 epoch 0 开始。

一个策略可以跨多个交易所持仓，但只能属于一个柜台/账户。

### 5.2 账户总持仓

```text
account_positions

  short_qty

```

账户总持仓是唯一以账户为维度的持仓汇总页。

### 5.3 持仓权威来源与对账

账户持仓以柜台快照为权威：

```text
account_position = counter snapshot
```

策略持仓和手工簿只做归因：

```text
attributed_position
  = sum(strategy_positions)
  + manual_book_position

unassigned_position
  = account_position - attributed_position
```

`unassigned_position` 是待认领差额，不是配平项：

- 外部成交
- 手工补录
- 历史遗留
- 策略归属丢失

新增表：

```text
unassigned_trade
  trade_id
  account_id
  counterparty_id
  exchange
  instrument_id
  side
  price
  qty
  source
  status
  assigned_to_book_id
  assigned_by
  assigned_at

position_assignment
  assignment_id
  trade_id
  from_book_id
  to_book_id
  qty
  reason
  approved_by
  created_at
```

认领流程：

- 运维/风控页面展示未分配成交和持仓
- 认领到策略/手工簿必须写审计
- 超过 60s 未认领告警；重大金额/手数可配置阻止该账户新开仓
- 外部成交不得自动归入策略

策略平仓、策略风控、策略 PnL 只使用策略自身持仓；账户持仓只用于账户级风控和汇总对账。

## 6. 策略 PnL 与账户 PnL

### 6.1 策略 PnL

```text
strategy PnL
  = realized PnL
  + unrealized PnL
  - fees
```

未实现盈亏使用策略部署柜台/交易所的行情：

```text
(counterparty_id, exchange, instrument_id)
```

不能使用其他柜台的同合约价格。

PnL 口径：

```text
已实现：FIFO，逐笔成交归属到策略
手续费：trades.fee 逐笔计入，策略 PnL 汇总
未实现：mark source 可配置 LAST / SETTLEMENT / THEORETICAL
期货：盘中 LAST，日终 SETTLEMENT
期权：合约乘数 + mark source + Greeks/IV，按标的/到期/交易所分组
手工簿：book_positions.realized_pnl/fees + 行情估值
账户 PnL：柜台账户快照权威；与策略汇总差异显示为 RECON_DIFF
```

所有 PnL 显示 `asOf/source/stale`；FIFO 与柜台结算口径差异只显示、不静默覆盖。

### 6.2 账户 PnL

```text
account PnL
  = 柜台账户快照权益变化
  = 权威值
```

策略汇总只用于归因和对账：

```text
account PnL
  ≈ sum(strategy PnL)
  + manual PnL
  + unassigned PnL
```

差异必须显示：

```text
STRATEGY_RECON_DIFF
UNASSIGNED_PNL
```

不能静默覆盖账户权威值。

### 6.3 多策略共享账户

同一个账户可以运行多个策略：

```text
SIMLOCAL-001
  ├─ TEST-STRAT-PAIR-01
  ├─ TEST-STRAT-HEDGE-01
  ├─ TEST-STRAT-OPT-01
  └─ MANUAL-SIMLOCAL-001
```

账户汇总：

```text
账户持仓 = 柜台快照（权威）
attributed = 各策略持仓 + 手工簿持仓
unassigned = 账户持仓 - attributed
```

账户 PnL：

```text
账户 PnL = 柜台账户快照权益变化（权威）
策略归因 PnL = 各策略 PnL + 手工簿 PnL + 未分配 PnL
```

共享账户的保证金和可用资金以柜台账户为权威；策略只能配置“风险预算/归因额度”，不能把柜台保证金强行拆成互不相干的多个钱包。

策略详情显示：

```text
账户可用 / 账户已占用 / 本策略估算占用
同账户其他策略合计持仓 / PnL
账户级挂单数 / 成交手数 / 限额
```

下单同时校验账户级和策略级限额；策略 A 用满预算不能阻止账户真实可用资金，但可以拒绝 A 的新开仓，B 仍按账户级限额校验。

每个策略的订单/成交必须带 `book_id` 和 `strategy_id`（自动策略）；否则不能做策略归因。

### 6.4 账户 PnL 快照

```text

  account_id
  trading_day
  as_of
  equity
  cash
  deposit
  withdraw
  realized
  unrealized
  fees
  source
  stale
```

- 账户 PnL 以“上一交易日结算权益”为基准
- 出入金、手续费、交割/行权、资金费必须单列或剔除
- 策略 PnL 与账户 PnL 的 `diff/tolerance/stale/last_success` 可见
- 默认容差：`max(100 CNY, 0.1% equity)`，连续 2 次告警
- 账户快照陈旧 >5s 或差异超过阈值时阻止新开仓，只允许平仓/撤单

## 8. 策略交易与路由

### 8.1 策略执行上下文

```text
StrategyExecutionContext
  strategyId
  deploymentId
  deploymentGeneration
  agentId
  counterpartyId
  accountId
  orsId
  environment
```

订单、撤单、回报、成交都必须以它为准。

### 8.2 路由

```text
策略订单
  → 校验 strategy / deployment / account / counterparty
  → 校验 account 的 ACTIVE ORS
  → 校验 ORS fencingToken / generation
  → 选择柜台订单流
  → 发布
```

没有有效路由：

```text
NO_ACTIVE_ROUTE
```

不得回退 legacy stream，不得自动切到其他柜台。

### 8.3 回报保护

`OrderUpdate` / `Trade` 必须带：

```text
bookId
strategyId
deploymentId
deploymentGeneration
accountId
counterpartyId
exchange
orsId
fencingToken
routeId
orderEpoch
```

消费端只接受匹配当前 `deploymentGeneration + orsId + fencingToken + routeId` 的回报。

旧 generation / 旧 ORS / 旧 fencingToken / 旧 route：

```text
STALE_UPDATE
```

记录告警并丢弃，不能覆盖新状态。

旧 ORS 必须进入 `FENCED` 状态，不能继续消费其回报：

```text
FENCED → 人工/新 ORS 查柜台确认 → 重新绑定新 route/fencingToken
```

状态机禁止：

```text
FILLED → CANCELED
CANCELED → FILLED
```

除非人工对账调整并写审计。

### 8.4 策略上下文版本

`deploymentGeneration` 同时作为策略执行上下文版本：

```text
StrategyContextVersion = deploymentId + deploymentGeneration
```

预检、下单、撤单、批量操作必须携带：

```text
bookId
strategyId
deploymentId
deploymentGeneration
```

版本变化后旧的 preview 立即失效；服务端返回 `409 CONTEXT_CHANGED`，要求重新预检。

### 8.5 CTP / SBE 归属链路

当前 SBE 的 `OrderRequest/OrderUpdate/Trade` 字段不足以完整表达策略归属，必须升级协议：

```text
OrderRequest:
  bookId
  strategyId
  deploymentId
  deploymentGeneration
  accountId
  counterpartyId
  exchange
  targetAgentId
  orsId
  fencingToken
  clientOrderId
  requestId

OrderUpdate / Trade:
  bookId
  strategyId
  deploymentId
  deploymentGeneration
  accountId
  counterpartyId
  exchange
  orsId
  fencingToken
  requestId
```

SBE 升版要求：

采用**新增 v2 消息**，不原地修改 v1 字段：

```text
OrderRequestV2   message id=20
OrderUpdateV2    message id=21
TradeV2          message id=22
MarketDataV2     message id=23
PositionSnapshotV2 message id=24
```

公共新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| bookId | BookId (fixed 64) | STRATEGY/MANUAL/UNASSIGNED |
| strategyKey | StrategyKey (fixed 64) | 字符串策略键 |
| deploymentId | uint64 | 部署 ID |
| deploymentGeneration | uint64 | 部署版本 |
| accountId | AccountId | 账户 |
| counterpartyId | GatewayId | 柜台/接入通道 |
| exchange | Exchange enum | SHFE/DCE/CZCE/CFFEX/INE/SIM |
| orsId | GatewayId | 执行实例 |
| fencingToken | uint64 | 所有权 fencing |
| routeId | uint64 | 路由版本 |
| orderEpoch | uint64 | 订单 epoch |

兼容：

```text
OrderRequest.strategyId(int32) 只保留为旧字段
bookId/strategyKey 字符串是 V2 归属键
v1 消息进入兼容队列，不得直接更新策略持仓
```

CTP/ORS 侧要求：

- 收到订单时持久化 `clientOrderId → executionContext` 映射，重启可恢复
- CTP 回报按 `OrderRef/clientOrderId` 回填 `bookId/strategyId/accountId/counterpartyId/exchange`
- 无映射的回报进入 `UNASSIGNED`，不得猜策略
- 旧协议回报只能进入兼容队列，不能直接更新策略持仓，不能直接更新策略持仓

在协议升级完成前：

```text
strategy_positions = 本地归因账
account_positions = 柜台快照权威
```

两者差异必须显示，不能宣称策略持仓已经与 CTP 完全一致。

### 8.6 跨交易所

一个策略可以通过同一柜台交易多个交易所的合约：

```text
策略 A
  柜台 SimNow
  账户 TEST-001
  SHFE au2612
  DCE TA701
```

策略详情按交易所分组展示持仓和 PnL。

策略不能跨柜台；跨柜台组合只能在账户/组合汇总层表达，不能伪装成单个策略。

## 14. 迁移方案

### Phase 1：数据模型、SBE 与权限

- `counterparty_exchange` 关联表
- `orders/trades` 增加 `book_id/strategy_id/deployment_id/deployment_generation/account_id/counterparty_id/ors_id/fencing_token/route_id/order_epoch/environment/exchange`
- 建立 `book_type=MANUAL` 手工簿与 `book_positions`
- 回填现有策略订单；无归属成交进入 `UNASSIGNED`
- SBE v2 消息冻结（字段 ID/类型/版本），旧 v1 进入兼容队列
- 行情键改为 `(counterparty_id, exchange, instrument_id)`
- `strategy_positions` / `account_positions` 增加交易所/epoch/source/as_of 字段
- 建立 `user_account_permission` 唯一键、默认拒绝
- `AuthorizationService` enforcement 接入所有数据/下单接口
- 启动时 invariants：一柜台一账户、一策略一 ACTIVE 部署、order stream 唯一
- 迁移脚本与校验：
  - 旧手工单按 `source/strategy_id` 回填 MANUAL book
  - trades 按 `client_order_id` 关联订单回填 book/strategy
  - 旧 `strategy_positions` 去重并补 `book_id/position_epoch/exchange/source/as_of`
  - 旧 `positions` 映射 `account_positions`
  - 旧 SBE 双写/兼容队列
  - 迁移后校验 `orders/trades without book = 0`，失败进入 UNASSIGNED
- 数据库约束：
  - `accounts.counterparty_id UNIQUE`（v1）
  - `strategy_deployments(strategy_id) WHERE status='ACTIVE'` 部分唯一索引
  - 运行中账户禁止修改 counterparty_id
  - 并发部署使用 generation/乐观锁

### Phase 2：成交归因、策略持仓与 PnL

- CTP/ORS `clientOrderId → context` 映射与 SBE v2 回报接入
- 策略持仓、成交归因、手工簿/未分配账本
- 策略 PnL 使用对应柜台行情
- 账户 PnL 快照与 `unassigned` 差额
- 策略平仓按策略/账户可平量取严格值并加锁
- 对账差异、旧 ORS/fencing、`FENCED` 状态机
- 权限 enforcement 验收

### Phase 3：策略只读界面

- 策略列表 / 策略详情（只读）
- 策略持仓、订单、成交、PnL、对账
- 顶部移除柜台选择器，但仅在所有数据页过滤与权限验证通过后
- 不在本阶段开放编辑/Fork/部署动作

### Phase 4：账户汇总

- 总持仓按账户
- 账户 PnL 以柜台快照为权威
- 手工簿与未分配认领
- 共享账户保证金/风险预算展示

### Phase 5：策略版本、Fork 与部署闭环

- `bound_agent/account/counterparty/ors` 不可变
- 编辑生成版本，更新到当前 Agent
- Fork 生成新策略，不继承持仓/PnL
- 部署 generation / drain / rollback / 审批
- Fork 必须选择新的账户/柜台/ORS/Agent 四元组
- 同一账户多策略共享同一个 ORS，不允许创建第二个 ORS

### Phase 6：应急与多柜台运维

- 策略级应急默认当前策略
- 账户/全局应急显式范围
- 多柜台/多交易所监控
- LIVE 审批、红色确认、环境隔离
- 旧 SBE 兼容队列清理

## 16. 已冻结的产品决定

1. 策略详情默认展示“全部交易所”，可按单个交易所筛选。
2. 手工簿不在策略列表主区，单独分组/账户汇总显示。
3. 策略 PnL 默认拆分为已实现、未实现、手续费、资金费四项。
4. 账户 PnL 与策略汇总差异的阈值按第 18 节配置，超过阈值告警，快照陈旧时阻止新开仓。
5. 版本更新默认先停止新开仓、撤单、平仓；携带持仓升级必须显式确认并填写原因。
6. v1 Fork 必须指向新的 Agent/账户/柜台/ORS 四元组；同一账户不能创建第二个 ORS，因此同账户 Fork 到另一个 Agent 不允许；同账户多策略共享同一个 ORS。
7. 共享账户保证金以账户权威，策略只做风险预算/估算归因，不拆成独立钱包。
8. 保留行情、期权链、手工交易页面；所有入口携带 book/strategy/account/counterparty/exchange 上下文。

## 19. P2 体验补充
