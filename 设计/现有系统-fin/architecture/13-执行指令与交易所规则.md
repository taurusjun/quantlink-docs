# 执行指令与交易所规则

- 状态：建议方案
- 日期：2026-11-07
- 目标：业务策略不感知交易所差异，执行层统一处理开平/平今/平昨

## 1. 问题

当前手工交易页和订单请求直接暴露 CTP 的 offset：

```text
OPEN / CLOSE / CLOSE_TODAY / CLOSE_YESTERDAY
```

不同交易所规则不同：

- SHFE / INE：区分平今、平昨，`CLOSE` 容易报“平仓仓位不足”
- DCE / CZCE / CFFEX / GFEX：通常只接受 `CLOSE`，不接受平今/平昨

如果让策略或交易员记住每个交易所的底层指令：

- 新增交易所必须改业务代码
- 容易下错 offset
- 策略无法跨交易所复用
- 风控和审计难以统一

## 2. 建议分层

```text
业务策略 / 手工交易
        ↓
Order Intent（语义化）
        ↓
Execution Policy（交易所规则适配）
        ↓
Order Router（拆单/风控/审计）
        ↓
Aeron OrderRequest
        ↓
C++ CTP Adapter（只做协议映射）
        ↓
CTP 柜台
```

### 业务层只表达意图

建议业务层只使用：

```text
OPEN          开仓
CLOSE         平仓（默认自动处理今昨）
CLOSE_TODAY   显式平今（仅高级/测试）
CLOSE_YESTERDAY 显式平昨（仅高级/测试）
```

更推荐新增：

```json
{
  "positionEffect": "CLOSE",
  "closePolicy": "AUTO"
}
```

`closePolicy`：

- `AUTO`：执行层根据今仓/昨仓自动决定
- `TODAY`：只平今
- `YESTERDAY`：只平昨
- 策略路径的 `AUTO` 可以在 SHFE/INE 跨今昨时拆 1–2 笔；手工路径不拆

### Execution Policy 负责交易所规则

配置表建议：

```text
exchange_rule
  exchange
  offset_mode: SINGLE_FINAL_OFFSET
  supported_offsets
  close_policy_default
```

映射：

| 交易所 | 业务 CLOSE + AUTO | 业务 CLOSE_TODAY | 业务 CLOSE_YESTERDAY |
|---|---|---|---|
| SHFE / INE | 策略路径按今昨仓拆 1–2 笔，每笔一个最终 offset；手工路径单笔，跨今昨拒绝 | 映射 CloseToday | 映射 CloseYesterday |
| DCE / CZCE / CFFEX / GFEX | 只接受单笔 Close；显式平今/平昨拒绝 | 拒绝 | 拒绝 |

### C++ Adapter 保持薄

C++ CTP Adapter 只负责：

```text
中性 offset → CTP CombOffsetFlag
```

不负责：

- 判断交易所规则
- 拆分订单（策略路径的拆单在 L2；L0 只收逐笔最终 offset）
- 读取策略配置
- 猜测今昨仓

原因：Adapter 没有完整账户/策略/仓位上下文，规则应放在控制面 Execution Policy。


## 2.1 参考 quantlink-trading 的实现

参考项目 `quantlink-trading` 的 ORS 在：

```text
ors/China/src/ORSServer.cpp
SetCombOffsetFlag(...)
```

做法不是拆子单，而是**按仓位自动选择一个 offset**：

```text
BUY:
  qty <= todayShort  → SHFE: CloseToday；其他: Close
  qty <= ONShort     → Close
  否则                → Open

SELL:
  qty <= todayLong   → SHFE: CloseToday；其他: Close
  qty <= ONLong      → Close
  否则                → Open
```

关键点：

- 前端/策略只表达 `OPEN / CLOSE / CLOSE_INTRADAY`，不直接传 CTP offset
- ORS 维护每个合约的 `todayLong / ONLong / todayShort / ONShort`
- SHFE/INE 的今仓映射 `CloseToday`，昨仓映射 `Close`
- 其他交易所统一映射 `Close`
- 参考实现**没有拆子单**，注释明确说过拆单版本曾导致持仓不对称和回报丢失。
当前策略路径的拆单是 L2 子单，不是 L0/ORS 拆单。
- `UseTodayPosition` 用于 SHFE/INE；`CloseTodayFirst` 用于 CFFEX 手续费优化，不改变 CTP offset

### 对当前方案的修正

L0/ORS 不应拆单；拆单只能发生在 L2。当前策略路径允许把跨今昨的 CLOSE 拆成
CLOSE_TODAY + CLOSE_YESTERDAY 子单，手工路径不拆。更贴近参考实现的单笔选择是：

```text
业务 CLOSE
  → Execution Policy 查今仓/昨仓
  → 选择一个最终 offset
  → 单笔订单下发
```

只有数量同时超过今仓和昨仓时，才：

- 手工路径默认拒绝，提示可平不足
- 策略路径由 L2 拆成 1–2 笔最终 offset 子单（无独立 SPLIT 配置）

参考实现“超过今昨合计就开仓”的 fallback 有风险，不建议照搬。

当前产品路径的明确差异：

```text
策略路径（StrategyOrderService）：
  SHFE/INE 的一个 CLOSE 跨今昨时，L2 拆成 CLOSE_TODAY + CLOSE_YESTERDAY 子单；
  每个子单独立发 OrderRequest，L0 仍只看到逐笔最终 offset。

手工路径（TradingController）：
  不拆单；跨今昨直接返回不可下单原因，要求操作员分两笔。
```

`SPLIT` 不是当前存在的配置项；不要把它写成可开启开关。

SimVenue 作为测试 venue，接受最终 `CLOSE_TODAY/CLOSE_YESTERDAY` 并模拟今昨仓；
这不代表交易所策略，生产路径的非 SHFE/INE explicit close 仍必须由 L2 拒绝。


## 2.2 是否保留显式平今/平昨

建议：**保留，但降级为手工交易的高级覆盖，不允许策略使用。**

分层：

| 入口 | 默认 | 是否允许显式 |
|---|---|---|
| 策略 / 算法 | `OPEN / CLOSE`（自动解析） | 不允许 |
| 手工交易默认 | `OPEN / CLOSE`（自动解析） | 不显示 |
| 手工交易高级 | 展开“高级开平” | 允许 `CLOSE_TODAY / CLOSE_YESTERDAY` |
| API | `OPEN / CLOSE` | 显式字段仅 ADMIN/TRADER 手工单 |

约束：

- 显式平今/平昨只对 SHFE/INE 生效
- 非 SHFE/INE 显式传入直接拒绝
- 显式覆盖必须写审计：`offset_override=true`、操作人、原因
- UI 必须显示“请求 offset → 解析后 offset”
- 策略代码只依赖 `OPEN / CLOSE`，新增交易所不需要改策略
- 显式入口主要用于运维纠错和测试，不作为日常交易路径

这样既保留了处理特殊场景的能力，又不会把交易所细节重新泄漏给业务层。

## 3. 今仓/昨仓数据

需要新增持仓明细，不能只靠汇总：

```sql
position_lots
  account_id
  instrument_id
  trade_date
  open_date
  side              -- LONG / SHORT
  qty
  avg_price
  exchange
```

或等价字段：

```sql
positions
  long_qty
  short_qty
  today_long
  today_short
  yesterday_long
  yesterday_short
```

推荐 `position_lots`，因为后续还要支持：

- 平今/平昨
- FIFO/LIFO
- 逐笔对账
- 交割月规则

## 4. 策略路径自动拆单（当前实现）

仅策略路径支持；手工路径不拆。SHFE 多头今仓 2、昨仓 3，业务发：

```text
SELL CLOSE 4，closePolicy=AUTO
```

Execution Policy 可以生成：

```text
Parent Order: CLOSE 4
  Child 1: CLOSE_TODAY 2
  Child 2: CLOSE_YESTERDAY 2
```

要求：

- 父子订单关联 `parent_order_id`
- 任一子单失败不能假装父单完成
- 前端显示父单汇总状态和子单明细
- 审计记录原始意图和最终 offset
- 手工路径不做此拆单；非 SHFE/INE 也不拆 explicit 平今/平昨

## 5. 撤单失败与重试

撤单失败常见原因：

- Aeron/控制面断开
- CTP 前置断开、未登录
- 订单已成交/已撤/已不存在
- 撤单太晚
- 交易所休市
- 权限/席位限制
- 请求频率限制
- 柜台超时未返回

重试策略建议：

| 原因 | 是否重试 |
|---|---|
| 网络/Aeron 断开 | 是，恢复连接后 |
| 柜台超时/无响应 | 是，幂等重试 |
| 频率限制 | 是，退避 |
| 已成交/已撤/不存在 | 否 |
| 权限/参数错误 | 否 |
| 交易所休市 | 否 |

推荐：

- 指数退避 1s / 2s / 5s
- 最大 3 次
- 每次写审计
- 状态：`CANCEL_REQUESTED → RETRYING → CANCEL_FAILED / CANCELED`
- 超过次数进入人工处理队列
- 撤单必须幂等，不能重复产生新撤单请求

## 6. 对系统的影响

采用该方案后：

- 策略代码不感知交易所
- 新交易所只加规则配置
- 手工交易默认“平仓自动”
- 风控统一按业务意图校验
- CTP Adapter 保持稳定
- 测试可按“业务意图 → 最终 offset”验证

## 7. 落地顺序

1. 增加 `exchange_rule` 配置
2. 增加 `position_lots` 或今昨仓字段
3. 增加 Execution Policy（AUTO/TODAY/YESTERDAY；策略路径内部拆单，无独立 SPLIT 配置）
4. 订单模型增加 `parent_order_id`、`resolved_offset`
5. CTP Adapter 只接收最终 offset
6. 前端默认 `CLOSE + AUTO`，高级模式才显示显式平今/平昨
