# 架构硬约束（P0）

本文件是强制约束，不是建议。

任何实现、重构、Code Review 如果违反本文件，必须按 P0 处理。

## 1. 控制面 / 数据面 / 交易面分离

```text
Control Plane = 管理面
Aeron         = 数据面 + 交易面
Runtime/Agent = 本地决策 + 本地风控
```

禁止：

```text
控制面在 tick 热路径上
控制面在订单同步路径上
控制面宕机导致 runner 停止交易
```

## 1.1 管理面 / 运行面硬边界

管理面（Control Plane / Web）**不产生任何派生数据计算**。

管理面只允许：

```text
配置
权限
审批
部署/停止/撤单等生命周期指令
读取运行系统或定时任务已经生成的数据
WebSocket 转发
历史查询
审计
```

禁止管理面计算：

```text
策略 PnL
策略持仓
账户权益 / 账户 PnL
组合权益 / 组合 Greeks / 组合 PnL
指标值
对账差异
未分配持仓
风险占用
```

所有派生数据必须来自：

```text
Runtime Agent / ORS
  → 策略订单、成交、持仓、PnL、Greeks、风险

Adapter
  → 账户快照、账户持仓、柜台健康

定时数据任务
  → 指标值、PnL 快照、对账、日终结算、费率/保证金、告警评估
```

数据流：

```text
运行系统 / 定时任务
  → SBE / Aeron / 数据表
  → 管理面只读消费
  → WebSocket 转发
  → Web 展示
```

判定规则：

> 一个值如果依赖行情、成交、持仓、账户余额或历史序列计算得到，
> 它就不属于管理面。管理面只能读取已经算好的结果。

禁止的实现方式：

```text
Controller 请求时调用 StrategyPnlService 现算
Controller 请求时聚合账户权益
管理面定时器重算 PnL/指标
管理面行情线程计算指标
浏览器轮询触发管理面计算
用 accounts.balance + 浮动 PnL 冒充账户权益
```

Code Review 强制项：

```text
新增 @Scheduled 计算任务：必须归入“定时数据任务”，只写数据表/事件，不提供管理 API
新增 Controller 计算逻辑：P0 违规，拒绝合并
新增页面轮询：P0 违规，必须改为事件/WS
```

## 2. 行情热路径

唯一允许的实盘行情主链路：

```text
CTP Adapter
  → Aeron market data
  → Runtime / Runner 直接订阅
  → Strategy
```

禁止：

```text
CTP Adapter → 控制面 → HTTP → Runner
Runner 轮询 /market/ticks
每个 tick 写 PostgreSQL / ClickHouse
每个 tick 做 HTTP / RPC
```

控制面可以异步复制行情用于：

```text
UI
指标
告警
审计
历史落库
```

但它不能位于策略决策之前。

## 3. 下单热路径

唯一允许的实盘下单主链路：

```text
Strategy
  → 本地预交易风控
  → Aeron order stream
  → ORS / CTP Adapter
```

控制面异步消费：

```text
订单
成交
持仓
审计
PnL
```

禁止：

```text
每笔订单同步 HTTP 调控制面
每笔订单同步写数据库
控制面不可用时禁止下单/撤单/对冲
```

本地风控至少包括：

```text
账户状态
可用资金
持仓
MAX_OPEN_ORDERS
MAX_LOSS / UPNL / STOP_LOSS
reduce_only
价格 tick
lot size
```

## 4. 控制面降级

验收标准：

```text
control-plane 停止
→ runner 继续收行情 / 决策 / 撤单 / 平仓
→ 风险快照新鲜期内继续开仓
→ 快照超过 riskMaxAgeMillis 后 OPEN fail-closed
→ CLOSE / CANCEL 仍允许
→ 恢复后补审计与状态
```

控制面恢复后允许短暂状态不一致，但必须有对账：

```text
orders
trades
positions / strategy_positions
daily state
```

## 5. 延迟 SLO

```text
tick 到达 → 策略决策        p99 < 5ms
决策 → Aeron order 发出    p99 < 1ms
控制面 UI 刷新             允许 500ms~2s
```

必须有指标：

```text
tick_to_decision_ns
decision_to_order_ns
runner_queue_depth
aeron_backpressure
control_plane_lag
```

禁止用“感觉不慢”代替测量。

## 6. 禁止在热路径做阻塞操作

策略循环内禁止：

```text
JDBC / MyBatis
HTTP / RPC
文件 IO
同步日志刷盘
大对象 JSON 序列化
锁竞争
```

允许：

```text
内存队列
RingBuffer
Aeron
本地缓存
异步 telemetry
```

## 7. 配置与状态

```text
控制面是配置源
runner 本地缓存配置
```

启动：

```text
从控制面拉取配置
本地校验
失败 fail-closed
```

运行中：

```text
控制面配置变更异步推送/轮询
热路径只读本地缓存
```

禁止：

```text
每个 tick 查配置
每个订单查数据库配置
```

## 8. 策略归属

```text
1 strategy = 1 agent
1 account = 1 agent = 1 ORS
```

策略持仓、PnL、收盘平仓、紧急平仓必须按：

```text
strategy_id + account_id + instrument_id
```

归属，不允许按账户总持仓反推。

## 9. 行情单一来源

实盘行情只认 Aeron：

```text
CTP Adapter / Sim Exchange / Replay Gateway
  → Aeron
  → runner
```

禁止同时维护：

```text
HTTP tick 源
Aeron tick 源
```

两套源会造成延迟和状态不一致。

## 10. 故障隔离

必须验证：

```text
控制面宕机
数据库宕机
Aeron 短暂 backpressure
CTP Adapter 重启
runner 重启
双 runner
```

任何单点故障不得导致：

```text
裸腿无人管
重复下单
收盘不平仓
持仓归属丢失
```

## 11. Code Review 强制项

任何 PR 出现以下情况直接拒绝：

```text
热路径新增 HTTP / JDBC / MyBatis
热路径同步写库
控制面进入行情/订单同步链路
新增轮询 /market/ticks 作为实盘行情源
新策略没有本地风控缓存
新策略持仓没有 strategy_id 归属
```

## 12. 例外流程

如果确实必须违反上述约束：

```text
1. 写 ADR
2. 标明延迟/故障影响
3. 给出回退方案
4. P0 架构评审
5. 不允许静默绕过
```

没有 ADR 的例外视为缺陷。

## 7. 当前实现（P0 已落地）

### 7.1 行情

```text
SimVenue: sim-venue SimVenueMarketDataGenerator → Aeron 1001（单一写入方）
CTP:      CTP Adapter → Aeron 1100/1110...
Runner:   AeronMarketData 直接订阅
Control:  MarketDataAeronConsumer 仅异步旁路
```

SimVenue/CTP 的 runner 均不再轮询 `/api/v1/market/ticks`。SimLocal 时代的
`qf-sim-long + SimMdPublisher` 行情桥已删除。

### 7.2 下单

```text
Strategy
  → AeronOrderGateway（本地风控）
  → Aeron OrderRequest
  → SimExchangeAeronGateway / CTP Adapter
  → OrderUpdate / Trade
```

`OrderRequest`、`OrderUpdate`、`Trade` 均携带：

```text
requestId
strategyKey
```

`strategyKey` 用于把成交归属到 `strategy_positions`，`requestId` 用于
HTTP/审计/订单/成交/告警全链路关联。

### 7.3 本地风控 fail-closed

runner 启动和运行期间通过 `/api/v1/strategy-runtime/risk` 获取快照。

规则：

```text
快照未加载 / 超过 riskMaxAgeMillis
  → 禁止 OPEN
  → 允许 CLOSE（降低风险）
```

快照包含：

```text
strategy_positions
MAX_OPEN_ORDERS
MAX_SIZE / MAX_TRADED_QTY
MAX_LOSS / UPNL / STOP_LOSS
reduce_only
available funds
tick size / lot size
```

控制面只做异步订单/成交/持仓/审计副本，不参与下单同步路径。

### 7.4 SimLocal 撮合

```text
SimExchangeAeronMain
  order=2120
  cancel=2121
  update=2122
  trade=2123
```

控制面、runner、SimLocal 网关共用同一组 Aeron 流。


## 8. 热路径指标实现

Runner 已内置 `RunnerMetrics`，每 30 秒输出：

```text
[metrics] {
  tickToDecisionP50Ns / P99Ns / MaxNs
  decisionToOrderP50Ns / P99Ns / MaxNs
  aeronBackpressure
  runnerQueueDepth
  controlPlaneLagMs
}
```

实测 SimLocal（4 vCPU）：

```text
tickToDecisionP99 ≈ 4.3~4.9ms
decisionToOrderP99 ≈ 3.0ms
aeronBackpressure = 0
controlPlaneLagMs ≈ 1~3ms
```

Soak 脚本：

```bash
bash tools/soak-simlocal.sh 3600 30
```
