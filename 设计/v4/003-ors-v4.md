# ORS v4 实施方案

- 状态：DRAFT（2026-11-26）
- 范围：CTP ORS v4 的代码基线、模块拆分、Aeron 接入、account query、测试和迁移
- 业务基线：公司 ORS + `tb_origin`
- 架构：`001-v4-architecture.md`
- Contract：`002-contract-v4.md`

---

## 1. 目标

```text
公司 ORS 的业务行为保持不变
  +
SHM Request/Response 替换为 Aeron
  +
account query 是唯一业务改动
  +
SDK 只做通信，不持有订单状态
```

ORS v4 仍然是：

```text
一个进程 = 一个 CTP 账户
一张账户级订单 map
一套账户级 RMS
一个 TraderApi / MdApi 会话
```

不按交易所拆分订单管理。

---

## 2. 不做什么

- 不沿用 v3 的 `TradingChannel`、`OrderRegistry`、`FillLedger`、平仓预扣
- 不把 v3 `CtpAdapter` 的 `NEW/ACK/PARTIAL` 状态机当作 ORS v4 核心
- 不在 SDK 里维护订单状态
- 不重写公司 ORS 的订单、撤单、RMS、终态逻辑
- 不做多 adapter 单进程路由
- 不在本次方案里改 SimVenue/FastTrade 的业务逻辑；它们按 contract v4 迁移

---

## 3. 源码策略

```text
业务主干：公司 ORS 原始代码
生产修复：quantlink-trading/ors/China 逐项 cherry-pick
Aeron 实现参考：当前 quantlink-ors 的 Aeron transport
```

不直接整包使用 `quantlink-trading/ors/China`，因为它带有非 account query 的改动（StrategyID、Dashboard、拆单历史等）。

建议在 `quantlink-ors` 内新增独立目录：

```text
quantlink-ors/
  v3/                    # 当前 v3 CTP 实现，冻结，v4 切换后移除
  v4/
    core/                # 公司 ORS 核心：ORSServer、OrderInfo、RMS
    transport/           # Aeron 出入口
    md/                  # 公司 MDHandler + Aeron MarketUpdate
    query/               # account query
    main.cpp
    CMakeLists.txt
```

v4 先与 v3 并行构建，验证通过后删除 v3 active 构建。

## 4. 核心改造点

### 4.1 把 SHM 从 `ORSServer` 中拿掉

公司 ORS 当前有三处 SHM 耦合：

```text
ORSServer 构造函数：
  createClientStore / createRequestClients / createResponseClient

ORSServer::Start：
  startMonitorAsyncORSRequest

ORSServer::PushUpdate：
  m_responseInterface->enqueue
```

改造为 transport 接口，不改变订单逻辑：

```cpp
class OrsTransport {
 public:
  virtual ~OrsTransport() = default;
  virtual void sendResponse(const ResponseMsg&) = 0;
  virtual void sendMarketData(const MarketUpdateNew&) = 0;
  virtual void sendSession(const SessionEvent&) = 0;
};
```

`ORSServer` 只保留：

```text
ProcessRequest(RequestMsg*)
PushUpdate(ResponseMsg*)
CTP callbacks
订单 map / RMS / position
```

`PushUpdate` 从 `m_responseInterface->enqueue` 改为 `transport_->sendResponse(*resp)`。

### 4.2 输入改为 Aeron subscription

新增 `AeronOrsTransport`：

```text
Aeron REQUEST stream
  -> decode OrsRequest
  -> ORSServer::ProcessRequest

Aeron ACCOUNT_QUERY stream
  -> decode AccountQuery
  -> ORSServer::QueryAccount

Aeron CONTROL stream
  -> ClientRegister / ClientRegisterResponse
  -> 分配 clientId

Aeron MARKET_DATA / RESPONSE / SESSION
  <- encode and publish
```

`ClientRegister` 是替换公司 SHM ClientStore 的控制路径，不改变订单/RMS 逻辑。OrderID 仍按
`clientId * 1_000_000 + orderCount` 生成。

请求处理线程与 CTP 回调线程的边界按公司 ORS 原有语义保留；不要为了 Aeron 把订单处理拆成多线程状态机。

### 4.3 MDHandler 改为输出 sink

公司 `MDHandler::ProcessMDUpdate` 当前直接写 `MarketDataShmWriter`。  
改为：

```text
ProcessMDUpdate
  -> 更新 m_timestamp/m_seqnum
  -> transport_->sendMarketData(*update)
```

MD 的 `m_symbol`、`m_exchTS`、`m_timestamp`、`m_seqnum`、20 档结构按公司 `MarketUpdateNew` 保留，不自造 v3 `MarketData` 语义。

### 4.4 account query

公司 CTP ORS 原始代码的 `ReqQryAccount()` 基本是禁用的。v4 只在这里做业务改动：

```text
AccountQuery
  -> ORSServer::QueryAccount()
  -> CTP ReqQryTradingAccount
  -> OnRspQryTradingAccount
  -> AccountSnapshot
```

要求：

- 只查当前账户
- 有节流，不背靠背查询
- 查询失败不改变订单状态、不影响 READY
- account snapshot 通过单独 Aeron stream 返回
- 不改 position query 的既有行为
- 不把 account query 做成订单状态查询

### 4.5 公司订单行为保留

必须保持：

- `m_ordLocalMap` / `m_ordExchMap`
- 未知撤单返回 `CANCEL_ORDER_REJECT`
- 撤单拒绝后原订单继续
- 终态清理
- `NEW_ORDER_CONFIRM` / `TRADE_CONFIRM` / `ORDER_ERROR` 时序
- RMS 和撤单计数
- 旧 front/session 过滤
- OrderID 作为账户级订单主键

不要把 v3 的 `OrderUpdate.status` / `CancelState` 引入核心。

## 5. ORS 与 SDK 的接口

SDK 负责：

```text
Aeron 连接/重连
RequestMsg/ResponseMsg 编解码
OrderID 分配
请求/响应关联
超时
回调分发
```

SDK 不负责：

```text
订单状态
订单 map
RMS
预扣
终态判断
```

ORS 只接受 SDK 的请求，返回公司语义的响应。

---

## 6. 进程与部署

```text
一个 CTP 账户
  -> 一个 ORS v4 进程
  -> 一个 TraderApi 会话
  -> 一个 MdApi 会话
```

多账户：

```text
account-1 -> ors-1
account-2 -> ors-2
```

不共享订单 map，不做进程内多账户路由。

每个进程需要独立：

```text
ORS_ID
CTP 账户配置
trader/md flow path
日志路径
Aeron request/response stream
```

Aeron 目录可以共享，stream 不能冲突。

## 7. 迁移步骤

### 阶段 1：基线可运行

- 复制公司 ORS 核心到 `v4/core`
- 保持 SHM 或临时 stub，先让订单/RMS/CTP 行为跑通
- 建立公司 ORS 行为样例和回归测试

### 阶段 2：Transport 解耦

- 引入 `OrsTransport` / sink 接口
- 移除 `ORSServer` 对 `ShmMgr` 的直接依赖
- 用内存 transport 做单元测试

### 阶段 3：Aeron 接入

- 实现 `AeronOrsTransport`
- REQUEST -> `ProcessRequest`
- RESPONSE -> `PushUpdate`
- MD -> `MarketUpdate`
- back-pressure/断线错误上抛
- 完成未知撤单、订单终态、撤单拒绝、成交时序测试

### 阶段 4：account query

- CTP `ReqQryTradingAccount` / `OnRspQryTradingAccount`
- AccountQuery/AccountSnapshot 编解码
- 节流和失败处理
- 验证不影响订单/RMS

### 阶段 5：SDK 与 contract v4

- SDK 接 v4 contract
- TradeBot 使用 SDK
- SimVenue/FastTrade 接同一 contract v4
- 版本矩阵锁定 contract 4.0.0

### 阶段 6：cutover

- v3 active 构建删除
- v4 ORS 成为唯一 CTP ORS
- 保留 v3 历史文档和旧 artifact，不作为 active 依赖

## 8. 测试与验收

### 核心行为

- 下单/撤单字段映射与公司 ORS 一致
- 未知撤单返回 `CANCEL_ORDER_REJECT`
- 撤单拒绝后订单继续有效
- 终态订单清理
- 成交先于终态
- 旧 front/session 回报丢弃
- RMS 拒单和订单状态不变
- account query 成功/失败
- 账户查询不影响 READY/订单状态

### Transport

- Aeron back-pressure 不静默丢请求
- 断线重连
- response/orderId 关联
- 重复/乱序响应处理
- MD 不重复、不旧 tick 覆盖

### 集成

- ORS v4 + SDK + TradeBot
- ORS v4 + SimVenue + FastTrade
- 多账户多进程
- 交易时段 live lifecycle

---

## 9. 风险

- 公司 ORS 代码老，依赖 hftbase/SHM/RMS；解耦会碰大量旧代码
- `ResponseMsg.ExchangeOrderId` 是 `double`，不要随手改类型
- `StrategyID` 不在公司 `RequestMsg` 中；TradeBot 的 `OrderIDStrategyMap` 仍按 OrderID 归属
- CTP account query 有频率限制，必须节流
- MD 结构字段多，contract v4 必须按实际消费字段裁剪，不能直接照搬 v3 `MarketData`
- 如果 SDK 重发请求，ORS 必须按 OrderID/订单 map 做幂等或明确拒绝
- SimVenue/FastTrade 同时迁 contract v4，联调窗口要一起排
