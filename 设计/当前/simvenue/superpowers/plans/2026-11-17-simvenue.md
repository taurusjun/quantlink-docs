# SimVenue Independence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an independent SimVenue process from the existing sim-exchange/sim-venue code, using only the published venue contract 0.1.8.

**Architecture:** `sim-exchange` is a pure Java matching library. `sim-venue` is the only runnable process and owns Aeron, contract codecs, synthetic market data, VenueStore and health. Market data and orders both come through the contract; execution updates and trades share one `EXECUTION` stream and one sequence.

**Tech Stack:** Java 25, Gradle 9.8.2, Aeron 1.54.0, Agrona 2.1.0, Jackson 2.18.2, JUnit 5, `venue-contract:0.1.8`.

**Spec:** `docs/superpowers/specs/2026-11-16-simvenue-design.md`

## Global Constraints

```text
Java: 25
Contract: com.quantlink.contract:venue-contract:0.1.8
Contract group: com.quantlink.contract
Packages:
  com.quantlink.simvenue.exchange
  com.quantlink.simvenue.venue
One runnable process: sim-venue
One execution stream: EXECUTION=2003; OrderUpdate + Trade share sequence
MD must flow through MARKET_DATA stream, not an in-process bypass
No V2 messages
No deploymentId / deploymentGeneration / orderEpoch / fencingToken / routeId
No SimExchangeAeronMain
No SimExchangeAeronGateway
No SimOrderCodec
No cross-repo P0 tests
No quantlink-fin dependency
```

## Review Focus

- MD arrives on `MARKET_DATA` and re-matches resting DAY orders.
- OrderUpdate and Trade both appear on one execution stream with one sequence.
- An opening order is rejected when simple nominal margin makes `available < 0`.
- Restart restores cash, positions and open orders from VenueStore.
- Wrong venue/account/environment is rejected before matching.

- [ ] **Step 4: Implement margin**

```text
mark = markPrice(instrument)
if mark <= 0 -> avgPrice
margin = sum(abs(netQty) * mark * multiplier * marginRate)
available = balance - margin
```

For a new opening order, check the projected margin before matching:

```text
projectedMargin = margin()
  + abs(request.qty()) * request.price() * multiplier * marginRate
projectedAvailable = balance() - projectedMargin
```

Reject if `projectedAvailable < 0`. For `MARKET` orders use the current
opposite-side mark/price for the projection. Closing orders skip the
opening-margin check but still enforce reduce-only.
