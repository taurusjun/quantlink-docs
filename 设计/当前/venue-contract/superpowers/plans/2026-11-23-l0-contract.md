# L0 单合同 0.2.0 实施计划

> **面向 agentic workers：** 必须使用子技能 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐步执行。步骤使用 `- [ ]` 复选框跟踪。

**目标：** 让 `quantlink-venue-contract` 0.2.0 成为从 L1 贯穿到 L0 的唯一合同：不带策略归因、只使用 `orderRef`、支持 MODIFY、20 档行情、快照必需。

**架构：** 保留现有 SBE + Aeron 边界。先改 canonical 消息和 codec，再改两个消费方 `quantlink-simvenue`、`quantlink-fasttrade/access-sdk`，让它们使用同一份 wire contract。不做运行时协商，不保留双字段兼容。

**技术栈：** Java 25、Gradle 9.8.2、SBE 1.35.6、Aeron 1.54.0、Agrona 2.1.0、JUnit 5。

**Spec：** `docs/superpowers/specs/2026-11-23-l0-contract-design.md`

## 全局约束

```text
Contract 版本：0.2.0
破坏性变更：L0 contract 不再有 strategyKey/clientOrderId
L0 订单身份：orderRef
L0 账户：accountId = venue 账户
行情：20 档
PositionSnapshot 和 AccountSnapshot 为必需消息
OrderUpdate 和 Trade 共用一条 execution stream 和一个 sequence
不做 contract handshake、发现或运行时版本协商
所有模块用 Java 25 构建
```

## 评审重点

- 旧 0.1.8 客户端仍发送 `clientOrderId`/`strategyKey`：必须编译失败或被拒绝，不能静默接受。
- MODIFY 指向不存在或已终态的订单：必须返回 rejected `OrderUpdate`，不能改错订单。
- venue 不足 20 档：缺失档位补零，不能重复或伪造。
- `accountId` 与 ORS/venue 绑定不一致：下单/撤单必须在进入撮合前被拒绝。
- 旧 session/epoch 的迟到 execution 或行情：必须被 `VenueSession`/sequence 逻辑丢弃。
