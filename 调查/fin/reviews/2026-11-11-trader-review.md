# 交易端评审：quantlink-fin（A）vs quantlink-trading（B）

- 日期：2026-11-11
- 评审视角：期货/期权实盘交易员（日盘/夜盘、多柜台、Pair 与期权做市），不是架构评审
- 评审对象：A = quantlink-fin V2（SHADOW）；B = quantlink-trading `/product_management/check`「实时监测」
- 只读声明：全程只打开页面、切 Tab、开弹窗后关闭，未下单/撤单/停止/激活/改配置/删数据；未重启 190 上任何服务；未改 `web/src`、`backend/**`
- 证据目录：`docs/evidence/trader-review/`（22 张截图 + 接口快照）

---

## 0. 结论摘要

**一句话：以交易员标准，B 的“KPI 带 + 策略主表 + 右侧明细 Tab + 常驻应急入口”更接近一屏盯盘，A 的数据真实性与操作护栏更适合当交易控制台；但两套都不满足“一屏决策”，目标形态应是 B 的骨架 + A 的内核。**

三条支撑结论：

1. **A 的数据是对的，但交易员在驾驶舱看不到“能不能交易”。** 采集时刻系统里有 500 条“本地风控快照过期 → 报单被拒”的告警，策略仍在“运行中”，订单页今日委托为 0，驾驶舱没有任何阻塞提示。这印证了 AGENTS.md 的“管理面不计算”原则，但也暴露了一个空档：**运行体算出来的“不能交易”结论，没有变成交易员能看见的一等公民。**
2. **B 的信息架构是对的，但它把交易员最需要的东西省掉了。** 挂单表没有时间、没有状态、没有成交进度、没有逐单撤单（只有 `cxl All`）；全页没有行情列、没有延迟、没有断线提示（`connectionStatus` 计算了但从未渲染）；`停止/杀死` 单击即执行。
3. **A 的“状态”是给工程师看的，不是给交易员看的。** 同一策略可以同时是「部署 INACTIVE」「策略 ACTIVE」「actualState RUNNING」「desired RUNNING」；驾驶舱按 `deploymentState` 数出“3 个运行中”，而其中包含没有 Agent 数据的策略。交易员的第一个问题永远是“它现在发不发单”，当前 UI 无法一句话回答。

适用人群判断：

| 交易员类型 | 更合适 | 原因 |
| --- | --- | --- |
| 量化/做市台，按策略编排，SHADOW→LIVE 管控 | A | 有版本/部署/回滚/审计/对账/逐策略 PnL，护栏完整 |
| 盯盘型主观/半主观，按产品与进程盯单 | B | 进程级 KPI、全量推送、主表+明细一屏、应急票 |
| 多柜台运营（3 个以上 ORS） | 都不合适 | A 把柜台健康聚合掉，B 完全没有柜台概念 |

## 2. 场景对比表

评分口径：★=不可用，★★=勉强，★★★=可用但需绕路，★★★★=顺手，★★★★★=一屏完成。

| 场景 | A（quantlink-fin） | B（`/product_management/check`） | 胜者 | 差距（要合一还缺什么） |
| --- | --- | --- | --- | --- |
| **盘前 5 分钟** | 有交易日历、会话时钟（“下一开盘 20:55 夜盘集合竞价”）、非交易时段横幅、账户快照、逐策略卡；但“运行中 3”与卡片 ACTIVE/INACTIVE 对不上，看不到“今天能不能开、哪些柜台在线、参数是否就绪” | KPI 直接给「策略总数/运行中/待启动/无进程」，主表首列 `Status` 用红/绿/黄底色；双击 ModelFile 可改参数、双击告警列标记已读；但没有交易日历、没有会话状态、没有柜台/行情，全部是进程视角 | **B（就绪判定）** A★★☆ / B★★★ | A 缺“单一运行状态 + 就绪清单”；B 缺“今天是否交易日/柜台是否在线”。两边都没有“盘前 checklist”（参数版本、保证金、限仓、合约到期、未平仓） |

| **收盘** | 会话时钟临近收盘变黄、盘后查询（持仓/账户/时段）、持仓快照页、策略对账 Tab、账务与结算；但没有“收盘检查清单”、没有当日交易报告、PnL 曲线与顶部数字冲突 | 无任何收盘概念（没有交易日历、没有收盘倒计时、没有日终快照） | **A（完胜）** A★★★☆ / B★ | A 缺“收盘前 15 分钟 checklist + 一键日报”；B 缺整个收盘域 |

**总评**

- **A = 数据面 4 星，交互面 2 星。** 它知道真相（Agent PnL、scoped quote、对账、审计），但把真相拆散在 5 个页面、3 套状态词里。
- **B = 交互面 3.5 星，数据面 1.5 星。** 它知道交易员怎么扫屏，但不知道交易员需要看到价格、时间、延迟和撤单。
- **“一屏决策”当前两边都不满足。** A 的驾驶舱是“策略卡片墙”，不是“交易台”；B 的监测页是“进程看板”，不是“交易台”。

## 3. 问题清单

> 证据格式：`页面/文件:行号` + 截图文件名。截图均在 `docs/evidence/trader-review/`。

### 3.1 P0 · 交易阻塞（6 条）

#### TR-01 策略状态有三套词表，交易员无法判断“它到底在不在发单” · P0

- **证据**
  - `/strategy-center` 同一行：`SIMVENUE-OPT-01` 显示「部署 INACTIVE」+「策略 ACTIVE」（`02-strategy-center.png`）
  - `/execution` 同一策略：desired `RUNNING` / actual `RUNNING`，但「状态」列写 `INACTIVE`（`09-execution.png`）
  - 接口：`deploymentState=INACTIVE`、`actualState=RUNNING`、`strategyStatus=ACTIVE` 三者并存（`api-snapshot.md` §2）
  - 驾驶舱「3 个运行中」按 `deploymentState` 统计（`web/src/pages/Dashboard.tsx:167-168`）
  - 详情页同时展示 `策略 / 部署 / 版本 / 代` 四个 chip（`StrategyCenter.tsx:1566-1575`）
- **交易员影响**：盘前无法确认策略是否已就绪；盘中看到「INACTIVE」会以为没在跑，看到「ACTIVE」又可能以为在发单。真正出事时（如 TR-03 的拒单）界面仍然显示“运行中”。
- **建议**：由运行体上报、控制面派生**唯一** `runState ∈ {UNDEPLOYED, INACTIVE, STARTING, ACTIVE, DEGRADED, STOPPING, STOPPED, ERROR, HALTED}`；驾驶舱每行只显示一个状态灯，`desired/actual/lastOrderAt/lastQuoteAt` 放 tooltip；其余词表只留在运维页。

#### TR-02 告警风暴：3 分钟 500 条同指纹，7.7 小时未过期，无聚合无分级 · P0

- **证据**
  - `/alerts` 整页同一条原因（`05-alerts.png`）
  - 接口：500 条（上限）全部为 `PAIR order rejected: local risk snapshot is stale`，`11:11:53–11:15:02` 产生，采集时仍 `NEW`（`api-snapshot.md` §3）
  - 驾驶舱只显示前 5 条 + 一个「100」角标（`Dashboard.tsx:344-362`；`useStrategyAlerts` 固定 `limit=100`）
  - 告警无 severity 字段（`Alerts.tsx:26-40`）
- **交易员影响**：真正的 P0（风控不可用、报单被拒）被 500 条同义重复淹没；交易员会形成“告警页不用看”的条件反射——这是最危险的习惯。
- **建议**：服务端生成 `fingerprint = hash(strategy_id, instrument_id, reason_code)`，60s 窗口内只保留一条并累加 `count`；增加 `severity(P0/P1/P2)`；未 ack 的 P0 5 分钟后升级并置顶；超过 24h 自动过期；前端默认只看 P0/P1。

#### TR-03 报单被全部拒绝，驾驶舱与订单页都看不见 · P0

- **证据**
  - 告警原文：`local risk snapshot is stale; loaded=true ageMs=221947 maxAgeMs=15000`（风控快照 221.9s 未更新，阈值 15s）
  - `/orders` 今日委托 **0**、今日成交 **0**（`03-orders.png`；接口 `orders/page?...&startMs=今日` → total 0）
  - 驾驶舱 KPI 只有：策略数 / Agent PnL / 未归属 / 柜台权益（`Dashboard.tsx:197-207`），没有拒单、没有风控状态、没有“最近一次成功报单时间”
- **交易员影响**：策略实际已停摆，界面显示 PnL 0、挂单 0、“运行中”。如果这是实盘，交易员会以为在做市，实际一笔没发出去；如果是套保，会以为已对冲。
- **建议**：新增「今日委托/成交/拒单」「风控状态」「最近成功报单」三项；任一策略 5 分钟内拒单 >0，顶部出现红色阻塞条并给出首条原因与一键处置（切只减仓 / 停止该策略）；拒单必须写入订单表（`status=REJECTED`）而不是只写告警。

#### TR-04 手工单价格直接取浮点最新价，未按最小变动价位取整 · P0

- **证据**
  - `12-manual-order-dialog.png`：价格框自动填 `866.5739174493044`
  - 代码：`setNewPrice(String(quote.lastPrice))`（`web/src/pages/ManualBook.tsx:193`）
  - 同屏买一/卖一 `866.56 / 866.60`，但无时间、无龄（`ManualBook.tsx:587-591`）
- **交易员影响**：au 的最小变动价位是 0.02，这个价格必然废单；交易员必须手动改成 866.56/866.58，夜盘急单时极易改错一位。更糟的是，价格来自一次 REST 快照，行情停了也看不出来。
- **建议**：价格默认取**对手价**（买=卖一、卖=买一），输入按 `tickSize` 步进（↑↓ 1 tick），非整数倍即时红框禁用提交；价格旁显示 `tick 龄 + 来源柜台`；偏离最新价 >2% 触发二次确认。

#### TR-05 策略订单没有撤单入口，只能“全撤”或停策略 · P0

- **证据**
  - `/orders` 表格 11 列，无“操作”列（`web/src/pages/OrdersV2.tsx:251-264`；`03-orders.png`）
  - `/orders` 策略订单 Tab 528 条，同样无撤单（`20-strategy-orders-tab.png`）
  - 全站唯一撤单在手工簿（`ManualBook.tsx:502-507`）与顶栏「全撤」（`AppShell.tsx:249-252`，`scope: 'ALL'`）
  - 后端其实已有行级撤单：`POST /api/v1/strategy/orders/{id}/cancel`（`StrategyOrderController.java:48`），**前端零调用**
- **交易员影响**：Pair 策略一条腿成交、另一条腿挂单挂在远离盘口的位置，交易员无法只撤那一腿；要么等策略自己撤，要么“全撤”（把别的策略的单也撤了），要么停策略（触发平仓）。这是实盘里最常见的“小事故变大事故”的路径。
- **建议**：订单行加「撤单」（二次确认显示合约/方向/价格/数量）；工具栏加「撤当前筛选(N)」；支持 `strategy:<id>` / `account:<id>` / `instrument:<id>` 作用域（后端已支持 `EmergencyController.java:194-201`）。撤单后按钮立即变 `CANCEL_REQUESTED`，并显示逐单回执。

#### TR-06 「更新版本」要求手写 JSON，且“保存并部署”会隐式触发撤单+平仓 · P0

- **证据**
  - `11-strategy-version-dialog.png`：版本 `v0.1.1`、配置 JSON `{}`，没有当前配置、没有 diff、没有字段说明
  - 默认值写死：`useState('v0.1.1')` / `useState('{}')`（`StrategyCenter.tsx:1367-1368`），且从未被预填（全文件只有这两处赋值）
  - 保存逻辑：若 `!versionCarry && hasPosition` 先调用 `POST /api/v1/emergency/stop`（`StrategyCenter.tsx:1760-1766`），按钮文案仍是「保存并部署」
  - 后端对 config 做 merge patch（`StrategyCenterController.java:379-395`），所以 `{}` 不会清空配置——但交易员无从知道这一点
- **交易员影响**：想改一个 `maxPosition`，必须打开另一个窗口查当前 JSON、手写 patch、自己保证不写错 key；更危险的是，只要账户有持仓且没勾“带仓升级”，点「保存并部署」会**先撤单再平仓**——交易员以为在发版本，实际把仓平了。
- **建议**：版本发布改成“结构化表单（预填当前值）+ 只读 JSON + diff 预览”；版本号自动递增；把「仅保存版本」与「保存并部署」拆成两个按钮；凡是会触发平仓的路径，必须单独弹窗写明“将撤 N 单 / 平 M 手”，并要求输入策略 ID 确认。

### 3.2 P1 · 日常摩擦（14 条）

#### TR-07 驾驶舱的策略列表、未归属、账户只在打开时加载一次 · P1

- **证据**：`load()` 只在 `useEffect(..., [])` 调用一次（`Dashboard.tsx:121-139`）；没有 `useMarketEvent`、没有 `setInterval`；只有 PnL/指标/账户快照通过 WS 更新。
- **影响**：开盘后新建/停止/删除的策略不会出现；未归属数不会变；“账户与风险”表的持仓行数是静态的。交易员必须记得手动点「刷新」。
- **建议**：订阅 `strategy-view` / `alert` / `account_snapshot` 事件后 2s 内重载 overview；或 10s 轮询（与详情页一致）。

#### TR-08 账户快照不全时直接展示部分合计，没有 PARTIAL 遮罩 · P1

- **证据**：`15-dashboard-1280.png` 显示「账户快照 1/3 · WAITING」，同屏「柜台权益 10,016,137.68 · 可用 10,016,137.68 · 保证金 0」；`01-dashboard.png` 同一位置为 33,626,353.64。代码用 `portfolio?.equity ?? sum(accountSnapshots)` 兜底（`Dashboard.tsx:161-166`）。
- **影响**：交易员看到的是一个“看起来完整”的权益数字，实际只含 1/3 账户，且保证金为 0 会让人误判风险。
- **建议**：`snapshotCount < accountCount` 时数字加 `~` 前缀、灰底、角标「1/3」，并在 tooltip 列出缺失账户；保证金为 0 时显示「未上报」而不是 0。

#### TR-09 同一屏两个 PnL 数字冲突，且无口径说明 · P1

- **证据**：`19-strategy-pnl-tab.png` 顶部「总 PnL 0.00 / 已实现 0.00 / 浮动盈亏 0.00」，下方曲线「最低 -335.00 最高 -335.00 最新 -335.00」，历史表全为 `2026-11-09` 的 `-335.00`（`STRATEGY_LEDGER`）；顶部卡片同时写 `Agent 实时 0.00`。
- **影响**：交易员会问“到底亏没亏 335”；在收盘对账时无法判断以哪个为准。
- **建议**：明确两个口径（`AGENT_LIVE` vs `STRATEGY_LEDGER`）并在标题上写清；历史数据按交易日分段并标注“非当日”；两者差异超过阈值时显示一条对账提示。

#### TR-10 指标阈值 0/0 导致永久 CRIT，且数值不按单位格式化 · P1

- **证据**：`06-indicators.png` 中 `PAIR_HEDGE_LATENCY 269,081.3 ms CRT`、`PAIR_SPREAD 11,278.3 CRT`，阈值显示「0 / 0」；详情页同指标显示 `269081.321ms`、`11289.154374644851`（`10-strategy-detail.png`）。接口 `warning_threshold=0.0 critical_threshold=0.0`、`message=">= critical 0.0"`。
- **影响**：CRIT 变成“默认状态”，颜色失去意义；交易员会忽略所有指标告警。原始浮点让读数变慢。
- **建议**：阈值为 0/0 时状态显示 `UNCONFIGURED`（灰色），不参与告警；数值按 `unit` + 3 位有效数字格式化；阈值必须在指标配置页强制填写（带默认建议值）。

#### TR-11 持仓/成交没有新鲜度语义，两天前的持仓与 18:01 的持仓同样式 · P1

- **证据**：`04-manual-book.png` 手工簿持仓更新于 `2026-11-09 21:46:29`；`21-orders-positions.png` 中 11-09、11-10、11-11 的行同样式；`/orders` 的「总持仓」还包含 0/0 空行。
- **影响**：交易员会把“昨天的残留仓”当成“今天的仓”，尤其是在换月/交割周；0/0 行浪费扫描注意力。
- **建议**：`updated_at` 超过 1 个交易时段即降级（灰字 + 「过期」角标 + 悬浮显示来源）；提供「仅显示非零」开关；0/0 行默认折叠。

#### TR-12 多柜台健康被聚合，2/3 ORS HALTED 仍显示「ORS 运行 / 通道正常」 · P1

- **证据**：`08-monitor.png` 三行 ORS：`shengli HALTED`、`simnow HALTED`、`simvenue RUNNING`，但顶部「Agent / ORS」显示绿色「ORS 运行」；顶栏「通道正常」（`AppShell.tsx:339-348`）；`MonitoringV2.tsx:67-69` 使用布尔 `orsRunning`。
- **影响**：交易员无法知道“哪个柜台还能发单”。18:56 的 HALTED 本身是预期，但同一套布尔聚合在日盘柜台故障时也会给出绿色结论——以为三个柜台都在，实际只有一个。
- **建议**：顶栏改为「柜台 1/3 在线」，点击展开逐柜台（ORS 状态 / agent 心跳 / 行情龄 / 最后 tick / 队列）；任一柜台 HALTED 时顶栏不得显示“通道正常”。

#### TR-13 详情页 10 个动作平铺，危险动作与安全动作相邻，激活/停用无确认 · P1

- **证据**：`10-strategy-detail.png` 两行按钮：刷新 / 订单成交 / 编辑策略 / 激活策略 / 停用策略 / 停止策略 / 更新版本 / 复制策略 / 停止并平仓 / 删除策略（`StrategyCenter.tsx:1487-1564`）；「激活」「停用」直接 `apiPost`，只有 LIVE 策略走一个通用 `liveAck` 确认（`1406-1417`）。
- **影响**：SHADOW 下「停止并平仓」一次点击 + 一次确认就执行，LIVE 也只是两个通用确认；确认框里始终没有“撤多少单 / 平多少手 / 涉及哪个账户”。而「复制策略」就在它左边。激活/停用没有确认，盘中误点会直接改变发单状态。
- **建议**：分三组（常规 / 生命周期 / 危险），危险组折叠进「更多」；所有改变发单状态的动作都要确认，并在确认框里显示影响（将撤 N 单 / 持仓 M 手）。

#### TR-14 订单页「总持仓」计数懒加载为 0，订单/成交无实时 · P1

- **证据**：`03-orders.png` 标签为「总持仓 (0)」；点开后变「总持仓 (6)」（`21-orders-positions.png`）；持仓只在 `tab===2` 时才请求（`OrdersV2.tsx:98-110`），标签用 `positions.length`（`239`）；订单/成交无 WS、无轮询（`112-145`）。
- **影响**：交易员以为没有持仓；盘中必须手动刷新才能看到新成交，容易漏看大单成交。
- **建议**：进入页面即拉一次持仓计数；订单/成交订阅 WS（`order`/`trade` 事件）或 1s 轮询；断线时显示「数据可能过期 x s」。

#### TR-15 对已部署策略点「编辑策略」必然失败，且弹出英文后端原文 · P1

- **证据**：后端在任一部署处于 `ACTIVE/SHADOW/RUNNING/DEPLOYING` 时直接 409：`"strategy is deployed; create a new version instead of editing the live config"`（`backend/.../TradingController.java:183-191`）；前端向导仍允许进入编辑模式，提示只写“编辑沿用新建策略向导”（`StrategyWizard.tsx:355-360`）。
- **影响**：交易员改参数时先撞一次英文报错，再被要求“新建版本”，但版本入口又要手写 JSON（TR-06），于是干脆不改。
- **建议**：编辑入口前置判断部署状态：已部署则直接跳到「新建版本」表单并预填当前参数；错误信息中文化并给出下一步按钮。

#### TR-16 未归属只能进二级 Tab，驾驶舱 KPI 不可点击 · P1

- **证据**：驾驶舱「未归属 1 / 2 手」（`Dashboard.tsx:202-204`）使用无 `onClick` 的 `Metric` 组件（`383-398`）；认领入口在 `/strategy-center` 的「未分配」Tab（`22-strategy-unassigned.png`）。
- **影响**：交易员看到“有 2 手不归属”，但不知道去哪处理；未归属成交会污染策略 PnL 与日终对账。
- **建议**：KPI 可点击直达带筛选的认领列表；支持批量认领；认领后 2s 内 KPI 更新并写审计。

#### TR-17 时区不一致：策略中心显示 UTC，驾驶舱显示 CST · P1

- **证据**：`02-strategy-center.png` 右上「快照 10:57:24」，同屏驾驶舱为 18:57；代码直接切 ISO 字符串：`overview?.generatedAt?.slice(11, 19)`（`StrategyCenter.tsx:829`）。
- **影响**：交易员用“快照时间”判断数据新鲜度时会被 8 小时误导；跨页面核对时间会对不上。
- **建议**：统一 `toLocaleTimeString('zh-CN', { timeZone })` 并显示时区标识；禁止对 ISO 字符串做 `slice`。

#### TR-18 告警页文案与默认过滤矛盾，无严重度、无静默规则 · P1

- **证据**：副标题写「仅显示当天策略提醒」（`Alerts.tsx:148-150`），但默认 `todayOnly=false`（`50`）显示全部日期；静默只有单条 30 分钟（`121-128`）；无 severity、无按策略/合约静默。
- **影响**：交易员打开页面看到的是 7 小时前（甚至跨日）的旧告警；想静音一类噪音只能逐条点。
- **建议**：文案与默认值一致（默认当日或最近 4 小时）；增加 P0/P1/P2；静默支持 `(策略, 合约, 指纹) × 30m/4h/当日`，规则可见可撤销。

#### TR-19 行情只有全局一个“新鲜”状态，没有逐合约/逐柜台的延迟、涨跌停与停牌 · P1

- **证据**
  - 顶栏只有一个 `marketFresh / marketAgeMs` 布尔与单值（`AppShell.tsx:339-348`、`130-137`），`/api/v1/system/status` 也只返回一组；采集时绿灯，但无法知道是哪个柜台的哪一腿在更新
  - 期权链只在“有报价”的行显示「龄」（`OptionChainV2.tsx:50, 151-152`，`07-options.png`）
  - 手工单弹窗显示买一/卖一，但没有时间/龄（`ManualBook.tsx:587-591`）
  - `/orders` 与驾驶舱主表完全不显示价格（`OrdersV2.tsx:244-249`）
- **说明**：A 在**柜台隔离**上是对的——tick 键为 `counterparty:exchange:instrument`，期权链明确“无报价显示 N/A，不做全局 fallback”（`useMarketData.tsx:18-20`、`OptionChainV2.tsx:95`）。问题不在隔离，而在“新鲜度只汇总成一个数”。
- **交易员影响**：集合竞价、停牌、涨跌停板上按最后价报单；单柜台行情停了，顶栏仍是绿的；Pair 两腿中一腿延迟，价差判断失真。
- **建议**：行情健康按 `(counterparty, exchange, instrument)` 上报 tick 龄；顶栏显示「最差合约龄」并可展开；每个价格旁带龄徽标；下单前校验合约状态（集合竞价/停牌/涨跌停/不可交易），不满足时禁用提交。

#### TR-20 风险页没有限仓额度，敞口在浏览器里现算 · P1

- **证据**
  - 风险 Tab 只有账户权益、保证金、占用率、策略净数量、名义敞口、最大单合约敞口（`17-strategy-risk-tab.png`；`StrategyCenter.tsx:2040-2069`）
  - 敞口是前端用 `|net| × avg_price × multiplier` 现算，`multiplier` 缺省为 1（`StrategyCenter.tsx:2028-2039`）；这与 AGENTS.md「管理面不计算」原则冲突，口径也依赖持仓行是否带 multiplier（本次 ag=15、au=1000 正常）
  - 全站没有任何「限额 / 已用 / 剩余 / 使用率」字段，也没有单笔、单品种、单策略上限（`/risk` 路由不存在，风险只在策略详情 Tab）
- **交易员影响**：交易员无法回答“我离限仓还有多远”“这笔加仓会不会超限”；出事后只能去柜台查。风控做成“事后展示”，不是“事前提示”。
- **建议**：由运行体上报 `limit / used / remaining / utilization`（按账户+品种+策略），驾驶舱与下单弹窗都显示剩余额度；敞口/名义价值由运行体计算，前端只展示；接近限额 80% 变琥珀、100% 红色并阻止开仓。

### 4.3 颜色与告警规则

**状态灯（唯一真源：runState + 数据新鲜度）**

| 颜色 | 条件 | 含义 |
| --- | --- | --- |
| 绿 | ACTIVE 且 tick 龄 <2s 且 风控 OK | 正常发单 |
| 琥珀 | STARTING / DEGRADED / tick 龄 2–10s / 快照 PARTIAL | 降级，需关注 |
| 红 | ERROR / HALTED / 5 分钟内拒单 / 风控不可用 / tick 龄 >10s | 不能交易 |
| 灰 | UNDEPLOYED / INACTIVE / STOPPED | 未参与交易 |

**数值颜色**

- PnL：**红盈绿亏**为默认（国内习惯），提供偏好开关切换；负号前置；千分位；2 位小数；`tabular-nums`。
- 价格：涨跌色与 PnL 色分离；所有价格旁带「龄」徽标；龄 >3s 数字变灰，>10s 加删除线 + 红点。
- 禁用按钮：灰 + tooltip 说明原因（“策略未部署”“无未完成订单”），**不要隐藏**。

**告警规则**

| 级别 | 触发 | 呈现 | 升级 |
| --- | --- | --- | --- |
| P0 | 报单被拒、风控不可用、柜台断线、对账不平、行情 >10s | 顶部红条 + 声音 + 必须 ack | 5 分钟未 ack 重复提示并置顶 |
| P1 | 行情 2–10s、快照 PARTIAL、指标 WARN、未归属新增 | 右栏琥珀 + 角标 | 30 分钟未处理合并计数 |
| P2 | 指标 STALE、配置提示 | 仅入队 | 不升级 |

## 8. 未决问题（需要产品或用户决策，不阻塞本评审）

1. **策略单被交易员手工撤掉后，策略是否自动补单？** 这决定了 REQ-04 的语义：撤单是“一次性干预”还是“冻结该价位”。建议默认“一次性干预”，并在策略侧记录 `manual_cancel` 事件。
2. **未归属的自动认领规则**：是否允许按 `client_order_id` 前缀/策略下单时间窗自动归属？自动归属会减少人工，但也会掩盖归属错误。建议先只做“建议归属 + 人工确认”。
3. **颜色习惯**：默认红涨绿跌还是绿涨红跌，需要实盘团队投票；建议做成用户级偏好而不是全局。
4. **版本发布的“带仓升级”默认值**：当前默认不带仓（会先平仓）。对做市策略，平仓再升级的成本可能很高；是否需要按策略类型设置默认值，需要产品确认。
5. **B 的像素级对比缺口**：B 无可用运行实例（8080 属其他产品，生产指向内网）。若需要截图级对比，需要提供可访问的 B 环境与只读账号。
6. **告警存储与合规**：500 条同指纹告警是否要全量入库（审计需要）但只在 UI 聚合？建议入库全量、UI 聚合，二者分离。
