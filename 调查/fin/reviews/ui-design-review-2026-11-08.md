# quantlink-fin UI 设计评审

- 评审日期：2026-11-08
- 评审对象：`quantlink-fin` Web 控制台（`web/src`）与 Electron 桌面壳（`desktop/electron`）
- 评审方式：源码走查 + 实时页面走查 + 1440/1366/1920 截图 + 交互打开只读弹窗
- 评审结论：**可演示，不可上桌。**
- 一句话：**它已经有一个像交易终端的外壳，但内部仍是一个 MUI 管理后台。最大的问题不是“好不好看”，而是“数据是否可信、动作是否安全、盘中是否够快”。**

---

## 1. 执行摘要与总体评分

### 1.1 总体判断

这个版本比典型的 CRUD 后台更完整：有全局应急入口、交易日历、角色/离线只读、订单分页、策略向导、PAIR 专用视图、执行拓扑和审计。登录页也有明确的品牌表达。

但作为交易终端，它还缺三样最核心的东西：

1. **可信的数据状态**：API 失败会静默回退到 mock/缓存；`交易通道已连接` 实际只代表 `/health` 可访问；监控页的 `UP` 可能只代表“配置启用”；环境（SIM/SHADOW/LIVE）没有全局、不可忽略的标识。
2. **安全的交易动作**：手工单预填 918.42，而当时的实时最新价是 873.38；`预检并提交` 在小额单上可以一步直接发出；订单页没有撤单；策略激活、部署、解绑、停用柜台等动作没有确认或审批。
3. **盘中可用的工作区**：1440 宽度下看不到市场行情条；驾驶舱没有图、没有 PnL 曲线、没有持仓合计、没有下钻；期权链在 1440 下只露出 Put 的一半列；没有合约搜索、快捷键或命令面板。

### 1.2 评分

| 维度 | 分数 | 判断 |
|---|---:|---|
| 信息架构 | 5.5 / 10 | 有分组，但“策略详情”被当成一级导航，单页成组，“消息中心/系统告警”割裂，“通用配置”命名过泛 |
| 视觉系统 | 6.5 / 10 | 深色底、琥珀强调色、卡片边框是统一的；但 9–10px 标签、状态色语义冲突、满屏 chip，整体仍有明显 MUI 模板感 |
| 交易效率 | 4.0 / 10 | 缺行情上下文、图、持仓总览、撤单、快捷键；手工单和驾驶舱都需要多次跨页确认 |
| 一致性 | 4.5 / 10 | 中英混排、日期/小数/单位不统一、BUY 绿/SELL 红与“红涨绿跌”并存、主色和警告色几乎同色 |
| 可访问性 | 4.0 / 10 | 键盘焦点不可见；填充 chip 白字对比度 3.0–3.49:1；9–10px 文本低于舒适阅读尺寸；图标按钮缺可访问名称 |
| **综合** | **4.9 / 10** | **视觉第一眼 7 分，真正交易时 4 分。** |

> 评分不是“工程完成度”评分。若只按 MVP 演示标准，可以给 6.5；按“专业交易终端”标准，4.9 更接近真实体验。

### 1.3 最严重的三个问题

1. **假数据/假在线会让人做错决策**：Dashboard、Orders、Audit、Indicators 在接口失败时静默显示 mock 或缓存数据，只用一个小号 `MOCK` chip 提示；CommonConfig 已经报 `API 502`，页面仍允许继续编辑。详情见 P0-01/P0-02。
2. **手工下单的默认值是过期价格，且“预检并提交”可能一步成交**：截图时实时价 873.38，表单预填 918.42；没有订单类型/TIF/本地只减仓，风险预览在提交前是空白。详情见 P0-03。
3. **危险动作没有闭环**：策略向导写着“ACTIVE 需要二次确认”，但实际直接创建并部署；执行拓扑的激活/停止/解绑、柜台停用、合约停用都没有确认；订单页没有撤单；打开策略详情会自动把未读提醒全部 ack。详情见 P0-04/P0-05/P0-08。

## 2. 当前优点

这些不是客套，是下一轮改版应该保留的资产：

1. **登录页是全产品最强的界面**。品牌图形、深色网格背景、`SHADOW ENVIRONMENT` 标签、左右分栏和特性卡片形成了明确的“控制面”气质，和内部页面的模板感拉开差距。参考：`docs/evidence/T-023/macos-login.png`。
2. **深色主题的基础色调成立**。`#0f1218` 画布 + `#161b24` 卡片 + 琥珀强调色，在 1440 下不刺眼，长时间看盘比纯黑更舒适；卡片使用 1px 边框而不是重阴影，方向正确。
3. **全局壳层有交易终端的骨架**。左侧分组、当前项高亮、顶部柜台选择、连接状态、交易日状态、三个应急按钮（全撤/停全部/只减仓）都在正确的位置上。
4. **交易日历做得完整**。月网格、今天高亮、交易日/周末/休市图例、下一交易日、接下来 12 个交易日、夜盘规则说明，信息层级清楚，是内部页面里完成度最高的一个。
5. **订单页的密度在 1366 下是合适的**。20 行订单、状态计数、账户筛选、分页、成交明细，表格行高约 37px，数字右对齐，基本具备 blotter 的雏形。
6. **安全意图是存在的**：手工单有服务端风控提示、角色/离线禁用、按名义金额触发的输入合约确认；策略激活有确认弹窗；应急操作有确认弹窗和回执。方向对，缺的是执行一致性和更细的权限/影响提示。
7. **执行拓扑的数据密度和字段完整度高**。Agent、ORS、绑定、部署、心跳、PID、fencing token、stream id 都在，是很好的运维数据基础。
8. **空状态和错误提示并非完全没有**。Alerts、StrategyView 的订单/成交/影子信号、Calendar 的后续交易日、Monitoring 的对账都有“暂无/不可用”文案，比直接显示空白好。

## 3. 问题清单

> 分级口径：
> - **P0 必须修**：会导致错误决策、错误订单、漏撤、误停、无法审计，或让人误以为系统已生效。
> - **P1 应该修**：显著降低盘中效率、增加误操作概率、破坏信息可信度，试点前应完成。
> - **P2 审美/打磨**：不直接影响交易正确性，但决定它像不像专业终端。

应急操作可以保留一键可达，但建议从“三个常驻红黄按钮”改为一个明确的 `应急处置` 入口 + 快捷键，展开后是“全撤 / 停全部 / 只减仓 / 降杠杆”，每个动作带范围、影响、回执。这样既不丢速度，也不让全站长期处于“红色警报”状态。

### 4.3 四条核心用户旅程

1. **开盘前 5 分钟**：驾驶舱 → 权益/保证金 → 策略健康 → 待处理提醒 → 交易日/夜盘状态。
2. **盘中下单**：合约搜索/期权链 → 交易票 → 预检（名义/保证金/费用/偏离）→ 确认 → 订单回执 → 订单表。
3. **异常处置**：告警 → 定位策略/合约 → 只减仓/停策略/全撤 → 逐单回执 → 审计。
4. **收盘复盘**：订单/成交 → 策略 PnL/持仓 → 配置/部署变更 → 审计导出。

如果一条旅程需要跨 3 个以上一级导航、且没有上下文携带，就说明 IA 还需要收紧。

## 5. 页面级建议

### 5.1 Dashboard / 交易驾驶舱

**现状：** 4 个指标卡、6 个指标卡、1 张持仓表、右侧提醒/策略/事件。全部是等宽卡片，没有图，没有持仓合计，没有下钻；1920 下拉满，1366 下紧凑但信息不足；今日休市用整行黄色 Alert。

**建议首屏：**

```text
┌ 顶栏：环境 | 交易日/时段 | 数据龄 | 账户/角色 | 搜索 | 通知 | 应急 ┐
├ 风险带：权益 | 当日 PnL(已实现/浮盈/费用) | 保证金使用率[bar] | 可用 | Delta/Gamma/Vega/Theta 限额用量 ┤
├──────────────────────────────────────┬─────────────────────────────┤
│ 8 列：标的走势 + 持仓/挂单/成交标记      │ 4 列：策略健康 + 告警时间线    │
│      （1m/5m/日，数据龄，图例）          │      （按 severity 排序）      │
├──────────────────────────────────────┼─────────────────────────────┤
│ 8 列：当前持仓（分组/合计/可下钻）        │ 4 列：今日事件（过滤心跳）      │
└──────────────────────────────────────┴─────────────────────────────┘
```

**关键改动：**

- 风险带优先回答“今天赚/亏多少、离限额多远、还能不能加仓”，而不是先展示 Greeks。
- 每个数字带单位、阈值、数据龄；`0.0%` 保证金用中性色，只有 >80% 才变黄、>90% 才变红。
- 持仓表增加：最新价、浮动盈亏率、保证金、到期日/剩余天数、策略归属、交易所、是否主力；底部合计行。
- 所有卡片/行可点击下钻到期权链、订单、策略详情，并带过滤条件。
- 策略提醒按 severity + 时间排序，显示“建议动作”而不是只显示内部状态。
- 最近事件默认过滤 `RUNTIME_HEARTBEAT`，只保留交易、状态变化、错误、配置变更。
- 删除正文中的日历 Alert；session 信息放顶栏 chip + popover。
- 数据失败时整页进入“只读/过期”状态，不要用 mock 填满。

### 5.2 ManualOrder / 手工交易

**现状：** 左表单右空风险面板；默认价与实时价脱节；`预检并提交` 一步可能发单；无订单类型/TIF/本地只减仓；三条警告堆叠。

**建议：**

- 三栏工作区：市场上下文（盘口/最近成交/持仓/合约参数）｜订单票｜预检与提交。
- 订单票字段：账户（选择器）、合约（搜索 + 最近）、方向（买/卖 segmented）、开平、订单类型（限价/市价/FAK/FOK）、价格（tick stepper + 最新价/买一/卖一快捷键）、数量（lot stepper + 1/2/最大）、TIF、只减仓、备注。
- 默认价格取最新价或留空；偏离最新价超过阈值时黄色提示，超过更大阈值时红色并需额外确认。
- 右侧预检常驻：名义金额、预计保证金、可用资金、预计手续费、成交后仓位/ Greeks、价格偏离、风控结果；修改任何字段立即失效并要求重新预检。
- CTA 拆成“预检” → 预检结果卡 → “确认下单”；大额单输入合约代码确认，确认框重复显示环境/账户/方向/价格/数量。
- 提交后保留表单并显示订单生命周期：已创建 → 已报 → 部分成交 → 成交/撤单/拒单，附“查看订单”。
- 把服务端校验说明收进一个 info popover，不要三条 warning 占满首屏。

### 5.3 Orders / 订单与成交

**现状：** 1366 下密度不错，计数/筛选/分页/成交明细都有；但列优先级、搜索、撤单、详情、sticky header 缺失，状态中英混排，mock 回退。

**建议：**

- 顶部 tabs：`未完成 2` / `已成交 4` / `已撤 19` / `全部 25`；默认“未完成”。
- 工具栏：合约/订单号搜索、账户、策略、来源（策略/手工）、方向、时间范围（今日/本周/自定义）、刷新暂停、导出。
- 列：时间（含秒）→ 合约 → 方向/开平 → 委托价 → 数量/已成 → 状态 → 来源 → 订单号 → 操作；账户/场所放行详情或上下文。
- 行内：撤单、详情；勾选后批量撤单/按筛选撤单；撤单请求后显示“已发/已撤/失败”状态，而不是只发一个 toast。
- 行展开/抽屉：生命周期时间线、拒单原因、策略 ID、offset/TIF、成交明细、手续费、已实现 PnL。
- sticky header、列排序、列配置、密度切换；空态给“今日暂无订单 + 查看全部/刷新”。
- 成交明细独立 tab，补手续费、成交均价、对手方向、订单链接。

### 5.4 Strategies / 策略配置

**现状：** 3 行列表 + 最近部署；5 个文本操作；统计 chip 不可点；状态/模式重复；无健康/PnL/心跳；向导可跳过校验、直接 deploy；ACTIVE 承诺确认但未实现。

**建议：**

- 列表改为“策略健康板”，支持表格/卡片切换；每行：策略名、类型、标的、部署状态 + 心跳点、当日 PnL、持仓、挂单、告警、最后更新、操作。
- 顶部：搜索、状态筛选（全部/运行/停止/异常/未部署）、标的筛选；“仅看异常”开关。
- 操作收进“更多”：详情、编辑（新版本）、部署、停止、复制、查看日志；主操作只保留一个，且按状态变化。
- 部署前：显示版本、配置 hash、目标 ORS、账户、冲突检查、限额叠加、预计保证金；部署后显示 PENDING → ACTIVE/FAILED，失败可回滚。
- 向导：四步 + 右侧摘要；每步校验；数字带单位/范围；账户/负责人/环境必填；复核页人话摘要 + diff + what-if；`保存草稿` / `提交审批` / `部署` 分离；ACTIVE 需 ADMIN 审批或输入策略 ID。
- PAIR 参数：按“腿/入场出场/对冲/风险”分组；每个缩写给中文名、单位、默认值、说明；高级参数折叠；保存前 diff；展示价差图和当前偏离。

### 5.5 StrategyView / 策略详情

**现状：** 两层 header；6 个统计卡多为 0；无 PnL 图、无持仓、无配置 diff、无日志；PAIR 专用视图和通用视图分支有死代码；打开即 ack 提醒。

**建议：**

- 单一 header：策略名 + 环境/状态/心跳 + 主操作；下面 tabs：概览 / 持仓与订单 / 指标 / 配置与版本 / 日志 / 部署。
- 概览：PnL 曲线（当日/累计）、持仓与敞口、成交/挂单数、拒单率、报价覆盖率、最后心跳；右侧固定风险限额/告警。
- 配置：当前生效参数（GLOBAL/OVERRIDE 来源）、版本、hash、diff、回滚；不要只显示只读 JSON。
- 日志：按时间倒序，过滤心跳，显示信号/下单/拒单/风控触发；可按订单号/策略 ID 关联。
- PAIR：价差主图 + entry/exit/remove 带 + 成交标记 + 两腿盘口 + 价差持仓/挂单；不要把 4 个数字重复成 8 张卡。
- 告警：显式“确认/全部确认”，不要自动 ack；显示 ack 人/时间。

### 5.6 Monitor / 系统监控

**现状：** 2 张服务卡 + 3 个“未接入”进度条 + 2 张空卡；没有自动刷新；UP 由配置启用推导；告警不能操作；1280 监控窗仍带完整侧栏。

**建议：**

- 顶部状态条：`交易可用/只读`、`控制面`、`行情 WS`、`ORS/CTP`、`数据龄`、`版本`、`最后刷新`。
- 服务网格：每张卡显示 health、latency、uptime、version、last heartbeat、error reason；区分 `ENABLED` 与 `HEALTHY`。
- 指标区：Runtime p99、Aeron 队列、ClickHouse 磁盘、WS 连接数、API p99、拒单率、报价覆盖率；每个带 1h/1d sparkline + 阈值。
- 告警区：severity、当前值/阈值、持续时长、影响策略/合约、ack/静默/升级、runbook。
- 对账：last run、样本数、差异明细、跳转到订单/持仓；不要只显示“一致”。
- 自动刷新 5–10s，可暂停；刷新失败显示 stale，不打绿。
- Electron `/monitor` 使用无侧栏 compact 模式：2 列大字号状态 + 告警 ticker，适配 1280×860 always-on-top。

### 5.7 Alerts / 消息中心

**现状：** 仅当天、最多 200 条；无 severity/筛选/批量 ack/系统告警；空态占满页面；两个导航入口重复 badge。

**建议：**

- 统一为告警/通知收件箱：待处理 / 已确认 / 全部；来源（策略/系统/执行/风控）、severity、策略、合约、时间。
- 行：severity 图标、标题、策略/合约、触发值/阈值、时间、状态、ack 人；展开显示建议动作/runbook/关联订单。
- 批量 ack、全部 ack、静默 1h/4h/当日；ack 可加备注；保留至少 30 天。
- 通知设置：声音/桌面通知/仅 P0；与 Electron Notification 集成。
- 导航只保留一个入口 + 顶栏铃铛；badge 只显示未确认数。

### 5.8 Calendar / 交易日历

**现状：** 页面完整但偏长；3 张摘要 + 月历 + 12 个后续交易日重复；没有节假日名称/session 详情；内部文件名外露。

**建议：**

- 摘要压缩为一行：今天/下一交易日/本月交易日/夜盘状态。
- 月历格显示：日盘/夜盘/休市/节假日名；今天用边框 + 标签；点击日期打开右侧详情（session、夜盘归属、到期/交割月、备注）。
- 后续交易日 6 个 + “展开”；去掉重复的 12 卡片。
- 副标题改为“交易所交易日与夜盘规则”，不要出现 `trading_days.txt`。
- 增加“到期日/交割月”提醒，服务策略和期权链。

### 5.9 Fees / 费率配置

**现状：** 18 行表格；只能编辑，不能新增；金额/手数没有单位；账户/合约/交易所混排；没有生效日/版本；0 值可能代表“未配置”而不是“免费”。

**建议：**

- 增加新增/复制/批量导入/从模板生成；按账户分组，组内按合约。
- 列：账户、合约、交易所、计费方式（元/手、成交额万分比、固定）、买、卖、乘数、昨结、生效日、版本、操作；表头写单位。
- 0 值显示“未配置”或“0（免费）”，用不同样式；不要用 0 混淆。
- 编辑对话框分组：身份（账户/合约/交易所只读）｜费用｜乘数/昨结｜生效日；保存前 diff + 影响预估（一手往返费用）。
- 增加“按当前费率估算一手成本”的小卡片。

### 5.10 Accounts / Venues / 柜台与账户

**现状：** 柜台 + 账户合并在一个页面，信息完整；但余额/可用/保证金可手工编辑；没有连接健康/最后同步；状态 chip 文案 `配置已启用/Adapter离线` 混在一个标签里；停用无确认。

**建议：**

- 分两个区块：`柜台连接`（ID/名称/类型/前置/状态/最后心跳/关联 ORS）与 `账户`（账户/柜台/BrokerID/InvestorID/类型/余额/可用/保证金/同步时间/状态）。
- 真实环境下余额/可用/保证金只读，来源标记“CTP 同步/模拟 fixture”；模拟环境可编辑但要显著标注。
- 账户行显示绑定 ORS、运行状态、最后同步、异常原因；停用/启用加确认与影响提示。
- 增加“测试连接”与“查看绑定策略”入口。
- 密码/密钥永不明文展示（当前已做到，保留）。

### 5.11 Execution / 执行拓扑

**现状：** 4 张表（Agents/ORS/绑定/部署）数据很全，是很好的运维基础；但全是堆叠表格，没有拓扑图、筛选、自动刷新、确认。11 列的 ORS 表在 1440 下换行严重。

**建议：**

- 顶部可视化拓扑：Agent → ORS → Strategy/Deployment，节点用 health 点 + 心跳 age；点击节点打开详情抽屉。
- 下方保留表格作为明细，加搜索/状态筛选/自动刷新/最后更新时间；离线行整行浅红/橙底，而不是只有 chip。
- ORS 列分组：身份（ORS/柜台/账户/Agent）｜连接（Adapter/PID/心跳）｜流（Order/Cancel/Update/Trade/MD）｜Fencing；表头可折叠。
- 激活/停止/解绑加确认与影响摘要（受影响策略、未完成订单、持仓）；操作后显示 PENDING/ACTIVE/FAILED。
- `desired / actual` 改成“目标/实际”+ 同步图标/tooltip；不要小写英文。
- 策略绑定支持批量/搜索，显示版本/进程/最后心跳。

### 5.12 Audit / 审计日志

**现状：** 3 条 mock 记录；无筛选/分页/diff/导出；payload 截断；心跳和真实变更混在一起。

**建议：**

- 只显示真实数据；失败时 fail-closed，禁止 mock。
- 工具栏：时间范围、操作者、动作、对象、结果、trace id；默认过滤心跳。
- 行详情：before/after diff（结构化字段）、来源 IP/会话、请求 id、关联订单/策略。
- 分页/虚拟滚动；导出 CSV；显示只读/追加写/哈希校验状态。
- 关键动作（下单、撤单、部署、配置、权限）用醒目图标/级别；提供“复制 trace id”。

### 5.13 OptionChain / 期权链（补充）

- 真实数据或明确“合成/只读”，不要既展示又允许下单。
- 到期/标的切换必须绑定数据；当前 `2027-03` 选项是假控制。
- 保持连续行权价；未配置合约置灰“不可交易”，不要删掉 ATM。
- Strike 列 sticky；Call/Put 两侧对称滚动；列显示配置；1440 下至少能看全核心 6 列。
- 所有数字 formatter；`IV Rank`/`25Δ RR` 不要输出浮点原值。
- Bid/Ask 单元格 hover 显示“点击卖出/买入”；快捷下单复用交易票，预检后才可提交。
- 页头显示数据源/数据龄/ATM/标的；增加 `Ctrl+F` 合约搜索。

### 5.14 Indicators / CommonConfig（补充）

- **Indicators**：卡片布局可以保留；增加 sparkline、变化值、阈值使用率、被引用策略、最后计算时间；API 失败显示错误态而不是 mock；`9–10px` 的 chip 提到 11px；阈值/单位写在卡片底部而不是藏在标题里。
- **CommonConfig**：`SIZE/MAX_SIZE/SLOP_TICKS` 等缩写加中文名、单位、默认值、来源；展示“全局默认 vs 策略覆盖”的 diff；保存前确认影响范围；API 失败时禁止编辑；增加版本/审计/恢复默认确认。当前 11 列表格在 1440 下过挤，建议按“执行/风控/收盘”分组或改成详情抽屉。

## 6. 设计系统建议

### 6.1 颜色 Token

当前问题：`primary` 和 `warning` 都是琥珀系；`success` 填充 chip 白字对比度不足；买卖/涨跌/盈亏/错误复用红绿。建议拆成四组 token，并在组件中禁止跨组复用。

| Token | 建议值（深色） | 用途 |
|---|---|---|
| `bg.canvas` | `#0b0e14` | 页面底色 |
| `bg.surface` | `#121821` | 卡片/面板 |
| `bg.elevated` | `#18202b` | 弹窗/抽屉/悬浮 |
| `bg.hover` | `#1e2733` | 行 hover |
| `border.subtle` | `#253040` | 卡片/表格分割 |
| `border.strong` | `#364457` | 输入框/选中 |
| `text.primary` | `#e8edf5` | 主文本 |
| `text.secondary` | `#aab4c2` | 次要文本 |
| `text.muted` | `#748092` | 辅助/时间 |
| `brand.amber` | `#f5a623` | 品牌、选中、登录 CTA |
| `action.primary` | `#5b8def` | 页面主操作（新建/应用/确认） |
| `success` | `#37c39a` | 系统正常/已成交（配深色文字或 tint） |
| `warning` | `#e9b34a` | 需要注意但非错误 |
| `danger` | `#ff5d5d` | 错误/危险动作 |
| `info` | `#62a8ff` | 提示/链接 |
| `env.sim` | `#4f8cff` | SIM 环境条 |
| `env.shadow` | `#9b7bff` | SHADOW 环境条 |
| `env.live` | `#ff4d4f` | LIVE 环境条 |

**对比度要求：**

- 正文/表格 ≥ 4.5:1；大字号 ≥ 3:1；状态 chip 的白字必须 ≥ 4.5:1。
- 当前 `#26a69a` + 白字 = 3.0:1，`#ef5350` + 白字 = 3.49:1，均不满足小字号 AA。建议改用 tint 背景 + 高对比文字，例如 `rgba(55,195,154,0.14)` 背景 + `#7fe3c4` 文本。
- 红色/绿色不是唯一信息通道：状态必须同时有文字/图标；PnL 带 `+/-` 符号。

**方向色建议：**

- 若目标用户是中国期货交易员：默认“红涨/红买、绿跌/绿卖”，但在设置中允许切换；系统语义（warning/danger）不要直接复用买卖色，改用琥珀/蓝色 + 文案。
- 若面向国际用户：绿涨/红跌；同样提供切换。
- 无论哪种，`BUY/SELL` 必须有中文/英文文本，不能只靠颜色；SELL 不应使用 `error` 语义色。

### 6.2 字体层级

当前：H5 约 22.3px，正文 14.9px，表格 12px，chip 9–10px。建议：

| 角色 | 字号/字重 | 用途 |
|---|---|---|
| Page title | 24 / 600 | 页面标题 |
| Section | 16 / 600 | 卡片/区块标题 |
| Body | 13 / 400 | 正文、表格 |
| Table | 12.5–13 / 400 | 数据表；数字用 tabular-nums |
| Caption | 11 / 500 | 单位、时间、辅助说明 |
| Micro | 11 / 600（下限） | 状态 chip；禁止 9px |
| Numeric display | 28–36 / 700 | 驾驶舱关键数字 |
| Mono | 12 / 400 | 订单号、trace id、日志 |

- 全部数字启用 `font-variant-numeric: tabular-nums`；订单号/日志使用 `Roboto Mono` 或 `SF Mono`。
- **字体必须真正加载**：当前只写了 `Inter` 字体栈，没有 `@fontsource`/Web Font 引入；建议自托管 Inter Variable，或明确采用系统字体栈，避免不同机器回退导致列宽/数字跳动。
- 不要用字号大小表达所有层级；用字重、颜色、间距一起建立层级。
- 中文使用 `PingFang SC`/`Microsoft YaHei`，英文/数字 `Inter`，保持当前字体栈即可。

### 6.3 间距、圆角、边框

| 项 | 建议 |
|---|---|
| 基础网格 | 4px；常用 8/12/16/24/32 |
| 页面 padding | 24px（`clamp(16px, 1.5vw, 24px)`） |
| 卡片 padding | 16px（紧凑 12px） |
| 区块间距 | 16px；页面大区块 24px |
| 表格行高 | 34px 紧凑 / 38px 舒适；表头 32px |
| 输入框高度 | 36px（small）/ 40px（常规） |
| 圆角 | 按钮/输入 4px；卡片 6px；弹窗/抽屉 8px；状态标签 4px（不要全部 999 胶囊） |
| 阴影 | 深色下基本不用；用 1px 边框 + 层级背景。仅弹窗/抽屉用轻阴影 |
| 分割线 | `border.subtle`；表格行之间可以不用线，靠 hover/间距 |

### 6.4 表格规范

交易终端 80% 的时间在看表，表格是核心组件，不应每页各写一套。

- **结构**：工具栏（搜索/筛选/刷新/导出/列配置）→ sticky header → 虚拟滚动 body → 汇总/分页。
- **数字**：右对齐；价格按 instrument tick 精度；数量整数；金额千分位；单位写在表头（如 `Vega（元/vol）`）。
- **状态**：dot + 文本 + 可选 code；不要只用颜色；状态列固定宽度；`OPEN`/`PARTIAL` 高亮。
- **排序**：所有数值/时间列可排序；默认时间倒序；排序状态可见。
- **行**：hover 显示操作；选中行有左侧 2px 主色条；危险操作不放在行内第一位置。
- **空态**：图标 + 一句解释 + 主 CTA（如“暂无未完成订单 · 查看全部”）。
- **加载**：按列宽生成 skeleton 行，不要整页 spinner。
- **错误**：表内错误条 + 重试；不要把错误变成空表。
- **密度**：紧凑/舒适切换；保存到用户偏好。
- **响应式**：1366 不横向滚动页面；宽表在卡片内部横向滚动，Strike/订单号等关键列 sticky。

### 6.5 表单规范

- 标签外置，单位后缀（`价格（元）`、`数量（手）`、`Vega（元/vol）`）。
- 数字字段用 `type=number`/`inputMode=decimal`，加 step/min/max；价格/数量用 stepper 或快捷键。
- 两列表单只在 ≥1440 使用；1366 下单列或 2 列但标签不换行。
- 校验时机：blur 后显示字段错误，提交时显示错误摘要并聚焦第一个错误；不要只禁用按钮不解释。
- 危险表单（配置/费率/策略）保存前显示 diff/影响；未保存时关闭需确认。
- 提交按钮有 loading + 防重复；成功后保留上下文并显示回执，不要只弹 toast。

### 6.6 状态标签规范

| 状态 | 建议标签 | 颜色 | 处理 |
|---|---|---|---|
| SIM | `SIM · 模拟` | 蓝 | 全局环境条常驻 |
| SHADOW | `SHADOW · 影子` | 紫 | 全局环境条常驻 |
| LIVE | `LIVE · 实盘` | 红 | 全局环境条 + 下单确认重复 |
| OK/ACTIVE/RUNNING | `正常/运行中` + 英文 code | 绿点 + 文本 | 不要整块绿色填充 |
| WARN/INACTIVE | `警告/未激活` | 琥珀 | 需要动作时置顶 |
| CRIT/OFFLINE/FAILED | `严重/离线/失败` | 红 | 附原因/最后心跳 |
| UNKNOWN/未接入 | `未知/未接入` | 灰 | **绝不能显示绿色** |
| OPEN/PARTIAL | `未完成/部分成交` | 蓝/琥珀 | 订单表默认高亮 |
| FILLED | `已成交` | 绿点 + 文本 | 不要用白字亮绿底 |
| CANCELED | `已撤` | 灰 | 与失败区分 |
| REJECTED | `拒单` | 红 | 附拒单原因 |

- Chip 高度 22px，字号 11px，圆角 4px；最多 1 个主状态 + 1 个辅助标签。
- 颜色之外必须有文本/图标；同一屏不要超过 3 种高饱和色。

### 6.7 图表与数据可视化

- 统一 ChartTheme：轴/网格/工具提示/图例全部使用 tokens；不要 `echarts.init(..., 'dark')` 后让库自己配色。
- 主图至少 320px 高；支持 crosshair、时间轴缩放、数据缺口断线、数据龄水印。
- 驾驶舱至少 3 类图：PnL 曲线、标的走势、风险限额条/暴露条形图；策略详情至少 2 类：PnL + 持仓/成交。
- 期权链用表格而不是图；Vol Smile 需要 ATM 标记、25Δ 标记、单位、到期切换。
- 动画只用于状态变化（150–200ms 淡入/闪一下），不要做持续动画；尊重 `prefers-reduced-motion`。

### 6.8 可访问性与键盘

- 全局 `:focus-visible` 2px 蓝色 outline + 2px offset；不要用 `outline:none` 除非提供等效高对比样式。
- 所有 icon-only 按钮加 `aria-label`；表格加 caption/aria-label；通知用 `aria-live`。
- skip link “跳到主内容”；导航 landmark；对话框焦点陷阱/ESC 关闭。
- 快捷键：`⌘K` 搜索、`B/S` 买卖、`Esc` 关闭、`F2` 改价、`Del` 撤单、`⌘⇧K` 应急；在帮助面板列出。
- 对比度：所有小字号文本 ≥4.5:1；选中/焦点状态 ≥3:1。
- 色盲：状态/方向都加文字、图标或形状；提供“色盲友好”主题（红/蓝替代红/绿）。
- 减少动态：遵循 `prefers-reduced-motion`；实时数字不要持续闪烁。

## 7. 响应式与桌面壳

| 场景 | 当前表现 | 目标 |
|---|---|---|
| 1366×768 | 页面无横向溢出（实测 `scrollWidth=1366`）；订单表 20 行可读；手工单两栏；期权链内部横向滚动 | 保持无页面横向滚动；驾驶舱首屏至少包含风险带 + 3 行持仓；合约搜索可见 |
| 1440×900 | 页面无溢出；行情条被隐藏；期权链 1500px 表格只露出部分 Put 列；6 个指标卡偏挤 | 行情条常驻；期权链核心列全可见（Strike sticky）；12 列网格 |
| 1920×1080 | 无溢出；4 张指标卡各约 405px 宽，文字仍 12px；驾驶舱/监控大量留白 | 最大内容宽 1680 或 3 栏；图表/深度/事件填满；不要让卡片等比放大文字不放大 |
| 1280×860 Electron 监控窗 | 仍显示 220px 侧栏 + 49px 顶栏；3 列 grid 只有 2 张卡 | 专用 compact monitor：无侧栏、2 列、大字号、告警 ticker、always-on-top |
| 1024 浏览器 | `document.scrollWidth=1280`，横向滚动，右侧被裁 | 显示“窗口过窄，请最大化”；或折叠侧栏 + 单列；Electron 已限制 minWidth 1280 |
| 多窗口 | Tray 可开 `/options`、`/orders`、`/strategies`、`/monitor`，但页面内没有“在新窗口打开” | 表格行/详情提供“在新窗口打开”；独立窗口保留上下文（策略/合约过滤） |

**桌面壳建议：**

- 为 `/monitor` 做独立布局，不要复用主壳。
- 更新提示不要在盘中被强制 reload；检测未提交表单/挂单。
- 增加全局快捷键帮助和“打开监控窗/订单窗”的入口。
- 窗口标题随页面/策略/合约变化，便于多窗口切换。

## 8. 改造优先级与工作量

### 8.1 快速收益（1–2 天）

| # | 改动 | 预估 | 价值 |

## 9. 验收清单

### 9.1 数据可信与安全

- [ ] API 失败时页面不显示 mock 业务行；显示“数据不可用”并禁用下单/撤单/部署。
- [ ] 缓存数据有 `as of` 时间与 `STALE` 标识；颜色与实时数据不同。
- [ ] 全局环境条明确显示 SIM/SHADOW/LIVE；下单确认重复显示环境与账户。
- [ ] 顶栏/侧栏账户一致；角色可见；切换账户/ORS 有确认。
- [ ] 控制面、行情 WS、ORS/CTP 健康分开显示；“交易通道已连接”不再只依赖 `/health`。
- [ ] 每个关键数字有数据龄；>3s 黄、>10s 红并禁用相关动作。

### 9.2 交易流程

- [ ] 手工单默认价=最新价或空；偏离 >0.5% 提示，>2% 额外确认。
- [ ] 有订单类型/TIF/开平/本地只减仓；账户/合约从选择器选。
- [ ] 预检结果常驻；改价/改量后旧预检失效；两段提交。
- [ ] 订单表可单笔撤单、批量撤单、按筛选撤单；有回执。
- [ ] 订单详情含生命周期、来源、offset/TIF、拒单原因、成交明细。
- [ ] 策略激活/停止/解绑/柜台停用/合约停用均有影响摘要 + 确认 + busy + 审计。
- [ ] ACTIVE 部署有审批或输入策略 ID 确认；不能重复部署。
- [ ] 打开策略详情不会自动 ack 提醒；ack 需显式操作。

### 9.3 信息架构与视觉

- [ ] 没有单页一级分组；策略详情不在一级导航。
- [ ] 通知/告警只有一个主入口；badge 只显示未确认数。
- [ ] 顶栏 1440 可见行情条；1920 内容不无限拉伸。
- [ ] 所有数字有单位/精度；无浮点原值；日期格式统一；表格数字右对齐。
- [ ] 状态色语义统一；BUY/SELL 不再复用 success/error；主色与警告色可区分。
- [ ] 每个页面有匹配布局的 loading/空/错误态；表格空态有 CTA。
- [ ] 9px 文本清零；chip ≥11px；填充 chip 对比度 ≥4.5:1。

### 9.4 响应式与可访问性

- [ ] 1366/1440/1920 无页面横向滚动；宽表内部滚动且关键列 sticky。
- [ ] 1280×860 monitor 使用无侧栏 compact 布局。
- [ ] 1024 浏览器提示窗口过窄或优雅降级。
- [ ] Tab 可到达所有交互元素；焦点环 2px 可见；ESC 关闭弹窗；skip link 可用。
- [ ] 图标按钮有 aria-label；表格有 caption；文档标题随页面变化。
- [ ] 色盲友好：状态有文字/图标；支持减少动态。
- [ ] Playwright 基线覆盖 1366/1440/1920 + monitor + 离线/错误态。

## 10. 下一步建议

1. **第 1 周：先修信任与安全**。fail-closed、环境/账户、手工单默认价与两段提交、危险动作确认、订单撤单。这些不需要等大改版，但能立刻降低事故概率。
2. **第 2 周：做驾驶舱 + 交易票 + 订单工作台**。这是交易员每天使用频率最高的三块，也是“像不像交易终端”的关键。
3. **第 3–4 周：策略/监控/告警/审计 + 设计系统**。把状态、表格、表单、确认、数据龄统一成组件；同步做 IA 重构和可访问性。
4. **每轮找 2–3 名真实交易员做任务测试**：开盘检查、手工下单、撤单、策略停止、告警处理；记录完成时间、误点次数、是否需要帮助。
5. **视觉回归**：在现有 Playwright 配置上增加 1366 和 1280 monitor 项目，覆盖 API 失败/离线状态，不要只截正常路径。
