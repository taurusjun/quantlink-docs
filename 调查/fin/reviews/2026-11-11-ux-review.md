# quantlink-fin 管理端 UX Review

> 日期：2026-11-11  
> 范围：`web/`（React + MUI）  
> 角色：独立 UX 设计师 agent  
> 方法：源码走查 + `docs/evidence/T-030/` 截图 + SHADOW 环境 1440/1280/900 只读实测  
> 约束：未提交订单、撤单、部署、审批、ack 或配置保存，未修改应用代码

## 0. 结论摘要

1. 系统已经有交易系统的壳，但还不是交易员的工作台。深色高密度、全局应急、实时状态链、手工单预检成立；但订单页缺单笔撤单/订单详情，顶栏/页面缺可用的 scoped 行情上下文。
2. 导航 4 组、20 个一级入口，“策略”组只有执行拓扑；执行拓扑/系统监控、消息中心/系统告警、持仓/快照/账务/策略账户存在重复。
3. 高风险动作是最大的信任缺口：策略详情 10 个动作，停用/停止/停止并平仓语义相近但确认不一致；应急无影响面和执行进度；只减仓无全局常驻状态。
4. 数据呈现不够可信：价格/金额/IV/时间/ID/枚举格式不统一，部分账户快照被当成总权益，表格存在列错位。
5. 1440 可用，1280 开始拥挤，900 存在功能性损坏。

## 1. 做得好的地方

- 深色交易终端视觉成立：`#0f1218` 画布、`#161b24` 卡片、6px 圆角、1px 边框、琥珀强调色；表格 12px、数字右对齐、`tabular-nums`。
- 全局壳层骨架正确：固定顶栏 + 分组侧栏 + 全局应急 + 交易日/连接状态；有 skip link、focus ring、路由标题。
- 健康状态拆分较细：`/system/status` 区分 `controlPlane`、`agentOnline`、`orsRunning`、`marketFresh`、`marketAgeMs`。
- 手工单闭环完整：填写 → 预览 → 名义金额/保证金/可用/合约参数 → 超阈值二次确认 → 提交。
- 策略详情领域信息完整：绑定柜台/账户、LIVE 警告、Agent/控制面/账本 PnL 来源、账户快照、指标过期、对账、版本、部署、日志。
- 失败态诚实：全撤文案不假装成功；撤单失败显示 Aeron 未连接；多数页面不再回退 mock 数据。
- 系统告警具备 P0/P1、ack/静默/解决、runbook、sticky header 等运维原语。
- 空态/骨架/确认框有统一意图，`ConfirmDialog` 已集中管理确认。

## 2. P0 问题

### P0-1 订单页没有撤单、订单详情和批量撤单

**位置**：`web/src/pages/OrdersV2.tsx:243-268`

问题：

- 订单表只有只读列，无操作列。
- 撤单只存在于 `ManualBook.tsx:502-506`，只覆盖 MANUAL book。
- 策略单发现挂错只能全局“全撤”。
- 无订单生命周期、拒单原因、offset/TIF、成交明细。

改法：

1. 固定操作列：撤单 + 详情；按 `OPEN/PARTIAL/CANCEL_REQUESTED` 控制动作。
2. 增加勾选和批量撤单，确认框列出订单号、合约、方向、数量、账户、策略。
3. 行详情抽屉展示生命周期：创建 → 报单 → 交易所确认 → 部分成交 → 撤单请求 → 回执/拒绝，附成交明细。
4. 撤单后行内逐单显示 `撤单已发 / 已撤 / 撤单失败`，写入审计。
5. 默认 tab 改为“未完成”，默认时间范围“今日 + 未完成”。
6. 宽表使用内部横向滚动，操作列 sticky。

验收：

- 1440/1280/900 都能点击撤单/详情。
- 单笔撤单 ≤2 次点击。
- 批量确认框列出 N 笔订单。
- 失败有原因，不刷新整页。

### P0-2 应急与只减仓缺少影响面、进度和常驻状态

**位置**：`web/src/components/AppShell.tsx:245-268, 377-388, 541-558`

问题：

- 全撤/停全部并平仓前看不到影响多少策略、账户、订单、持仓。
- 执行后只有 6 秒 Snackbar，无法知道逐策略完成情况。
- 只减仓只能在菜单文案体现，其他页面看不出。
- `Alt+C` / `Alt+S` 可直接打开应急确认，容易误触。

改法：

1. 应急改为右侧面板：环境、账户/柜台、未完成订单数、策略数、持仓行数、只减仓状态。
2. 停全部并平仓需要二次确认 + 影响摘要/输入确认。
3. 执行后展示逐策略 PENDING/RUNNING/DONE/FAILED 和审计链接，不自动消失。
4. 只减仓开启后所有交易页顶部显示常驻状态条，开仓按钮禁用。
5. 全撤结果与“逐单回执”文案一致，否则修改文案。
6. 移除或改造 `Alt+C`/`Alt+S`。

验收：

- 操作前显示准确影响数量。
- 停全部后能看到逐策略完成状态。
- 只减仓刷新后仍有 banner。
- 所有应急动作写审计。

### P0-3 策略详情动作过多、语义冲突、确认不一致

**位置**：`web/src/pages/StrategyCenter.tsx:1487-1563`

当前动作：

```text
刷新 / 订单成交 / 编辑 / 激活 / 停用 / 停止 /
更新版本 / 复制 / 停止并平仓 / 删除
```

问题：

- `停用`、`停止`、`停止并平仓` 差别没有解释。
- 详情激活无确认，列表激活有确认。
- `停用策略` 直接 POST，无确认。
- 删除按钮在 ACTIVE 时仍可见，只靠后端拒绝。
- LIVE 提示承诺二次确认，但未覆盖所有动作。

改法：

1. 每个状态最多 1 个主操作 + “更多”。
2. 明确定义：
   - 停用：停止新报单，保留持仓
   - 停止：停止运行并撤单
   - 停止并平仓：撤单 + 平仓
3. 所有危险动作统一确认：动作 + 对象 + 环境 + 柜台/账户 + 影响。
4. 删除仅在 STOPPED 且无持仓/挂单时可用，要求输入策略 ID。
5. 详情 sticky header + 关闭按钮。

验收：

- 详情最多 1 主操作 + 1 更多。
- 停用/激活不能无确认改变交易状态。
- 列表与详情同名动作走同一确认逻辑。
- ACTIVE 状态下删除不可达。

### P0-4 900px 存在功能性损坏

**证据**：

- `OptionChainV2.tsx:91-117`：标题逐字换行，Greeks 与 Put 列被裁，无横向滚动。
- `StrategyCenter.tsx:881-1009`：操作列被 Card 裁掉，按钮不可见。
- `Alerts.tsx:155-175`：筛选框被压成 20px，确认/静默列不可见。
- `ManualBook.tsx:424-441`：只减仓开关文案断成三行。
- `Dashboard.tsx:197`：金额被裁。
- `AppShell.tsx:50,392-405`：220px 固定侧栏 + 760px 详情抽屉覆盖内容。

改法：

1. `>=1440` 固定侧栏；1280-1439 折叠为 64px 图标栏；<1280 overlay Drawer + 菜单按钮。
2. 标题/副标题独占一行，筛选器下一行可换行。
3. 所有宽表 `TableContainer` + `overflow-x:auto` + `minWidth`，关键列/操作列 sticky。
4. 期权链筛选两行/高级筛选，Strike sticky，Call/Put 对称。
5. 详情 Drawer `<1200` 全屏，`>=1200` `clamp(720px,58vw,960px)`，加 sticky header/关闭。
6. Dashboard 指标卡 1280 两列，900 单列。

验收：

- 900 下 `document.documentElement.scrollWidth === 900`。
- 期权链 Put 侧可滚动到达。
- 策略列表/消息中心操作按钮可点击。
- 三档宽度视觉回归通过。

### P0-5 部分账户快照被当成总权益

**位置**：`web/src/pages/Dashboard.tsx:159-207`

问题：

- `portfolio.equity` 或 `accountSnapshots` 求和直接作为权益。
- 1/3 快照时仍显示大号总权益。
- 0/`—`/WAITING 混用。
- 账户快照与 WS 持仓没有 asOf/来源/覆盖说明。

改法：

1. 聚合卡显示覆盖数、来源、asOf。
2. 覆盖不足 100% 时主值显示“部分”或 `—`。
3. 真实零显示 `0.00`，缺失显示 `—`。
4. 两个持仓来源标注“柜台快照 / WS 明细”及 asOf。
5. 增加数据质量条，可下钻缺失账户。

验收：

- 覆盖不足时首页不出现无前缀“总权益/总 PnL”。
- 任何数字可追溯来源和时间。

### P0-6 执行页 Agent/ORS 表格列错位

**位置**：`web/src/pages/Execution.tsx:283-350`

问题：

- Agent 表头 6 列，body 5 个 cell。
- “账户登录”实际显示心跳时间，“心跳”永远空。
- ORS 表头 11 列，body 12 个 cell，后几列错位。

改法：

1. 用列定义数组驱动表头/cell。
2. 登录、心跳、PID、Fencing、stream 分开。
3. 添加测试断言 cell 数 == header 数。

## 6. 设计系统规范

### 6.1 页面头

- 标题 24/600 + 副标题 13。
- 最多 2 个动作；筛选器不得与标题同排。
- 筛选栏独立一行，最多 6 个控件，更多进高级筛选。
- 活跃条件用 chip 展示并一键清除。

### 6.2 DataTable

- 外层内部横向滚动，宽表 `minWidth`，禁止 Card 裁切。
- sticky header；关键列/操作列 sticky。
- 行高 36/40；数字右对齐、`tabular-nums`。
- 价格按 tick，金额 2 位，数量整数。
- 每行最多 1 主状态 + 1 辅助 chip。
- 行内 1 主操作 + 更多；危险动作不进第一位置。
- 空/加载/错误三态互斥；分页中文化；CSV 导出当前筛选全集。

### 6.3 详情 Drawer

```text
[返回] 策略名 [LIVE] [ACTIVE] [age] [主操作] [更多] [×]  ← sticky
[当日 PnL | 持仓 | 挂单 | 告警]                           ← KPI
[概览 | 持仓 | 订单 | 成交 | PnL | 风险 | 对账 | 版本]    ← tabs
```

- `clamp(720px,58vw,960px)`；<1200 全屏；必须有关闭按钮。
- 先回答“现在怎么样”，再给动作。
- 账户/指标/版本进 tab 或折叠区，不阻塞持仓/订单首屏。

### 6.4 状态与颜色

- 环境 SIM/SHADOW/LIVE 常驻，不只靠颜色。
- 状态：正常/运行中/未激活/已停止/失败/未知；英文 code 放 tooltip。
- `STOPPED` 中性色，`FAILED` 红色；`CANCELED` 中性色。
- 颜色 token 分层：品牌琥珀、主操作钢蓝、系统 success/warning/danger、订单方向独立。
- 禁止 `success=buy`、`error=sell`；状态 chip 用 tint 背景 + 高对比文字。
- 小字号对比度 ≥4.5:1；当前 `#26a69a` 3.0:1、`#ef5350` 3.49:1 需修。

### 6.5 格式规范

| 类型 | 规范 |
|---|---|
| 价格 | 按合约 tick_size；表头写单位；禁止全站 toFixed(4) |
| 金额 | 千分位，2 位；单位放表头；0 与 — 区分 |
| 百分比/IV | IV 百分比 1 位；PnL 带 +/- |
| Greek | 2–3 位；Vega 注明元/vol |
| 时间 | `YYYY-MM-DD HH:mm:ss` Asia/Shanghai；age `3s/2m18s` + tooltip |
| ID | 12px mono、中间省略、可复制 |
| 枚举 | 中文主标签 + 英文 code tooltip |
| 分页 | 中文“每页行数/共 N 条” |

### 6.6 响应式

| 宽度 | 侧栏 | 页面头/筛选 | 表格 | 详情 |
|---|---|---|---|---|
| ≥1440 | 220px 固定 | 分行 | 全列/内部滚动 | 720–960px |
| 1280 | 64px 图标栏 | 可换行 | 内部滚动/sticky | 720–880px |
| 900 | overlay Drawer | 纵向堆叠 | 内部滚动/操作可达 | 全屏 |
| <768 | overlay 全屏 | 单列 | 卡片/内部滚动 | 全屏 |
