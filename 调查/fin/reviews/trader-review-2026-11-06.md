# 交易员评审：quantlink-fin 管理系统

- 日期：2026-11-06
- 评审人：期货/期权交易员视角（SHFE au/ag，做市 + 方向 + 对冲）
- 评审对象：`web/src/pages/*`、`backend/control-plane`、`backend/runtime`、影子库 schema、T-010/T-011/T-014/T-018/T-019
- 评审结论：**当前系统是"能跑通的工程样机"，不是"能上桌的交易系统"。**
- 不改代码，只给交易员要什么、字段、流程、校验、优先级。

---

## 0. 一句话结论与先行修复

三句话：

1. 现在的页面回答的是"系统有没有这个功能"，交易员要回答的是"**我现在有多少风险、该不该动手、动了会不会错**"。
2. 最危险的不是缺页面，而是**假数据、假全撤、假离线、假部署**——四个"看起来生效、实际没生效"的地方。
3. 指标不是图表装饰，是策略的输入契约。没有指标注册表，就不可能有可信的策略创建器。

我作为交易员，明天要上桌之前必须先改的 5 件事（详见 A / G）：

| 顺序 | 事项 | 原因 |
|---|---|---|
| 1 | **禁止 mock/缓存数据静默冒充实时数据**，生产环境 fail-closed | 我会照着假持仓做真决策 |
| 2 | **全撤必须真的发撤单并回报结果**，不能只改本地库 | 以为撤了，单子还挂在交易所 |
| 3 | **手工单前置风控 + 二次确认 + 合约/价格校验** | 乌龙指一次就够亏掉一个月 |
| 4 | **应急总开关：停止全部策略 / 只减仓 / 降杠杆 / 全撤（带范围与回执）** | 盘中出事时没时间点五个页面 |
| 5 | **驾驶舱接真实 Greeks/保证金/PNL/数据龄**，并加指标配置与显示的最小闭环 | 否则驾驶舱只是装饰画 |

## A. 交易员视角的核心问题清单

### A.0 分级口径

- **P0**：会导致错单、漏撤、超限、看不懂风险，或让交易员基于错误数据决策。上模拟盘/试点前必须解决。
- **P1**：显著降低效率、增加误操作概率，或缺少交易员每天必用的信息。试点期内必须解决。
- **P2**：体验与效率优化，可以排后。

## B. 指标配置与显示（核心）

### B.1 设计原则（先立规矩）

1. **指标是一等对象，不是图表配置**。有 ID、版本、口径、单位、所有者、依赖、引用关系。
2. **一处定义，三处消费**：驾驶舱显示、期权链列、策略条件，必须引用同一个 `indicator_id + version`，禁止各页面各算一套。
3. **单位必须显式**。Vega 是"每 1 个波动率点"还是"每 1%"，Theta 是"每天"还是"每年"，Gamma 是"每 1 元"还是"每 1%"，必须在 UI 上写出来，否则交易员会误判一个数量级。
4. **点时正确（point-in-time）**。策略引用的是"当时可得"的值，不能用未来数据；回放/预览必须用同一套计算。
5. **缺失值是一等状态**。`N/A`、`STALE`、`WARMUP`、`NO_QUOTE`、`FILTERED` 必须可区分，禁止用 0 或前值伪装。
6. **指标必须可解释**。点开能看到：公式说明、输入、窗口、最近样本、最后计算时间、数据源、被哪些策略引用。
7. **指标有成本**。每个指标标注计算频率与数据量；不允许交易员随手加 50 个高频指标把 Runtime 拖垮。

| 缺失值策略 | 下拉 | N/A | N/A / 前值（带 stale 标记）/ 跳过 / 停算 | 前值不得用于策略触发（只能显示） |
| 可见范围 | 多选 | 全员 | 角色/用户 | — |
| 备注 | 文本 | 空 | ≤500 字 | — |

#### B.3.5 保存时的校验（服务端也要做）

| 校验 | 级别 | 提示 |
|---|---|---|
| ID 唯一 | ERROR | 指标 ID 已存在 |
| 参数组合合法（如 fast < slow） | ERROR | 快线窗口必须小于慢线窗口 |
| 窗口 × 周期 ≤ 可用历史 | WARN | 历史数据不足，指标上线后前 N 分钟为 N/A |
| 期权指标必须选到期 | ERROR | 期权类指标必须至少选择一个到期 |
| 期权指标不能选"合成行情 + 实盘" | ERROR | 合成行情只能用于 SHADOW/回放 |
| 高频指标数量超预算 | WARN | 当前标的已有 12 个 1s 指标，可能影响延迟 |
| 阈值方向与单位匹配 | ERROR | 该指标单位为 %，阈值 0.6 应写 60 |
| 被策略引用时修改口径 | ERROR | 该指标被 3 个策略引用，修改口径将创建新版本 |
| 删除被引用指标 | ERROR | 被策略引用的指标不能删除，只能停用 |

#### B.4.1 驾驶舱指标卡（统一组件）

规则：

- 一屏最多 8 张卡；超出折叠到"更多指标"。
- 卡片顺序可拖拽，按用户保存布局。
- 主值字号 ≥ 24px；变化值带箭头与颜色；单位紧跟数值。
- 阈值条：正常灰、警告黄、严重红；越限时卡片边框变红并置顶。
- `age > 1s` 显示黄色 `0.4s`，`>3s` 红色 + `STALE`，并冻结依赖该指标的按钮。
- 缺失值显示 `N/A` 灰色，hover 显示原因（`WARMUP` / `NO_QUOTE` / `FILTERED` / `STALE`）。
- 点击卡片 → 指标详情页（大图 + 参数 + 引用 + 历史 + 告警记录）。

#### B.4.2 图表叠加

- 主图（K 线/分时）最多叠加 3 个指标；超过 3 个必须分面。
- 左右双轴最多 2 个；**禁止**把量纲差异大的指标强行同轴（如 IV 与价格）。
- 图例显示：名称、单位、当前值、颜色、显隐开关。
- 叠加指标必须显示"与主图不同周期"的标记（如 1m 主图 + 5m 指标）。
- 回放与实时使用同一渲染路径；回放时显示"回放"水印与进度条。
- 数据缺口不得用直线连接（用断点），避免视觉欺骗。

#### B.4.3 期权链列（指标落到列）

Call 侧（从左到右）：`IV | IV chg | 理论价 | 我们的 Bid | 我们的 Ask | 市场 Bid | 市场 Ask | Delta | Gamma | Vega | Theta | OI | Vol`
中间：`Strike`（ATM 高亮，背景色按 moneyness）
Put 侧：镜像。

规则：

- 列可配置显示/隐藏；默认显示 `市场 Bid/Ask、IV、Delta、OI`，其余在"更多列"。
- 每个数值带单位/tick 精度；IV 保留 1 位小数（%），Delta 3 位，Vega 整数。
- 我们的报价与市场报价分色（我们=蓝，市场=灰）；穿价/未报价用图标。
- 单元格 hover 显示：理论价、IV、最后更新时间、报价策略。
- 排序：默认按行权价；可点列头按 IV/Delta/OI/价差排序；排序后 ATM 标记仍跟随标的。
- 筛选：仅双边 / Delta 区间 / OI≥N / 有我们的报价 / 到期。
- 性能：100 档、5Hz 更新不卡；只更新变化单元格。

#### B.4.4 策略引用

- 策略条件里选择指标时，只能选"已发布"的指标版本；草稿指标可引用但部署时阻断。
- 显示指标当前值/单位/数据龄，避免选错。
- 指标详情页显示"被哪些策略引用、哪些版本、哪个条件"。
- 修改被引用指标：自动创建新版本，旧版本冻结；部署包锁定版本 + 哈希。
- 指标停用：引用它的策略进入 `DEGRADED`，停止报价并告警。

#### B.4.5 实时值 / 历史值

- 实时值：来自 Runtime 指标总线（或控制面缓存），带 `ts` 与 `age`。
- 历史值：来自 ClickHouse `strategy_metrics` 或新增 `indicator_values`，按 `indicator_id + tags + ts` 查询。
- 图表默认 1D/5D/1M/3M/1Y；期权 IV 默认 3M。
- 历史查询必须显示"采样间隔"和"是否降采样"，禁止把降采样后的极值当真实极值。

### B.5 指标与策略的关系（条件模型）

#### B.5.1 引用方式

策略不写公式，只引用：

```
indicator_ref = { id, version, params_override?, instrument_scope }
```

- `params_override` 只允许覆盖"窗口/阈值"这类实例参数，不允许改公式。
- 覆盖后在策略详情显示"与全局口径不同"的黄色标记。
- 部署包锁定 `id + version + hash`。

#### B.5.2 条件组合

支持两层：

```
GROUP (AND)
  ├─ COND: OPT_IV_RANK(au, 252d) > 60, dwell 60s
  ├─ COND: BOOK_SPREAD(au2612C920) >= 2 tick, dwell 10s
  ├─ COND: BOOK_DEPTH(au2612C920, 5) >= 50 手
  └─ GROUP (OR)
       ├─ COND: GRK_DELTA(组合) > 150
       └─ COND: GRK_GAMMA(组合) > 限额 80%
```

规则：

- 最多 8 个条件、2 层嵌套；超过则要求拆成两个策略。
- 每个条件必须有：左值（指标）、运算符（> ≥ < ≤ = ≠ 区间 穿越）、右值（常数或另一指标）、持续时长、冷却。
- **进入条件与退出条件分开**（ hysteresis ），避免在阈值附近抖动。
- 支持"仅记录不触发"（SHADOW 条件），用于验证条件是否过严。
- 条件必须可解释：策略日志输出"哪一条命中/未命中、当前值、阈值、持续时间"。
- 数据龄保护是系统级硬条件：任何被引用指标 `age > 3s`，策略自动暂停报价并告警，不可被用户关闭。

#### B.5.3 预览

"预览"不是看一行字，而是给三个数字：

| 输出 | 说明 |
|---|---|
| 命中次数 | 最近 20 个交易日，该条件组合触发多少次 |
| 命中时长占比 | 平均每次持续多久、占交易时长比例 |
| 事后表现 | 命中后 N 分钟标的变动/IV 变动/若报价的模拟成交与 PnL |
| 误触发提示 | 单日触发 > 50 次 → 条件过松；从未触发 → 过严或数据缺失 |

预览必须支持选择回放区间，并显示样本不足警告（< 5 个交易日）。

## C. 策略创建器（8 步向导）

### C.0 原则

- **表单即配置**，JSON 只作为"只读高级视图"和导入导出。
- 每一步都能看到"当前配置摘要"和"校验状态"；允许随时保存草稿。
- 所有字段有单位、默认值、范围、错误提示；不允许"自由文本填魔法值"。
- 参数分三层：模板默认 → 标的/账户覆盖 → 本次实例覆盖。UI 要显示每个值的来源。
- 保存 ≠ 部署；校验 ≠ 部署；部署必须走状态机与审批。

### C.1 第 1 步：选择模板

| 模板 | 适用 | 默认开启 | 关键差异 | 风险提示 |
|---|---|---|---|---|
| 期权做市 `OPTION_QUOTING` | 双边报价赚价差 | 报价 + 库存偏置 + 最大持仓 | 需要期权链、Greeks、报价节流 | 高：gamma/vega 裸露、被行权 |
| Delta 对冲 `DELTA_HEDGE` | 对冲组合 Delta | 阈值触发 + 期货腿 | 需要 Delta、对冲阈值、最小变动 | 中：过度对冲、0 价保护 |
| 期货价差 `FUTURES_SPREAD` | 跨月/跨品种 | 价差 z-score + 双腿 | 需要价差指标、腿比例、腿滑点 | 中：单腿成交、基差风险 |
| 自定义 `CUSTOM` | 从空白/复制 | 无 | 全部手填 | 高：无默认保护 |

字段：

| 字段 | 类型 | 默认 | 校验 | 错误提示 |
|---|---|---|---|---|
| 模板 | 卡片单选 | 期权做市 | 必选 | 请选择模板 |
| 策略名称 | 文本 | `{品种}-{模板}-{序号}` | 3–40 字，全局唯一 | 策略名称已存在 |
| 策略代码 | 文本（自动） | 大写 + 下划线 | 唯一，不可改 | — |
| 账户 | 下拉 | 当前账户 | 必须可用、有资金 | 账户不可用或余额不足 |
| 环境 | 单选 | SIM | SIM / SHADOW / PAPER / PROD | 无 PROD 权限时置灰 |
| 负责人 | 用户 | 当前用户 | 必填 | — |
| 描述 | 多行 | 空 | ≤200 字 | — |

### C.9 状态机

状态：

```
DRAFT → VALIDATING → VALIDATED / INVALID
VALIDATED → PENDING_APPROVAL → DEPLOYING → SHADOW → CANARY → ACTIVE
ACTIVE ↔ PAUSED
SHADOW / CANARY / ACTIVE / PAUSED → ROLLING_BACK → ROLLED_BACK
任意运行态 → STOPPING → STOPPED
DEPLOYING / ROLLING_BACK → FAILED
VALIDATED / INVALID / STOPPED / ROLLED_BACK → ARCHIVED
```

| 当前 | 事件 | 目标 | 守卫条件 | 谁可操作 | 审计 |
|---|---|---|---|---|---|
| DRAFT | 保存 | DRAFT | 必填项完整 | TRADER | SAVE_DRAFT |
| DRAFT | 校验 | VALIDATING | — | TRADER | VALIDATE |
| VALIDATING | 通过 | VALIDATED | 0 ERROR | 系统 | VALIDATED |
| VALIDATING | 失败 | INVALID | 有 ERROR | 系统 | VALIDATION_FAILED |
| INVALID | 修改 | DRAFT | 自动 | TRADER | EDIT |
| VALIDATED | 提交部署 | PENDING_APPROVAL | 首次必须 SHADOW；ACTIVE 需审批人 | TRADER | SUBMIT_DEPLOY |
| PENDING_APPROVAL | 批准 | DEPLOYING | 审批人 ≠ 创建人 | RISK/ADMIN | APPROVE |
| PENDING_APPROVAL | 拒绝 | VALIDATED | 填原因 | RISK/ADMIN | REJECT |
| DEPLOYING | Runtime ack | SHADOW/CANARY/ACTIVE | 版本/哈希一致、心跳正常 | 系统 | DEPLOYED |
| DEPLOYING | 超时/失败 | FAILED | >60s 无 ack | 系统 | DEPLOY_FAILED |
| SHADOW | 观察达标 | CANARY | ≥1 个时段、拒单率<5%、无 P0 告警 | TRADER + RISK | PROMOTE |
| CANARY | 观察达标 | ACTIVE | 观察期结束、指标达标、限额 ≤10% | TRADER + ADMIN | PROMOTE |
| ACTIVE | 暂停 | PAUSED | 填原因 | TRADER | PAUSE |
| PAUSED | 恢复 | ACTIVE | 风险校验通过 | TRADER | RESUME |
| 任意运行态 | 回滚 | ROLLING_BACK | 存在回滚版本 | TRADER/ADMIN | ROLLBACK |
| ROLLING_BACK | 成功 | ROLLED_BACK | Runtime ack | 系统 | ROLLED_BACK |
| 任意运行态 | 停止 | STOPPING | — | TRADER/ADMIN | STOP |
| STOPPING | 完成 | STOPPED | 撤单完成、持仓已交接 | 系统 | STOPPED |
| FAILED | 重试/回滚 | DEPLOYING / ROLLING_BACK | — | ADMIN | RETRY |

硬规则：

1. 已 `VALIDATED` 的版本不可修改；修改 = 新草稿版本。
2. 新策略不能跳过 SHADOW。
3. `ACTIVE` 必须有人审批，且审批人不能是创建人。
4. 盘中部署/回滚会自动先撤该策略全部挂单，并冻结 30 秒。
5. 任何状态变化写审计，包含操作人、原因、版本、配置哈希。
6. 心跳丢失 > 10s → 自动 `DEGRADED`，停止报价并告警；恢复需人工确认。

### D.2 开盘前 Checklist（驾驶舱顶部"盘前检查"卡片）

必须有 9 项，全绿才允许一键"开始交易"：

1. 交易通道：CTP 登录成功、席位正确、结算组正确。
2. 行情：au/ag 主力 + 期权链有 tick，数据龄 < 1s。
3. 合约：主力/次主力/到期日/交割月/涨跌停/保证金率已刷新。
4. 账户：权益、可用、保证金、手续费率正确。
5. 持仓：与柜台一致（对账通过），无未知持仓。
6. Greeks：组合 Delta/Gamma/Vega/Theta 已计算，数据龄 < 3s。
7. 策略：版本正确、状态 ACTIVE/SHADOW 符合预期、无 FAILED。
8. 指标：关键指标（ATM IV、IV Rank、价差、深度）有值，无 STALE。
9. 告警：无未确认 P0；测试告警通道可用。

任何一项红：显示原因 + 修复入口 + "仍要开始"需 ADMIN + 原因 + 二次确认（并记录风险接受）。

### D.4 收盘后

1. **15:00 / 02:30 后自动任务**：撤单确认 → 成交/持仓同步 → 结算价 → 手续费 → PNL → 对账 → 生成日报。
2. 交易员要看：
   - 当日 PNL（已实现/浮盈/手续费/滑点）
   - 分策略/分标的/分希腊字母归因
   - 成交质量（成交率、滑点、拒单率、撤单率）
   - 风险事件时间线（几点越限、谁处理的）
   - 对账差异（订单/成交/持仓/资金）

| 平仓 | 持仓行"平仓" | 单合约 / 全部 | 显示平仓后 Greeks/保证金变化 | TRADER | 成交回报 | CLOSE_POSITION |
| 断开自动交易（Kill Switch） | 顶栏红色开关 | 全局 | 长按 3s + 输入 `KILL` | ADMIN | 所有策略 STOPPED、全部撤单 | KILL_SWITCH |
| 恢复自动交易 | 顶栏 | 全局 | 盘前检查全绿 + 原因 | ADMIN | 逐步恢复（先 SHADOW） | RESUME |

二次确认的统一规范：

- 确认框必须显示：**环境（SIM/SHADOW/LIVE）、账户、范围、数量、名义金额、当前风险 → 操作后风险、不可逆提示**。
- 危险按钮默认焦点在"取消"，不允许回车直接确认。
- 所有应急操作必须有"操作中"状态与"部分失败"结果，不允许只弹一个"成功"。
- 失败必须给出可执行的下一步（重试/联系柜台/查看哪张单）。

### D.6 系统必须主动阻止的行为（硬规则）

1. 数据龄 > 3s 时任何报价类操作（策略自动 + 手工）。
2. 交易通道断开时任何下单/撤单（可排队，不可假装成功）。
3. 超出单笔/单日/组合限额的订单。
4. 涨跌停外的限价单、非 tick 整数价格、0 价/负价。
5. 到期日/交割月的新开仓（按配置）。
6. 集合竞价阶段报价。
7. 同一合约同方向重复策略部署。
8. 保证金占用 > 上限时的新开仓。
9. 未经审批的实盘部署。
10. 被行权/到期未处理的合约继续报价。

## G. 落地顺序（交易员建议）

### 第 1 阶段（1–2 周，P0 止血，不做新功能）

1. 去掉 mock 静默回退；生产 fail-closed；全局环境色带。
2. 全撤改为真实撤单 + 逐单回执；增加范围选择与二次确认。
3. 手工单接服务端风控 + 二次确认 + 合约/价格/涨跌停校验。
4. 断线判定改为行情+交易+控制面三重心跳；只读服务端强制。
5. 驾驶舱接真实账户/持仓/保证金/Greeks/PNL（先只读，不做花活）。
6. 顶栏 KILL 区：全撤 / 停全部 / 只减仓。

### 第 2 阶段（3–5 周，指标最小闭环 + 策略向导）

1. 指标注册表 + 指标配置页（先支持 8 个核心指标：ATM IV、IV Rank、25Δ RR、价差、深度、Delta、Gamma、Vega）。
2. 指标在驾驶舱卡片 + 期权链列 + 策略条件三处复用。
3. 策略 8 步向导（先做期权做市 + Delta 对冲两个模板）。
4. 校验、风险摘要、冲突检查、版本、SHADOW 部署。
5. 状态机 + 回滚 + 审批。

### 第 3 阶段（6–8 周，交易闭环）

1. 期权链接真实行情、Greeks、OI、快捷下单。
2. 订单页撤改/筛选/回执；成交明细接真实。
3. 监控分级/确认/静默/升级 + 交易健康指标。
4. 对账页、账户资金页、部署页、runtime 实例页。
5. 到期/行权/交割月/主力换月流程。

### 明确不做（避免过度设计）

- 不做手机做市端。
- 不做复杂波动率套利/曲面拟合交易（先把报价和对冲做稳）。
- 不做 AI 预测/信号推荐。
- 不做跨交易所套利（先把 SHFE au/ag 做透）。
- 不做自动加仓/自动放大限额。

## H. 需要产品/量化确认的问题

1. **指标口径归属**：IV Rank 用 252 日还是 60 日？用哪个 IV 源（市场中间价/理论/拟合）？谁签字？
2. **IV 源**：无报价合约用拟合还是跳过？曲面模型用 SVI 还是多项式？
3. **交易日历**：以交易所日历为准还是内部日历？夜盘归属是否全系统统一？
4. **账户模型**：单账户还是多账户？策略级保证金如何分摊？
5. **权限**：RISK 角色能否直接停策略？实盘部署必须双人吗？
6. **做市义务**：是否申请 SHFE 做市商？若是，报价覆盖率/最大价差/应答时间的考核口径要进监控。
7. **期权行权**：是否允许交易员在系统内提交行权/放弃？还是只做提醒？
8. **数据留存**：指标历史保留多久？tick 是否长期保留用于复盘？
9. **部署窗口**：盘中是否允许部署？若允许，谁批、是否自动撤单？
10. **合成数据边界**：SHADOW 可以用合成链，但指标/策略预览是否允许？必须显式标注。
